# Управление стендом

При открытии карта использует «LAEA - РФ» (центр 60° с. ш., 90° в. д.) и
охват доступного прогноза. «Вид карты» также предлагает Меркатор, Глобус и
LAEA — Арктика. Переключение не требует `refresh-grib` и не меняет публикации.

Все команды выполняются из корня репозитория одинаково в Windows и Linux:

```text
node hmc-app.mjs --help
```

## Требования

- Node.js с npm. Проверены 24.22.1 (Linux) и 26.10.0 (Windows); результаты —
  в [проверке общей команды](docs/validation/hmc-app-60.md).
- Windows: Docker Desktop с Linux-контейнерами и WSL 2; Linux: Docker Engine
  и плагин `docker compose`. Контейнеры приложения — Linux/amd64.
  Проверены Engine 29.1.2, Compose 2.40.3 (Windows) и 5.0.0 (Linux).
  Требования к Windows и виртуализации — в
  [инструкции Docker Desktop](https://docs.docker.com/desktop/setup/install/windows-install/).
- Пользователь имеет доступ к Docker, исходникам, чтению GRIB и записи
  локальных настроек/отчётов. На Linux файлы GRIB должны читаться UID 65532,
  каталоги — разрешать проход; не размещайте их в закрытой домашней папке.
- При первом развёртывании нужен интернет для зависимостей и образов.
  Для повторного запуска подготовленного стенда интернет не требуется.
- Свободные разные порты: по умолчанию карта 8140, API 8141, только localhost.
- Место на диске для образов, БД, исходников, производных и временных данных.
  Бюджет обновления по умолчанию 64 GiB — лимит дискового хранения, не RAM.
  Во время замены старые и новые данные могут временно храниться одновременно.
- Проверенный минимум RAM/CPU всего приложения не установлен. У worker лимиты
  2 GiB RAM и 2 CPU, у GeoServer Java heap до 1536 MiB; нужны также ресурсы
  PostgreSQL, API, карты и ОС. Это ограничения компонентов, не минимум хоста.
  Минимум Docker Desktop для Windows — 8 GB системной RAM; это не проверка
  достаточной памяти для обработки вашего набора GRIB.
- Python, Bash и PowerShell для команд ниже отдельно не требуются.
  Python и обработка GRIB выполняются в контейнерах. Node.js управляет Docker.

Проверить установку:

```text
node --version
npm --version
docker version
docker compose version
```

Стенд использует явно заданные демонстрационные часы `2026-10-19T05:00:00Z`
для исторических GRIB. Дата загрузки не превращает их в свежий прогноз.

## Создать проект

```text
node hmc-app.mjs deploy hmc-app-live
```

- Собирает приложение и карту, создаёт отдельные пароли, тома и сеть.
- Запускает службы, применяет миграции и проверяет готовность.
- Не загружает GRIB. Повторный `deploy` существующего проекта прекращается.
- Карта: <http://127.0.0.1:8140>; API: <http://127.0.0.1:8141/health>.
- Для второго проекта выберите другие порты:

```text
node hmc-app.mjs deploy hmc-app-test --viewer-port 8150 --api-port 8151
```

## Состояние, остановка и запуск

```text
node hmc-app.mjs status hmc-app-live
node hmc-app.mjs stop hmc-app-live
node hmc-app.mjs start hmc-app-live
```

- `status`: службы, адреса и привязанный каталог GRIB.
- `stop`: останавливает контейнеры, сохраняет данные и настройки.
- `start`: запускает существующий проект с прежними томами и настройками.
- Существующий старый `hmc-app-live` принимается под управление по его
  действительным Compose-файлам, паролям, портам и томам. Путь к репозиторию
  должен совпадать с записанным в конфигурации стенда.

## Обновить GRIB

Сначала закончите добавление/удаление файлов в папке, затем выполните:

```text
node hmc-app.mjs refresh-grib hmc-app-live --folder data/grib
```

- Работает только с запущенным проектом.
- Показывает списки «снять / загрузить / оставить», затем запрашивает `ДА`.
- Снимает все доступные редакции с данными отсутствующих файлов; в смешанных
  редакциях сохраняет поля оставшихся файлов без повторного декодирования.
- Загружает все поля только новых либо не завершённых ранее GRIB-файлов.
- Сравнивает полные имена с учётом регистра. Содержимое уже опубликованного
  файла под тем же именем не сравнивается и не перезагружается.
- Читает только непосредственные обычные файлы, без подпапок и симлинков.
  GRIB определяется по заголовку, расширение не обязательно.
- Первый подтверждённый запуск закрепляет папку; `--dry-run` её не закрепляет.
  При смене папки команда завершается с объяснением.
- Пустая существующая папка снимает все публикации в этой области.
  Отсутствующая или недоступная папка вызывает ошибку.
- Без изменений не загружает файлы и не перезапускает контейнеры.
- При изменениях после успешного выполнения обновляет API/gateway.
  В открытой карте нажмите **«Проверить обновления»**.

Только просмотр или выполнение без вопроса:

```text
node hmc-app.mjs refresh-grib hmc-app-live --folder data/grib --dry-run
node hmc-app.mjs refresh-grib hmc-app-live --folder data/grib --yes
```

Для старых публикаций, у которых известно имя, но не записан каталог:

```text
node hmc-app.mjs refresh-grib hmc-app-live --folder data/grib --include-unlocated
```

Без флага эти записи остаются непроверенными. Публикации с известным другим
каталогом и синтетические проверочные публикации не включаются автоматически.

Изменить бюджет только этой операции:

```text
node hmc-app.mjs refresh-grib hmc-app-live --storage-budget-bytes 68719476736
```

## Удалить все GRIB-публикации, сохранив стенд

```text
node hmc-app.mjs refresh-grib hmc-app-live --remove-all --dry-run
node hmc-app.mjs refresh-grib hmc-app-live --remove-all
```

- Удаляет все GRIB-публикации проекта, включая историю и старые записи без
  каталога. Папка не требуется; исходные файлы не изменяются.
- Не загружает данные после очистки. Контейнеры, пароли, настройки и привязка
  исходной папки сохраняются. Проверочные публикации, созданные из GRIB,
  также удаляются. Обычный `refresh-grib` по-прежнему их не синхронизирует.
- Запрашивает имя проекта; `--yes` отключает вопрос.
- Запрещено при выполняющейся загрузке или другом обновлении данных.
- Доступ прекращается сразу, старые ссылки возвращают `410 Gone`.
  Физическая очистка выполняется сборщиком после защитного интервала и
  завершения чтений. Общие используемые данные сохраняются; исходники вне
  хранилища проекта никогда не удаляются. Перезапуск `start` возобновляет
  отложенную очистку, если сборщик был остановлен.

Переход со старых публикаций без пересоздания стенда:

```text
node hmc-app.mjs refresh-grib hmc-app-live --remove-all
node hmc-app.mjs refresh-grib hmc-app-live --folder data/grib
```

Вторая команда заново загрузит всю папку и запишет каталог происхождения.

## Удалить весь проект

```text
node hmc-app.mjs remove hmc-app-live --dry-run
node hmc-app.mjs remove hmc-app-live
```

- После подтверждения имени удаляет контейнеры, сеть, тома с БД и данными,
  а также настройки именно этого проекта. Это не резервное копирование.
- Исходные GRIB, отчёты, архивы и общие образы сохраняются.
- Проверяет владение ресурсами; том другого проекта или общий том не удаляет.
- `--yes` выполняет без вопроса. Для создания заново:

```text
node hmc-app.mjs remove hmc-app-live
node hmc-app.mjs deploy hmc-app-live
node hmc-app.mjs refresh-grib hmc-app-live --folder data/grib
```

## Прогресс, остановка и ошибки

- Во время обновления/очистки меняется одна строка прогресса. При неизвестном
  объёме движется индикатор этапа без фиктивного процента. При перенаправлении
  вывода в файл анимация отключена.
- Для остановки нажмите `Ctrl+C`: команда удаляет свой контейнер обработки.
  Это не откат уже снятых или успешно опубликованных данных.
- После ошибки следующие этапы не выполняются. Исправьте причину и повторите
  команду: завершённые файлы пропускаются, незавершённые обрабатываются заново.
- Не меняйте исходную папку во время операции. Параллельные команды изменения
  одного проекта блокируются.
- План, состояние и полные журналы каждого запуска находятся в
  `HMC_EVIDENCE_ROOT/hmc-app/<проект>/…`; по умолчанию
  `../hmc-app-evidence/hmc-app/<проект>/…`. Точный путь выводится на экран.
- Настройки и секреты: `data/live/hmc-app/projects/<проект>/`; не публикуйте
  env-файлы. У принятого старого стенда сохраняются его исходные файлы настроек.
