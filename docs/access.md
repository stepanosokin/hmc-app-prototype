# Доступ организаций — T8 / №20

Публичное демо использует существующие `/api/v1/...` и `/gis/v1/...` без
секрета. Это намеренно публичные опубликованные продукты, а не конфиденциальные
данные организаций. Отзыв ключа закрывает защищённый профиль; он не удаляет
публичный продукт. Разделение частных наборов данных в T8 не вводится.

Защищённые аналоги имеют префикс `/org`: `/org/api/v1/catalogue`,
`/org/api/v1/point`, `/org/api/v1/selections/{selection}/tiles.json`,
`/org/api/v1/selections/{selection}/tiles/2/{z}/{x}/{y}.f32`,
`/org/gis/v1/runs/{run}/revisions/{revision}/wms` и санитарно очищенный
`/org/api/v1/jobs/{id}`. Публичный статус задания сохраняет прежний контракт:
стадии и идентификаторы без внутренних путей и конфигурации. Административных
HTTP-команд управления ключами нет.

## Заголовки и профили

Передавайте **один** заголовок `Authorization: Bearer <ключ>` либо
`X-API-Key: <ключ>`. Второй вариант пригоден для настройки пользовательского
заголовка GIS-клиента. Одновременная передача обоих заголовков отвергается.
В браузере публичного демо ключей нет. Запрос публичного профиля с заголовком
организации возвращает 400, чтобы секрет не использовался там случайно.
Параметры URL `key`, `api_key`, `apikey`, `token`, `access_token`,
`authorization`, `x-api-key` запрещены независимо от регистра. Не вставляйте
секрет в адрес, пример, страницу, историю команд или журнал.

| Профиль ключа | Разрешённые защищённые маршруты |
| --- | --- |
| `numeric` | API: каталог, точка, метаданные и байты тайлов, статус задания |
| `gis` | GIS: scoped WMS |
| `all` | API и GIS |

Защищённый каталог сохраняет `/org` в ссылках; метаданные тайлов и ссылки
capabilities также сохраняют защищённый профиль. Ключ `numeric` может видеть
ссылку WMS, но запрос по ней получит 403. Ключ `gis` использует явно выбранный
адрес run/revision; публичный каталог доступен без ключа.

| Статус | Значение |
| --- | --- |
| 400 | Секрет в параметре URL или заголовок организации в публичном профиле |
| 401 | Ключ отсутствует, неверен, отозван или заголовки неоднозначны; `WWW-Authenticate: Bearer realm="organization"` |
| 403 | Действующий ключ не разрешает этот профиль продукта |
| 404 | Маршрут вне белого списка или недоступный опубликованный выбор |
| 503 | Хранилище авторизации или upstream недоступны; `Retry-After: 2` |

Ошибки доступа числового API и WMS используют единый профиль HTTP JSON
`{"code":"Unauthorized|Forbidden|...","description":"..."}` с русским
описанием и `Cache-Control: no-store`. Это документированный профиль gateway,
не заявление об OGC exception conformance. Успешные WMS-ответы и прикладные
ошибки сохраняют существующий контракт. Desktop QGIS и его полная совместимость
проверяются отдельной задачей; T8 проверяет передачу заголовков по HTTP.

## Команды оператора

Используйте тот же `--env-file`, `--project-name` и `--file compose.publication.yaml`,
что и для изолированного проекта публикации. Пароли Compose находятся только
во внешнем/игнорируемом файле окружения. Добавьте отдельный случайный
`GATEWAY_PASSWORD`; пустое значение оставляет роль без пригодного для входа
пароля и допускает лишь публичный профиль. Не храните этот файл в Git.

При обновлении существующей базы пересоздайте сервис `db` с новой переменной
окружения и выполните от имени оператора базы:

```powershell
docker compose <параметры проекта> up --detach --force-recreate db
docker compose <параметры проекта> exec --no-TTY db sh /docker-entrypoint-initdb.d/020-access.sh
docker compose <параметры проекта> run --rm --entrypoint python worker -m publication.access migrate
docker compose <параметры проекта> up --detach --force-recreate gateway api
```

Свежий PostGIS создаёт роль и схему автоматически; `access migrate` создаёт
таблицу ключей и выдаёт gateway только SELECT. Повторная миграция безопасна.
API и GeoServer доступа к ключам не получают. Существующие ключи и публикации
при миграции сохраняются. Перезапуск gateway не нужен для отзыва ключа.

```powershell
docker compose <параметры проекта> run --rm --entrypoint python worker -m publication.access create --organization partner-a --profile all --out /evidence/partner-a.key
docker compose <параметры проекта> run --rm --entrypoint python worker -m publication.access list
docker compose <параметры проекта> run --rm --entrypoint python worker -m publication.access rotate --id <идентификатор> --out /evidence/partner-a-next.key
docker compose <параметры проекта> run --rm --entrypoint python worker -m publication.access revoke --id <идентификатор>
```

В stdout возвращаются только идентификатор, организация и профиль. Идентификатор
организации содержит 1–64 ASCII-буквы/цифры/`_.-`, начиная с буквы или цифры.
Файл `--out` создаётся эксклюзивно с правами 0600 внутри Linux-контейнера;
существующий файл никогда не перезаписывается. Выберите приватный каталог:
на Windows права host bind mount дополнительно определяются ACL Windows.
Передайте файл партнёру по согласованному защищённому каналу и удалите локальную
копию. Нельзя печатать файл в журнал или прикладывать к отчёту. `/evidence`
выше — удобный пример игнорируемого host mount, а не публичный asset-каталог.

Ключ включает 256 случайных бит; в PostgreSQL сохраняются UUID, организация,
SHA256 ключа, профиль и UTC-времена создания/отзыва. Восстановимого секрета в
таблице нет. Ротация создаёт новый ключ той же организации/профиля и отзывает
старый в одной транзакции. Ошибка записи файла не отзывает старый ключ;
неудача транзакции удаляет новый файл. Повторный отзыв идемпотентен. После
сбоя процесса между записью файла и commit проверьте `list`: неполученный ключ
следует отозвать и выпустить заново. Удаление файла не заменяет отзыв.

## Кеш, изоляция и эксплуатационные границы

Gateway проверяет ключ в PostgreSQL при каждом защищённом запросе до обращения
к API/GeoServer и их кешам. Решения авторизации не кешируются. Недоступность
базы закрывает защищённый доступ с 503. Запросы, допущенные до commit отзыва,
могут завершиться; последующие запросы получат 401. Тёплый числовой кеш,
`If-None-Match` и ETag этого порядка не меняют. Ответы числовых тайлов и WMS
требуют HTTP revalidation (`private, no-cache`); метаданные — `no-store`.

Только gateway публикует host-порт на loopback. API, PostGIS, GeoServer и
хранилище assets не публикуют портов и находятся во внутренней сети. У gateway
нет mount assets или ключевых файлов. Белый список маршрутов исключает
GeoServer REST/web/WMS напрямую, staging, административные и файловые адреса.
Клиентские forwarding/prefix/identity-заголовки не пересылаются; исходный ключ
не передаётся в API или GeoServer. Доступ администратора Docker/host остаётся
операторским доверием, а не внешним HTTP-доступом.

Gunicorn access-log отключён по умолчанию, приложение не журналирует URL,
заголовки или значения ключей. Проверки сканируют журналы реальных сервисов
и отчёты на сырые ключи. При добавлении внешнего reverse proxy сохраняйте это
правило: не записывайте Authorization/X-API-Key/query string. Настраиваемый TLS для сайта/API/GIS задан в [T21 / №33](https://github.com/stepanosokin/hmc-app-prototype/issues/33) и разделе 10.1 [спецификации](../.scratch/hmc-meteo/spec.ru.md): включение через reverse proxy после получения сертификата, цепочки и закрытого ключа организации. Это будущая реализация; текущий стек работает по локальному HTTP. Готовность подключения проверяется тестовыми сертификатами, а публичный DNS, настоящие сертификаты и доверие целевых клиентов остаются входными условиями эксплуатационного запуска.
Резервируйте PostgreSQL с метаданными ключей и внешний файл паролей раздельно;
восстановление старого backup требует повторного отзыва ключей, отозванных
после backup. Квоты и учёт использования относятся к следующему срезу, T8
закрывает только часть A7.

## Воспроизведение

```powershell
./publication/run-access.ps1 -Project hmc-publication-t8-example -Port 8100
```

Runner заранее проверяет SHA256 реального GRIB, использует закреплённые образы,
новые volumes, независимые пароли и явные исторические часы. Он выполняет
T5-регрессию публикации всех 24 времён, проверки доступа и HTTP, доказывает
попадание в тёплый кеш при отключённой генерации, недоступность backend из
edge-сети, отказ при остановленной базе и сохранение отзыва после перезапуска.
Затем проверяет полную suite и неизменность входных файлов. `-Development`
пропускает дорогостоящую T5-регрессию и полную suite и не является финальным gate.
Данные попытки сохраняются в `data/reports/t8/<project>`; в `finally` отчёты
архивируются, ресурсы проекта удаляются с проверкой нулевого остатка.
Файлы `.key`/`.env` не входят в переносимый архив доказательств.
