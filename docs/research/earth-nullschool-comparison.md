# Earth Nullschool: обработка данных и визуализация

Дата изучения: 30 октября 2026 года. Термины «поле», «время действия прогноза», «частица ветра» и «проекция веб-карты» используются в смысле [глоссария проекта](../../GLOSSARY.md).

## Что подтверждено для действующего сайта

Earth показывает результаты внешних расчётов. Погоду поставляет GFS; океанические данные — OSCAR и Copernicus; химию атмосферы — GEOS-5 и CAMS. Сайт указывает декодер GRIB/NetCDF на основе Unidata netcdf-java, библиотеку D3 и несколько служб размещения данных. Это подтверждает работу с научными форматами, но не раскрывает всю современную серверную цепочку. Обновление погоды каждые три часа, указанное на странице, нельзя автоматически считать частотой запусков модели. [Описание сайта](https://earth.nullschool.net/about.html).

В интерфейсе выбираются время действия прогноза, уровень, цветное поле и анимация. Есть девять проекций, включая ортографическую, равнопромежуточную цилиндрическую и Equal Earth. В настройках доступны билинейная интерполяция и ближайший сосед. Интерполяция оценивает значения между узлами сетки; она не добавляет новых сведений о погоде. [Действующий интерфейс](https://earth.nullschool.net/).

## Как работает опубликованная открытая версия

Официальная страница называет `cambecc/earth` свободной версией исходников. Её устройство можно проверить по коду, но нельзя без дополнительной проверки переносить все детали на действующий сайт.

Путь данных в открытой версии:

`GFS → GRIB2 → выбор переменных и уровня → grib2json → JSON → браузер → карта`.

GRIB2 хранит поля прогноза. Для ветра нужны две компоненты: `u` и `v`. Утилита `grib2json` использует netCDF-Java и выдаёт записи с заголовком `header` и массивом чисел `data`. Заголовок описывает величину, единицы и уровень. Фильтры позволяют выбрать нужные записи до передачи в браузер. [grib2json](https://github.com/cambecc/grib2json).

В браузере `products.js` собирает числовую сетку из JSON. Метаданные содержат начало сетки, шаг, размеры, исходное время запуска и заблаговременность. Время действия получается их сложением. Между четырьмя соседними узлами рассчитывается билинейная интерполяция. Для ветра отдельно интерполируются `u` и `v`, затем определяется скорость `sqrt(u² + v²)`. Если нужных значений нет, интерполяция не выдаёт значение. Этот код рассчитан на определённый порядок обхода регулярной широтно-долготной сетки; он не является универсальным читателем любых сеток GRIB. [products.js](https://github.com/cambecc/earth/blob/master/public/libs/earth/1.0.0/products.js).

Географическая основа поступает отдельно: Natural Earth в Shapefile преобразуется через GeoJSON в TopoJSON. TopoJSON описывает берега и озёра, а не метеорологические значения. Открытая версия использует SVG для географии и два слоя Canvas: анимацию и цветное поле. Подготовленные файлы можно раздавать как статические объекты. [README открытой версии](https://github.com/cambecc/earth#readme).

Для изображения браузер переводит точку экрана обратно в долготу и широту, берёт значение поля и назначает цвет по шкале. Вектор ветра пересчитывается с учётом местного искажения проекции веб-карты. Затем частицы ветра перемещаются по этому экранному полю. Старые следы постепенно затухают; частицы с истёкшим сроком жизни создаются заново. Скорость анимации содержит выбранный автором масштаб. Поэтому след частицы показывает движение в выбранном поле, а не прогноз пути воздушной массы через последовательные сроки. [earth.js](https://github.com/cambecc/earth/blob/master/public/libs/earth/1.0.0/earth.js).

## Граница выводов

Цепочка GRIB2 → JSON, TopoJSON и сочетание SVG/Canvas подтверждены для открытой версии. Современный бинарный формат доставки, степень сжатия, применение GPU и внутренняя серверная архитектура действующего сайта этими источниками не установлены. Историческую сетку 1° из README также нельзя считать текущим разрешением всех слоёв.

## Сравнение с вашим проектом

Сравнение сделано по документации и текущим исходникам рабочей папки на 30.10.2026, включая незакоммиченные изменения. Оно не подтверждает состояние развёрнутого стенда и не заменяет проверку приложения.

| Этап | Earth: проверенная открытая версия | Ваш проект |
| --- | --- | --- |
| Получение поля | Готовый прогноз GFS в GRIB2 | Собственные входные GRIB2; декодирование ecCodes с проверкой метаданных и сетки |
| Хранение чисел | Для браузера подготовлены JSON-файлы; внутреннее хранилище действующего сервиса неизвестно | Zarr: float64 и маска пропусков; производные COG: float32; PostgreSQL хранит сведения о публикациях |
| Передача на карту | JSON с заголовками и массивами значений | JSON-метаданные и бинарные блоки исходной сетки: float32 плюс uint8-маска допустимости; 256×256 ячеек и граница по одной ячейке, итого 258×258 |
| Цветное поле | Вычисления в JavaScript, отрисовка Canvas | Пользовательский слой MapLibre: WebGL 2 выполняет одну билинейную интерполяцию исходной сетки и назначает цвет |
| Ветер | Компоненты u/v, экранная поправка проекции, частицы Canvas | Отдельный слой u/v, учёт ориентации исходной сетки и проекции; частицы также рисуются Canvas. GPU цветного поля не означает GPU для ветра |
| Число в точке | Открытая версия использует интерполированное поле | Канонический API читает ближайшую исходную ячейку Zarr на точный срок; сглаженная заливка карты имеет отдельный смысл |
| Внешний доступ | Открытый пример ориентирован на веб-визуализацию | Дополнительно: числовой API, ограниченный профиль EDR/CoverageJSON и GeoServer WMS-T для QGIS |

Основания сравнения: [декодер](../decoder.md), [хранение](../storage.md), [публикация](../publication.md), [числовой API](../numerical-api.md), [загрузчик блоков](../../viewer/field.ts), [GPU-слой](../../viewer/native-layer.js), [подключение к MapLibre](../../viewer/weather-layer.ts), [выборка и частицы ветра](../../viewer/wind.ts), [проекции](../adr/0003-web-map-display-projections.md).

Простой путь данных вашего проекта:

`GRIB2 → ecCodes → Zarr → опубликованная выборка → бинарные блоки → GPU → цветное поле`.

Параллельные пути: `Zarr → числовой API` и `COG → GeoServer → WMS-T/QGIS`. В браузерном пути уже существует и старый контракт тайлов WebMercator; его не следует путать с текущими блоками исходной сетки. См. [нативное отображение](../native-display.md).

Вывод: общий принцип близок — передать числа и построить изображение в браузере. Ваш проект дополнительно решает задачи публикации и числового использования: фиксирует запуск модели, редакцию публикации, срок, уровень, исходную сетку и пропуски. Переход на JSON по образцу старого Earth сам по себе не даёт выигрыша; сравнение производительности требует отдельного измерения. У Earth полезно изучать согласование проекции, цветного поля и частиц. Оно применимо без замены вашего Zarr и GIS-пути.
