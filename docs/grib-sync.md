# Снятие публикаций отсутствующих исходников

Команда `node tools/sync-grib.mjs` сравнивает имена непосредственных обычных
файлов `data/grib` с происхождением доступных публикаций выбранного стенда.
Она снимает публикации отсутствующих исходников; загрузку новых файлов и
пересчёт изменённых выполняют отдельно. Содержимое и контрольные суммы
исходников для определения наличия не сравниваются. Переименование считается
исчезновением прежнего имени; подпапки и символические ссылки не обходятся.
Происхождение проверяется по контрольным суммам манифестов и принадлежности
партий редакции. Просмотр не перечитывает числовые массивы и производные файлы.
Перед применением замены целостность её сохраняемых данных проверяется полностью.

По умолчанию выбран `hmc-app-live`. Его необходимые службы должны быть
запущены оператором отдельно: команда никогда не запускает их автоматически.
Действительные образ, сеть и том данных определяются по контейнерам стенда,
включая нестандартные имена томов из Compose override. Файлы конфигурации
другого стенда и значения Compose по умолчанию для операции не используются.

## Просмотр и применение

Из корня репозитория создайте отдельную папку для планов во внешнем архиве:

```powershell
New-Item -ItemType Directory -Force ../hmc-app-evidence/grib-sync-operations | Out-Null
node tools/sync-grib.mjs preview --plan ../hmc-app-evidence/grib-sync-operations/plan-20261026-01.json
```

Просмотрите JSON: `actions` перечисляет отсутствующие имена (`missing`),
снимаемые корни публикаций (`root`) и сохраняемые поля/сроки (`keep`);
`unchecked` перечисляет непроверенные публикации с причиной. Смешанная
редакция заменяется редакцией из оставшихся проверенных партий без повторного
декодирования. Исторические замены сохраняют прежний порядок и сроки хранения.

Для применения именно этого плана:

```powershell
node tools/sync-grib.mjs apply --plan ../hmc-app-evidence/grib-sync-operations/plan-20261026-01.json
```

Новый просмотр требует нового имени файла плана. Изменение списка исходных
имён, связанных записей каталога/политики/очереди, целевого стенда или кода
операции останавливает применение. Изменение байтов под тем же именем само
по себе не меняет план. Незавершённая загрузка отсутствующего исходника
блокирует применение: дождитесь её завершения и выполните новый просмотр.
При недоступной или отсутствующей папке операция останавливается.
**Успешно прочитанная пустая папка означает снятие всех публикаций в области.**

Для отдельного стенда укажите `--project ИМЯ`; для другого исходного каталога —
`--input-directory ПАПКА`. Оба параметра должны совпадать при просмотре и
применении. Каталог происхождения публикации должен соответствовать выбранной
папке: публикации из другого каталога автоматически не снимаются.

## Область и результат

Новые загрузки фиксируют каталог при постановке задания и сохраняют его
в `source.directory` через `GRIB_SOURCE_DIRECTORY` из Compose. При смене конфигурации загрузчика
передавайте действительный `PUBLICATION_INPUT_DIR`. **Старые публикации без
записанного каталога всегда остаются непроверенными**, даже если известно имя
файла. Совпадение имени не доказывает принадлежность к `data/grib`. Записи с
неизвестным происхождением и смешанные редакции с такими записями исключены
из автоматического снятия. Синтетические проверочные публикации также вне области.

Команда сначала подготавливает все замены и проверяет актуальность плана,
затем атомарно меняет доступность всех затронутых редакций. При сбое подготовки
доступность сохраняется. При потере подтверждения транзакции подготовленные
данные сохраняются до проверки результата: проверьте каталог и выполните новый
просмотр. Операция не удаляет существующие данные с диска; последующая штатная
очистка учитывает общие партии и выполняющиеся чтения. Созданный контейнер
операции удаляется и отсутствие проверяется, включая ошибки и таймауты.
Уже истёкшие по политике редакции получают долговечные отметки истечения,
чтобы уменьшение бюджета после снятия других редакций не вернуло их в каталог.

Снятые современные и legacy редакции исчезают из discovery; их прежние
числовые и ГИС-адреса возвращают `410 Gone`. Следующая загрузка не наследует
поля истёкших/снятых редакций. Возврат файла требует отдельной новой загрузки
(нового запуска `python -m publication.grib_batch --clock <UTC> --report /evidence/reload-new.json`,
с `--all-fields` для многополевого профиля T19); старые ссылки остаются
снятыми. Повторное выполнение прежнего уже завершённого задания новой
загрузкой не является.

Открытая карта при следующей проверке каталога автоматически выбирает
совместимую замену того же расчёта, поля, уровня, сетки, участника и срока.
Если её нет, кадр убирается и появляется «Публикация снята». У внешних
клиентов уже скачанные данные отозвать невозможно. Сообщение о снятии
описывает отсутствие выборки в каталоге и не устанавливает его причину.
После обновления исходников
внедрите новую версию API и собранного интерфейса по обычному порядку стенда;
сама синхронизация не перезапускает обслуживающие процессы.

## Проверки

`tools/run-grib-sync.ps1 -Project hmc-publication-sync-fresh -WithBrowser`
создаёт отдельный проект с настоящим образцом ICON, проверяет смешанные и
legacy редакции, устаревший план, откат транзакции, потерю ответа COMMIT,
исторический порядок, возврат исходника и пустую папку. Chrome и Edge
проверяют переключение и снятие кадра; браузеры/профили и Compose-ресурсы
удаляются. Используйте новое имя проекта для каждой попытки. Это отдельный
gate новой операции; регрессии T5/T6/T7 и полная матрица интерфейса выбираются
по [таблице проверок](development-workflow.md#choose-validation-by-the-change).
