# Нативное числовое отображение T23a

Задача [№37](https://github.com/stepanosokin/hmc-app-prototype/issues/37),
[согласованный проект](design/t23a-native-display-draft.md),
[контракт hmc-native-display/1](../publication/native-display.v1.json).
Статус реализации и неудачные пробы приведены в
[development evidence](validation/archives.md); этот документ сам по себе
не подтверждает окончательную приёмку.

## Доставка

Каталог возвращает ссылку `native_display` для опубликованной selection.
Metadata доступен по `/api/v1/selections/{selection}/display/1/native.json`.
В профиле организации пути имеют префикс `/org`, ключ передаётся существующим
`Authorization: Bearer …` или `X-API-Key`. Все URL в metadata соответствуют
выбранному профилю; ключей в URL нет.

`url`/`url_template` содержит `{column}` и `{row}` для блоков нативной сетки.
Для текущего ICON-EU T_G диапазоны равны column=0..5 и row=0..2. Это один
нативный уровень, а не WebMercator zoom. Старое ограничение zoom относится к
тайлам v2; для native действуют request/concurrency/time/output/byte budgets
и фиксированные пределы нового matrix. Неизвестные query-параметры отвергаются.

Блок: 258×258 little-endian f32 K, затем 258×258 uint8 validity, 332820 байт.
Внутренний размер 256×256, halo по одной ячейке с каждой стороны. Строки идут
с юга на север, столбцы с запада на восток, column меняется быстрее row.
Mask=1 означает конечное значение; mask=0 сопровождается значением 0.
Вне исходного массива padding всегда missing. Полный набор из 18 блоков
занимает 5990760 байт, включая повторяющиеся halo и padding.

Matrix, shape, spacing, origin, bounds, CRS/операция и immutable identity
находятся в metadata. Первая ячейка отступает на половину шага от юго-западного
внешнего края. Нативные lon/lat на сфере R=6371229 нельзя считать геодезическими
WGS84 углами. Прямое преобразование использует WGS84 h=0 и нулевой геоцентрический
datum shift; двумерная обратная операция пересекает нативный луч с WGS84 h=0.
Это согласованная прототипная гипотеза, а не подтверждение геодезии производителем.

Внутри полуоткрытого footprint дробные индексы ограничиваются крайними центрами.
Отображение выполняет ровно одну bilinear-интерполяцию нативных значений.
Missing участник с положительным весом делает результат missing; веса не
перенормируются. Point/EDR остаются каноническими nearest-native-cell запросами
одной точки, не загрузчиком числового растра.

## Ограничения исполнения

Native metadata объявляется ready после детерминированных probes (0,0), (1,0),
(2,1), (5,2) и проверки halo. Остальные блоки генерируются по запросу.
API ограничивает native cache 16 МиБ на процесс, сохраняя меньший установленный
`TILE_CACHE_BYTES`. Ключ включает contract hash/version, engine, CRS, grid,
matrix identity, selection и адрес блока. Eligibility/retention и наличие
опубликованных assets проверяются перед cache hit.

Связанные чтения retention/selection одного native-resolve выполняются в одной
транзакции PostgreSQL, без кеширования результата или доступа между запросами.

Один native reader сохраняет проверенные immutable samplers; его очередь и
файловые проверки/генерация ограничены общим десятисекундным deadline и
оставшимся сроком запроса. После timeout child уничтожается и собирается до
освобождения слота. Gateway переиспользует до восьми ограниченных HTTP workers
вместо Python startup на каждый блок. Пределы доступа и usage accounting не
повышаются; прекращение HTTP-посредника не подменяет окончание API backend.
Консервативный резерв timeout принадлежит своему admission bucket, поэтому
тесты timeout используют отдельную организацию.

Браузер держит одну selection, загружает не более двух блоков одновременно и
переиспользует их при смене режима. До выделения числовых GPU объектов проверяет
texture limits и суммарный предел 128 МиБ. Температурные текстуры используют
NEAREST/texelFetch и явные веса. Range-reduced atan и устойчивая формула
ортографии заменяют недостаточно точную проверенную реализацию GPU atan2.
Проекционные synthetic probes явно отделены от покрытия реального ICON-EU.

## Технический viewer и сравнение

Воспроизведение на Windows с Docker, закреплённым publication image,
приватным образцом `data/grib/ICON_EU_T_G_2026101500.grib2` и Chrome:

```powershell
powershell -NoProfile -File tools/run-native-display.ps1 -Project hmc-publication-t23a-unique -Port 8137
```

Runner проверяет SHA256 образца до выделения ресурсов, использует свежий проект,
фиксирует Git-filter identities и исходный commit, выполняет gateway tests,
GPU readback и независимый raw-GRIB/PROJ эталон. В конце каждой попытки сохраняет
логи, архивирует отчёт и автоматически удаляет контейнеры, сети и тома проекта.
Отчёты находятся в `data/reports/t23a/<project>`, retirement — в
`data/archives/publication/<project>/<archive-id>`.

Серверные fixed-screen кадры `/display/1/experiment/{ortho|laea}.f32` доступны
только при `T6_TEST_FAULTS=1`, не рекламируются discovery и не являются новым
публичным контрактом. Они нужны для сравнения в тех же экранных/географических
точках: GPU и серверный bilinear независимо сопоставляются с исходным GRIB.
Допуск кодирования ≤0,001 K и общий ≤0,01 K проверяются отдельно; COG ≤0,0001 K
остаётся отдельным пределом.

Viewer показывает сферическую ортографию и EPSG:3576 с общими геометрией поля,
локальной Natural Earth, подписями, границей и маркером. В LAEA показ ограничен
45° с. ш. Bearing rotation отключён; свободное вращение сферы и полноценная
рабочая карта относятся к T23/#25/#27. Эмуляция узких viewport на desktop не
подтверждает Android/iOS. Внешний WMS/QGIS не получает EPSG:3576 или новый контракт;
`hmc-temperature-tile/2` остаётся доступен с прежним смыслом.
