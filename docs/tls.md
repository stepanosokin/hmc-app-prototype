# HTTPS для карты, API и WMS

TLS включается дополнительным [Compose-файлом](../compose.tls.yaml).
Маршрут запроса: клиент → HTTPS → `tls-proxy` → gateway → API/GeoServer.
Статические файлы карты proxy получает от viewer; запросы данных идут через
gateway. Внутренняя связь работает по HTTP в закрытых Docker-сетях.

Proxy использует Nginx 1.31.6 Alpine с фиксированным digest образа.
Разрешены TLS 1.2 и 1.3. Контейнер работает с UID 65532, без capabilities,
с файловой системой только для чтения и временными файлами в `/tmp`.
Порт 80 не открывается; перенаправления HTTP → HTTPS нет.
Наследование SSL-объектов между reload отключено: быстрая замена или возврат
сертификата перечитывает файлы даже при совпадении времени изменения и inode.
Условия наследования описаны в [документации Nginx](https://nginx.org/en/docs/ngx_core_module.html#ssl_object_cache_inheritable).

Порядок включения и замены файлов — в [ADMIN.md](../ADMIN.md#включить-https-tls).
Формат цепочки описан в [документации Nginx](https://nginx.org/en/docs/http/ngx_http_ssl_module.html#ssl_certificate).
Команда перечитывания проверяет конфигурацию перед отправкой reload;
[Nginx сохраняет прежнюю конфигурацию при ошибке применения](https://nginx.org/en/docs/control.html#reconfiguration).

## Ручное подключение Compose

Для проекта, которым управляет `hmc-app.mjs`, используйте команды из ADMIN.
Прямой Compose предназначен для отдельных стендов с собственным файлом паролей.
Задайте переменные в окружении процесса либо в приватном `--env-file`:

| Переменная | Значение |
| --- | --- |
| `HMC_TLS_ORIGIN` | Внешний HTTPS origin без пути и завершающего `/`, например `https://meteo.example.org:8443` |
| `HMC_TLS_PORT` | Публикуемый порт, по умолчанию `443`; должен совпадать с origin |
| `HMC_TLS_BIND` | IPv4-адрес прослушивания, по умолчанию `0.0.0.0`; для локальной проверки `127.0.0.1` |
| `HMC_TLS_CERT_DIR` | Абсолютный путь к папке `fullchain.pem` и `privkey.pem` |

Файл паролей и переменные исходного Compose также обязательны.
Compose 2.24.4+ нужен для замены сетей и удаления прежних публикаций портов.
Сначала проверьте конфигурацию proxy, затем примените override ко всему проекту:

```text
docker compose --env-file data/live/environment.env -p hmc-tls -f compose.publication.yaml -f compose.tls.yaml run --rm --no-deps tls-proxy -t
docker compose --env-file data/live/environment.env -p hmc-tls -f compose.publication.yaml -f compose.tls.yaml up -d db geoserver api gateway viewer tls-proxy
```

Отсутствующий каталог, нечитаемый файл или несовпадающий ключ останавливают
проверку/запуск proxy. Не запускайте базовый Compose отдельно после включения
TLS: он снова публикует локальные HTTP-порты. Не удаляйте override из настройки
проекта при восстановлении сертификата.

Gateway берёт внешний origin из конфигурации `HMC_PUBLIC_ORIGIN`, которую
задаёт override. Он добавляет `/org` для защищённого профиля. Каталог,
метаданные числовых тайлов и WMS capabilities сохраняют этот адрес и
идентификаторы расчёта/редакции. Клиентские `Forwarded`, `X-Forwarded-*`
и `X-Publication-Prefix` не определяют эти ссылки.

Закрытые ключи не входят в Git, Docker build context, ресурсы сайта и отчёты.
Nginx не ведёт журнал доступа. Gateway журналирует результат запроса без
API-ключа. Резервные копии сертификатов и ключей хранит оператор отдельно
от переносимых доказательств.

## Воспроизводимая проверка

Используйте новый проект и свободные порты. Нужен исходный GRIB с контрольной
суммой, которую проверяет существующий T8 runner.

```powershell
# Быстрая проверка при разработке:
powershell -NoProfile -File publication/run-access.ps1 -Project hmc-publication-t8-tls-dev -Port 8171 -TLS -TlsPort 8443 -Development
# Полная приёмка, включая T5 и T8:
powershell -NoProfile -File publication/run-access.ps1 -Project hmc-publication-t8-tls-final -Port 8171 -TLS -TlsPort 8443
```

Проверяются две границы: команды оператора и реальные HTTPS-запросы.
Runner создаёт собственную CA, два сертификата с SAN `localhost` и ключи
в приватной папке `data/live`. CA передаётся только тестовому HTTPS-клиенту.
Проверяются доверие и имя, карта, публичные/защищённые данные и WMS,
ссылки, прогретый кеш, отказ неверным/отозванным API-ключам, изоляция портов,
замена/возврат сертификата и отказ на неверных файлах.

Секретные файлы удаляются после попытки. Отчёт `tls-gate.json` остаётся
в `data/reports/t8/<проект>`, журналы команд — также в
`data/reports/t21/operations/<проект>`. Родительский runner архивирует
результаты и удаляет контейнеры, тома и сети с проверкой остатка.
Перед внешним архивированием удалите оставшиеся секреты T8 (`*.key`),
сохранив только результаты; env-файл архиватор исключает автоматически.
Следуйте [правилам хранения доказательств](validation/evidence-storage.md).

Эта проверка устанавливает готовность TLS. Для эксплуатационного запуска
отдельно нужны настоящий DNS, сертификат организации и проверка доверия
на целевых клиентах. Выпуск ACME, mTLS и публичное развёртывание в №33 не входят.
