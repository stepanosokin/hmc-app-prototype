# Удаление архива доказательств из истории Git

26.10.2026 согласована цель: удалить `docs/evidence/` из истории публикуемых
веток и тегов, чтобы новые обычные clone не загружали накопленный архив.
Немедленное физическое удаление старых объектов на GitHub не является
критерием успеха. Это отдельный последующий этап после переноса из ADR
[0005](0005-external-validation-evidence.md), при котором историю сохраняли.

Пользователь подтвердил согласование остановки push и повторного клонирования
с участниками.
Перед переключением требуется отдельная локальная резервная копия старой
истории вне репозитория; после фильтрации сохраняется таблица старых и новых
SHA. Резервную историю нельзя публиковать обратно в очищенный репозиторий.
Изменение SHA потребует учитывать старые ссылки в Issues и отчётах.

Удаляется только исторический путь `docs/evidence/`. Нынешние
`docs/validation/`, `tests/fixtures/` и `tools/` сохраняются. Пользователь
принимает, что старые коммиты без удалённых доказательств могут не проходить
прежние проверки; для их изучения остаются резервная история и внешний архив.
Шесть локальных исследовательских веток и их worktree сохраняются отдельно
со старой историей и исключаются из дальнейшего push. Нужные изменения
переносятся выборочно в новый clone без слияния старой истории.

## План переключения

1. Восстановить сетевой доступ Git и повторно проверить удалённые ветки и
   теги, права и отсутствие новых изменений. Не публиковать неизвестные refs
   и не удалять ветки автоматически при расхождении с согласованным планом.
2. Сохранить вне репозитория резервную историю, список исходных refs и
   локальную работу, включая незакоммиченные изменения и worktree. Отделить
   старые рабочие копии от дальнейшей публикации, не удаляя их данные.
3. В отдельном свежем клоне выполнить `git-filter-repo` для удаления только
   `docs/evidence/` из публикуемой истории. Сохранить таблицу SHA вне Git.
4. Проверить отсутствие пути во всей публикуемой истории, сохранность
   текущего дерева исходников и возможность чтения резервной истории.
   Приложение не меняется: достаточно проверок Git и изменённой документации;
   нагрузочные, браузерные и сервисные тесты повторно не запускать.
5. Принудительно обновить только явно согласованные ветки и теги с проверкой
   их ожидаемых исходных SHA. Не применять безусловный `push --mirror`.
   Проверить удалённые refs и отсутствие архива в новом обычном clone.
6. Перевести участников и агентов на новые рабочие копии. Старые клоны
   оставить только для чтения и выборочного переноса работы. Не переносить
   локальные секреты и данные через Git. Зафиксировать краткий результат
   и ссылку на внешнюю резервную историю и таблицу SHA.

Внешний архив, работающий `hmc-app-live`, его конфигурация и Docker-тома
сохраняются. Их перенос и повторное развёртывание не требуются для очистки
истории. Существующая рабочая копия с приватными локальными данными не
заменяется удалением; её переключение должно сохранить эти данные.

Пользователь утвердил весь план и разрешил выполнение 26.10.2026.
Старые SHA в Issues и существующих отчётах не заменяются массово;
для их сопоставления используется внешняя таблица SHA.

## Работа после переключения

Участникам следует сохранить незакоммиченную работу вне старого clone и
клонировать репозиторий в новый каталог. Нельзя сливать старые ветки с новой
историей или отправлять старые refs. Для отдельной нужной правки используйте
патч либо выборочный перенос с просмотром diff: архив доказательств не должен
попасть в перенос. Приватную конфигурацию, исходные данные и Docker-тома
переносите отдельно от Git только при необходимости смены рабочего каталога.

На локальном хосте текущая основная рабочая копия может быть переведена на
очищенную `main` без удаления её файлов; исследовательские worktree остаются
для чтения и выборочного переноса. Локальные reflog и служебные refs могут
сохранять старые объекты: уменьшение этой старой рабочей копии не является
критерием облегчения новых clone. Локальная защита перед push должна запрещать
публикацию истории, содержащей `docs/evidence/`.
