# Единая команда управления стендом

27.10.2026 пользователь согласовал вопросы Q1–Q6: одна реализация на Node.js,
запускаемая как `node hmc-app.mjs <режим> <проект>` в Windows и Linux.
Режимы: `deploy`, `remove`, `stop`, `start`, `refresh-grib`, `status` и справка.
Команда заменит `tools/refresh_grib.ps1` после проверки новой реализации.

`deploy` подготавливает и запускает приложение без загрузки GRIB. Повторное
развёртывание существующего проекта не меняет его данные и сообщает, как
продолжить. `remove` после подтверждения имени удаляет контейнеры, сеть, тома
и настройки указанного проекта, сохраняя исходные GRIB, архивы отчётов и общие
образы. `stop` и `start` останавливают и запускают ранее развёрнутый проект.

`refresh-grib` показывает план «снять / загрузить / оставить» и запрашивает
подтверждение. Сопоставление выполняется по именам; уже опубликованные файлы
не загружаются повторно. `--dry-run` только показывает план, `--yes` отключает
подтверждение; оба флага поддерживаются также для удаления проекта.

Согласно ADR-0007 снятие прекращает доступность публикации. Новая команда
также включает очистку более не используемых данных с сохранением защиты
общих данных и активных чтений; освобождение места может завершиться позже
команды. Защитный интервал не отменяется ради немедленного удаления.
При замороженных демонстрационных часах срок физической очистки хранится
отдельно в реальном UTC и записывается атомарно со снятием. Перемещение часов
политики ради удаления изменило бы доступность исторических прогнозов.

Пользователь также согласовал Q7–Q12. Команда принимает существующий
`hmc-app-live`, сохраняя фактические тома, секреты и порты. Старые публикации
без каталога учитываются только с явным `--include-unlocated` и отдельно
перечисляются в плане. Пользователь планирует впоследствии удалить старые
публикации и загрузить данные новым механизмом; это не разрешение выполнять
удаление живых данных во время разработки.

За проектом закрепляется один каталог GRIB; попытка указать другой каталог
останавливает операцию с объяснением. Успешно выполненные этапы при ошибке
не откатываются. Повторный запуск строит новый план, пропускает полностью
опубликованные файлы и заново обрабатывает незавершённый файл. Если нет
изменений состава данных, команда не обрабатывает GRIB и не перезапускает
контейнеры. Очистка ранее снятых данных сохраняет согласованные ограничения
общих ссылок и защитных интервалов.

Для нового проекта `--viewer-port` и `--api-port` по умолчанию равны 8140
и 8141; службы доступны только на локальном компьютере. Занятые порты
вызывают ошибку до развёртывания.

Пользователь согласовал Q13–Q15: в ADMIN.md будет описан переход через
`remove`, `deploy`, `refresh-grib` с удалением прежней базы и настроек,
но сохранением исходных GRIB и архивов. Первое подтверждённое обновление
закрепляет каталог до изменения публикаций; `--dry-run` привязку не создаёт.
Для существующего стенда каталог определяется из конфигурации; неоднозначность
останавливает операцию. Имена сравниваются полностью, с учётом регистра,
одинаково на Windows и Linux. Содержимое для определения новизны не сравнивается.

В Q16 пользователь отклонил отдельный режим `clear-data`: вместо него
`refresh-grib --remove-all` удаляет все GRIB-публикации указанного проекта,
включая исторические и старые без записанного каталога, не меняет исходные
файлы и не запускает последующую загрузку. Остальные виды публикаций
не входят в эту область. GRIB-производные демонстрационные публикации
`correction`/`overlap` также удаляются: ограничение на синтетические fixtures
относится только к обычной синхронизации по именам. Сам проект и его
конфигурация сохраняются.
Правила снятия доступности, общих данных и защитных интервалов применяются
так же, как при обычном обновлении. Для этой операции не требуется чтение
исходной папки: область определяется публикациями проекта.

Пользователь согласовал Q17–Q18: перед полной очисткой выводятся последствия
и запрашивается имя проекта; доступны `--dry-run` и `--yes`. Выполняющаяся
загрузка или другое обновление данных запрещает очистку с понятной ошибкой.

Итоговое описание с дополнением о прогрессе подтверждено пользователем
27.10.2026. Обновление и полная очистка показывают одну изменяемую строку
прогресса; при неизвестном объёме используется движущийся индикатор без
выдуманного процента. В перенаправленном выводе анимация отключена.
Системные требования и проверенные версии описаны в [ADMIN.md](../../ADMIN.md).
Результаты реализации и границы проверки — в
[отчёте №60](../validation/hmc-app-60.md). Согласование разработки не означает
разрешения применять очистку или загрузку к живому стенду во время разработки.
