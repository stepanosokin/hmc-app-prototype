# Domain docs

## Read before exploring

This repository uses a single-context layout:

- Read [the root glossary](../../GLOSSARY.md).
- Read relevant decisions in [docs/adr/](../adr/).

If a domain document is absent, proceed silently.
Create domain documentation through domain-modeling when actual terms
or decisions are resolved.

## Vocabulary and decisions

Use glossary terms in issue titles, proposals, hypotheses and tests.
Consult domain-modeling when a needed concept reveals a vocabulary gap.
Explicitly identify conflicts with existing ADRs instead of silently
overriding their decisions.
