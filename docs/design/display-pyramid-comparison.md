# Пирамида отображения: согласование сравнительного прототипа

02.11.2026. [Задача №79](https://github.com/stepanosokin/hmc-app-prototype/issues/79).

Пользователь уточнил: «диаграммы» — прогнозный график точки, пирамида —
производные уровни после загрузки GRIB с сохранением исходных данных/API.
Разрешено обобщать и заливку, и изолинии. Допустимо смещение существенно
больше 1–2 пикселей ради сглаженного вида. Конкретный допуск не утверждён.

Согласовано сравнение исходного варианта и умеренного/сильного/очень сильного
обобщения на одинаковых реальных полях в обзорном и приближённом виде,
с указанием времени и объёма данных. Точка и график всегда возвращают
исходные значения ближайших ячеек с действующими правилами NoData.
Пользователь подтвердил переход к этому сравнению: «хорошо, давай так и сделаем».

В эксперименте используются уровни 2/4/8 и экранное скругление до 2/4/8 px.
Это кандидаты для выбора, не согласованные параметры промышленного LOD.
Приближение пока управляется отдельно от уровня, чтобы пользователь мог
сравнить одинаковый участок; автоматический выбор уровня предстоит определить.

Уточнение затрагивает [ADR 0011](../adr/0011-native-browser-contours.md):
изолинии могут использовать производную сетку и больший экранный допуск.
Историческая точность/приёмка не переопределяются; ADR будет пересмотрен
после выбора параметров и производственного решения. Новая ADR сейчас
не создаётся, поскольку способ и допустимая погрешность ещё сравниваются.

Начальные факты: browser loader скачивает все native-блоки без LOD; COG уже
содержат overviews 2/4, но native display читает Zarr. PointSeries делает
последовательные exact-time/nearest-native-cell запросы. Поэтому пирамида
нацелена на передачу/память карты и вычисление изолиний; пакетный API ряда —
отдельная возможная оптимизация, не часть этого прототипа.

[Запуск и границы измерений](../../viewer/prototype-pyramid/README.md).

Дополнение 02.11.2026, [№80](https://github.com/stepanosokin/hmc-app-prototype/issues/80):
пользователь принял скорость и качество заливки, отклонил угловатые/самопересекающиеся
изолинии и запросил сглаживание поверхности до их построения. В прототип добавлен
отдельный режим для изолиний; заливка и канонические значения сохраняются.
Финальное визуальное принятие нового рисунка ещё требуется.
