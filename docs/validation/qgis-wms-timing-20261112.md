# Задержки WMS в QGIS: измерения до QHD

12.11.2026 завершён согласованный объём
[измерений задержек WMS и перепроецирования](https://github.com/stepanosokin/hmc-app-prototype/issues/95)
для [карты ускорения GIS](https://github.com/stepanosokin/hmc-app-prototype/issues/93).
Пользователь исключил 4K и явно выбрал **2K = 2560×1440 (QHD)**.
Базовый уровень, Windows/PowerShell/Docker Desktop/QGIS MCP сохранены.

**Завершено исследование, включая наблюдения неуспешных кадров.**
Ограничение QHD не устранило медленные/неполные рендеры. Это не подтверждение
корректной работы всех сочетаний и не приёмка исправления продукта.

## Условия и метод

- QHD-серия: исходный HEAD `5275274c910c0bb2fb2ba376b2367b114816f7a8`;
  QGIS 3.44.11, GeoServer 2.27.0, GetMap limit 3000. Код и настройки live не менялись.
  Хеши API/gateway/geoserver/budgets совпали с предыдущей server-stage пробой.
- Проблемное поле **t / surface 0 / K**, GRIB-4-1 / 2026-10-21T06:00:00Z.
  Revision `305358c4c181b6f67e9ee23f64e28ea6d9d44a6cc2876aa4827741d5f9922f28`;
  field `3d691f71cdaaf46559eb578287a069b847d84ba6983c314b0cd6eafbfd4eeb9d`.
- Сроки 06:00→15:00Z 24.10.2026; центр 90°/60°→100°/65°;
  масштабы 1:75 364 600→1:18 000 000. CRS слоя 4326/3857;
  проекта 4326/3857/3576/LAEA 60°/90°. Размер canvas 2560×1440, обычный DPI,
  без URI size override; RenderPartialOutput включён.
- Свежий URL изолирует клиентский кеш, backend/GeoServer/ОС-кеши сохранены
  и дополнительно прогреты эталоном. Повтор того же кадра использует кеш QGIS.
  Setup/Capabilities/эталон исключены из render seconds.
- Полнота — внутренние точки альфа-маски глобального GetMap 1024×512, порог 0,99;
  это не побайтовая научная проверка. Границы и грубое разрешение дают расхождения.
  Снимки каждые 250 мс могут пропустить краткое мигание.
  Контроли без PNG не проверяют мигание.
- 15 с — ограничение наблюдения, не SLA и не серверный timeout.
  При остановке правильное время до полного кадра неизвестно, записана нижняя граница.
  Контроли продолжали следующие шаги после отмены; это отдельные условия.
  [Сценарий](../../tools/measure-qgis-wms.py) и его frozen версии/config/selection сохранены.

4326 0,68→3857 6,97→3576 6,93→LAEA 10,16 с; все контрольные маски 1.

## Составляющие задержки

- 13 QHD-серий / 52 шага / 283 нереференсных GetMap. Все HTTP 200,
  сопоставлены с gateway/API по request_id; выбранные TIME совпали с запросами.
  HTTP 200 не гарантирует кадр.
- Промежуточные GetMap часто 3000×3000. Для обзора 4326→3857:
  12 запросов / 108 млн пикселей, около 29 объёмов QHD-экрана.
  Для zoom 3857→3576: 20 запросов / 180 млн пикселей.
- QGIS process peak working set за всю последовательность 5,17 GiB;
  максимальный working set после шага 4,19 GiB. Это накопленные показатели процесса
  с кешами, не память одного кадра и не сопоставимый отдельный 4K-пик.
- Медианы API на запрос около 0,43–1,07 с; gateway минус API 40–102 мс
  в простых сочетаниях и около 0,87–1,66 с в тяжёлых.
  Последнее включает очередь/IPC/обвязку; чистое ожидание не выделено.
  Передача после заголовков на localhost мала; выводов о WAN нет.
- Предыдущая read-only stage-проба на неизменном коде: прямой GeoServer
  1206×521 0,097–0,098 с против limited-http 0,370–0,433 с;
  3000×1296 0,506–0,527 против 0,793–0,835 с. По три повтора, SHA256 совпали.
  Добавка обёртки около 0,27–0,34 с; доли запуска процесса и JSON/base64 отдельно
  не измерены. Gateway ProcessChannel постоянные.

Наиболее подтверждены затраты на промежуточные растры и CPU клиента,
повторную серверную работу/HTTP-обёртку и ожидание больших пакетов.
Точный профиль отдельных стадий не установлен. Кеш того же кадра уже работает
в QGIS; следующий вопрос должен сравнивать новые BBOX/сроки и повтор между клиентами.
Способ кеширования и замена GeoServer здесь не выбирались.

## Доказательства, очистка и пределы

[Реестр архивов и SHA256 индексов](qgis-wms-timing-20261112.archives.json).
Относительно `HMC_EVIDENCE_ROOT`:
`wayfinder-timing-95/20261112-qhd-host` — полный отчёт, корреляция логов,
входные хеши и receipts; index SHA256
`750eccc181a3ec0ab00790be350033a93037cc04b9bd5d1a04b22d76b17be600`.
Frozen изображения, HTTP, программы и конфигурации каждой попытки лежат в отдельных
`20261112-qhd-*`; предыдущие обычные/4K архивы сохранены.
Исходный предварительный текст сохранён в qhd-host/previous-report.md.

Все QHD-попытки подтвердили очистку canvas/proxy/socket и неизменность пустого проекта.
Новых аварий не было. Guard чужого профиля отклоняет запуск до создания ресурсов.
Собственный PID 21424 завершён штатно; отсутствие процесса проверено; удалён
только его временный профиль. Пользовательский проект в новой серии не открывался.
Docker-ресурсы не создавались; сохранён запрошенный **hmc-app-live**.

Исторические причины 4K-аварий и сохранность прежнего несохранённого проекта
остаются неподтверждёнными. Новый успешный изолированный запуск не доказывает обратного.
По решению пользователя завершение 4K-матрицы исключено из текущего объёма.

Продуктовые T9/T11, научная попиксельная приёмка и Identify не запускались.
Проверены согласованные измерения, сценарий изоляции, ссылки документации и архивные
размеры/SHA256. Завершение вопроса означает получение этих фактов, а не исправление рендера.
