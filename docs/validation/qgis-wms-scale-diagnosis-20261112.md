# QGIS: фрагменты и мигание WMS при увеличении масштаба

Диагностика после [№92](https://github.com/stepanosokin/hmc-app-prototype/issues/92),
исходный commit `b425b2bfbf3d62cc765a76693687133e8ecac22e`.
Согласованы базовый уровень, Windows/PowerShell, действующий `hmc-app-live`
и QGIS 3.44.11 через MCP. Серверные лимиты, код приложения и пользовательский
проект не менялись. Переключение флага проверялось на собственных скрытых canvas.

## Вывод и причинность

Подтверждён сбой клиентской промежуточной отрисовки при перепроецировании
WMS, загрузке отсутствующих в кеше данных и разбиении изображения на блоки.
При `RenderPartialOutput=true` появляются и вновь исчезают уже полученные
части изображения; итоговый кадр может остаться фрагментарным или пустым.
Отключение только этого флага восстанавливает полное изображение.

Это другой механизм, чем admission 429 из №92. На зафиксированных плохих
запусках сервер отвечал исключительно 200. Для двух повторов прежнего поля
сопоставлены все 31 GetMap: параметры и PNG побайтно одинаковы, но изображение
на canvas отличается. Последовательная передача не устранила дефект.

В официальных исходниках `final-3_44_11` найден согласующийся с результатами
механизм: основной renderer задаёт raster iterator размер из provider
(у нашего WMS 512×512), а `onNewData()` создаёт preview iterator с default
2000×2000. Preview повторно рисует тот же конвейер; RasterDrawer использует
`CompositionMode_Source`, заменяя ранее нарисованное изображение. Разная
разбивка preview/main — направление клиентского исправления; исправленный
бинарный QGIS не собирался и не проверялся.

Первичные источники: [preview и основной renderer](https://github.com/qgis/QGIS/blob/final-3_44_11/src/core/raster/qgsrasterlayerrenderer.cpp#L58),
[RasterIterator defaults](https://github.com/qgis/QGIS/blob/final-3_44_11/src/core/raster/qgsrasteriterator.h#L238),
[композиция изображения](https://github.com/qgis/QGIS/blob/final-3_44_11/src/core/raster/qgsrasterdrawer.cpp#L111),
[размер блока WMS](https://github.com/qgis/QGIS/blob/final-3_44_11/src/providers/wms/qgswmsprovider.cpp#L3847).
Точные исходники сохранены в архиве с исходными лицензионными заголовками.

В последней паре на точном URL совпали параметры и байты всех 55 GetMap
(включая независимый контрольный GetMap). Ожидание финального кадра около
40 с — это полный исходный сценарий; минимальный повтор на 2t занимает 12 с.

Проценты — доля заполненных точек контрольной сетки, где независимый
GetMap подтверждает данные. Границы/неустойчивые пиксели исключены;
для источника 3857 исключена его полярная область вне обычного охвата.
Мигание измеряется падением заполнения кадров более чем на пять процентных
пунктов при неизменном виде. Маленькое окно 320×187 и прогретый кеш могут
скрывать дефект. Поэтому одного фиксированного участка и экспортного
render job недостаточно для приёмки обычного интерактивного QGIS.

## Проверенный временный обход

В Python-консоли QGIS можно отключить промежуточный вывод текущего canvas:

```python
from qgis.core import Qgis
from qgis.utils import iface
canvas = iface.mapCanvas()
saved_flags = canvas.mapSettings().flags()
canvas.setMapSettingsFlags(saved_flags & ~Qgis.MapSettingsFlag.RenderPartialOutput)
canvas.refresh()
```

Изображение обновляется целиком после загрузки. В исследовании команда
применялась только к собственным canvas, пользовательская настройка сохранена.
Для возврата — `canvas.setMapSettingsFlags(saved_flags)` и `canvas.refresh()`;
новый canvas QGIS по умолчанию опять включает промежуточный вывод.

Повышать concurrency/request/byte budgets или таймауты по этим наблюдениям
не требуется. Увеличение WMS MaxWidth/MaxHeight может сдвинуть порог разбиения,
но не устраняет ошибку согласования блоков и требует отдельной проверки.
Следующий корректный шаг — клиентское исправление/проверка QGIS и расширение
T11: реальные canvas flags, cold/warm, несколько масштабов, кадры во времени,
разные CRS слоя/проекта и размеры окна, а не только готовое изображение.

## Повторение и границы объёма

[Проверочная программа](../../tools/diagnose-qgis-scale.py) запускается внутри
QGIS через `runpy.run_path`; вызов `probe_scale(config_path)`.
JSON фиксирует public selection, origin, source_crs, projection, scale, center,
size, canvas=true, partial_output и новый report. В архиве сохранены конфиги,
PNG ответов, промежуточные кадры, результат, snapshot программы и cleanup.
Для повторения выберите новый report и доступный путь к копии selection.

Пример внутри QGIS MCP (report в JSON должен быть новым):

```python
import runpy
probe = runpy.run_path('D:/path/hmc-app-prototype/tools/diagnose-qgis-scale.py').get('probe_scale')
probe('D:/path/reported-final-red-config.json')
```

Команда пройдена и выдаёт `Fragmentary WMS: 0.0%; HTTP {'200': 57}`.
Контроль с `partial_output=false` — 100%, без падений заполнения, те же 55 PNG.
Минимальный повтор на 2t занимает около 12 с; полный исходный показатель — 40 с.
Проверка типов всех 123 Python-файлов пройдена. Экспортный режим предыдущей
T11-матрицы создавал новые `QgsMapSettings` без `RenderPartialOutput`; поэтому
полнота готовых изображений не проверяла этот интерактивный путь.

Зафиксированы все 27 попыток, включая ошибки настройки первоначального
прототипа, исправление аннотаций и запуск с пользовательскими изменениями
проекта/конкурирующими запросами (он не используется для причинности).
Временные canvas и все proxy закрыты; пользовательский проект и флаги
основного canvas сохранены. Приложение продолжает работать без перезапуска.

Объём — диагностика и проверка обхода; исправление бинарного QGIS и изменение
настроек пользователя/сервера не выполнялись. Старый тикет №92 не изменялся.
