# Пропуски WMS в QGIS при перепроецировании — диагностика №92

[Тикет №92](https://github.com/stepanosokin/hmc-app-prototype/issues/92) открыт
для реализации исправления. Пользователь запросил диагностику и предложение
в виде тикета; согласовал базовые локальные проверки Windows/PowerShell,
действующего `hmc-app-live` и QGIS через MCP, затем серверное решение.
Исходный commit: `43d1f23d00639b95d0c5b879678b9f7956f07bf7`.

## Причина

Публичный bucket допускает два одновременных запроса. Отдельной политики
`public` в БД нет, поэтому применяется default из
[budgets.py](../../publication/budgets.py). При временной занятости слотов
[gateway.py](../../publication/gateway.py) сразу возвращает HTTP 429.
При перепроецировании QGIS отправляет несколько GetMap параллельно. Часть
запросов и их повторов отклоняется; изображение остаётся фрагментарным,
хотя слой valid и `QgsMapRendererSequentialJob.errors()` пуст.

CRS исходной сетки, CRS WMS-запроса и CRS проекта QGIS — разные понятия.
В воспроизведении сервер получает EPSG:4326, а клиент отображает результат
в EPSG:3857 либо EPSG:3576. Изменение проекции проекта влияет на пакет
запросов; доказательства не требуют исправления координат исходной сетки
или нового серверного CRS. Это сохраняет границу
[ADR-0003](../adr/0003-web-map-display-projections.md).

## Зафиксированный сценарий и результаты

- QGIS Desktop 3.44.11-Solothurn, Windows; GeoServer 2.27.0.
- Поле GRIB-4-1 / 2t, run `2026-10-21T06:00:00Z`, revision
  `305358c4c181b6f67e9ee23f64e28ea6d9d44a6cc2876aa4827741d5f9922f28`.
- QGIS запрашивает стандартный срок capabilities без TIME:
  `2026-10-24T06:00:00Z`. Прямой контроль использует тот же срок явно.
- CRS слоя EPSG:4326, CRS проекта EPSG:3857; участок WGS84
  `[80,50,100,65]`; размер изображения 320×187.
- Свежий локальный proxy origin исключает прогретый кеш QGIS; существующий
  кеш пользователя сохраняется. Шесть уникальных BBOX при параллельной
  и последовательной передаче совпадают.

| Проверка | Заполнение контрольной сетки | HTTP 429 |
| --- | --- | --- |
| `accepted-cold-1` | 30% | 16 |
| `accepted-cold-2` | 20% | 16 |
| `accepted-cold-3` | 30% | 16 |
| `accepted-serial-1`, те же запросы последовательно | 100% | 0 |
| `accepted-same-crs`, слой и проект EPSG:4326 | 100% | 0 |

Прямой GetMap каждой окончательной попытки заполняет 100% контрольной сетки.
Проценты относятся к регулярной выборке пикселей внутри заполненного участка,
а не к площади всего прогноза. Дополнительный `enforced-red` завершился
ожидаемым AssertionError: `QGIS 30.0%, контроль 100.0%` примерно за 2,2 с.
Снимки неполного и полного рендеров просмотрены.

Разведочные проверки также воспроизвели механизм на ICON-EU / T_G (30%
против 100%) и с CRS проекта EPSG:3576 (около 12% против 100%). Обратное
сочетание 3857→4326 при 320×187 прошло; совпадение CRS при 1204×700 тоже
прошло. Нельзя объявлять любое несовпадение CRS ошибочным само по себе.

Отдельный полностью пустой слой не воспроизведён; этот исход из сообщения
пользователя требует отдельного примера при реализации. Диагноз доказан для
фрагментации при конкурентном пакете запросов. Настройки данных и серверная
политика во время контрольного опыта не менялись.

## Повторение

[Проверочная программа](../../tools/diagnose-qgis-wms.py) выполняется внутри
QGIS через MCP. Указать существующий внешний архив и новый каталог отчёта:

```python
import json
from pathlib import Path
from uuid import uuid4
root = Path(r'D:/OSOKIN/PROG/HydroMetCenter/hmc-app-prototype')
archive = root.parent / 'hmc-app-evidence/qgis-wms-diagnosis/20261112'
cfg = json.loads((archive / 'accepted-cold-1-config.json').read_text(encoding='utf-8-sig'))
cfg['selection_file'] = str(archive / 'selection-2t.json')
cfg['report_directory'] = str(root / 'data/reports' / ('qgis-wms-repro-' + uuid4().hex))
config_path = Path(cfg['report_directory'] + '.json')
config_path.write_text(json.dumps(cfg), encoding='utf-8')
exec((root / 'tools/diagnose-qgis-wms.py').read_text(encoding='utf-8'))
diagnose_wms(config_path)
```

На исходной реализации ожидается ошибка неполного покрытия. Для причинного
контроля создать другой новый каталог и конфигурацию с `sequential=true`.
Последовательный proxy является диагностическим контролем, не исправлением
приложения. Программа использует публичный локальный WMS без ключей.

## Предложенное исправление и границы

Согласовано ограниченное ожидание concurrency для обычных пакетов WMS GetMap.
Тикет требует отдельной регистрации попытки и атомарного допуска того же ID,
однократного учёта, ограничений очереди по bucket и глобально, общего deadline,
сохранения rate/byte budgets, удержания слота незавершённым backend и проверки
отзыва ключа до допуска. Ожидание не должно занимать все восемь потоков gateway
и блокировать health, каталог или независимую организацию.

Предыдущая desktop-проверка сочетала одинаковые CRS источника/проекта и
проверяла только `any(alpha)`. Будущая приёмка должна проверять полноту маски,
независимые CRS, разные размеры и сроки. Реализация потребует complete T9,
двухфазного T11 и настоящего QGIS; полный T8 дополнительно при изменении
access policy. Эти приёмки исправления сейчас не запускались. Приложение,
политики, публикации и GRIB не изменялись. Исходная ошибка остаётся в live.

## Доказательства и очистка

Архив относительно `HMC_EVIDENCE_ROOT`: `qgis-wms-diagnosis/20261112`,
214 файлов; размеры и SHA256 проверены. SHA256 `archive-index.json`:
`3e102c75300d365f2d2aba620764817bc2858770060aa0dcc64131fe06f0bc28`.
Содержит JSON/PNG всех попыток, WMS-трассы, фактическую политику, каталожные
идентификаторы, замороженные исходники и их проверенные хеши.

Ранние разведочные отчёты и ошибка нормализации пути в первой версии
диагностического proxy сохранены отдельно от окончательных попыток.
В `attempt-notes.json` также отмечено уточнение фактического default TIME:
первые отчёты подписывали выбранную строку каталога, тогда как QGIS использовал
default capabilities. Окончательные попытки сравнивают один и тот же срок.

Проверены 25 receipts остановки proxy/закрытия сокетов, включая неудачную
попытку. В проект QGIS временные слои не добавлялись; исходный пустой проект,
CRS EPSG:4326 и отсутствие несохранённых изменений подтверждены. Docker-ресурсы
не создавались; состав контейнеров сохранён. `hmc-app-live` оставлен работающим.
Проверка исторических архивов не выполнялась.

Доказательства проверки ссылок, review и предкоммитного tracker readback:
`qgis-wms-diagnosis/20261112-finalization`. Изменения репозитория ограничены
проверочной программой и этой записью. №92 остаётся открытым с проверенными
диагностическими пунктами и непроверенными пунктами реализации; закрытые
№21, №23, №47, №49 и №77 сохраняют прежнее состояние.
