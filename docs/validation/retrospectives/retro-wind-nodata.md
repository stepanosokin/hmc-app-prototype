# Ретроспектива ветра и NoData: №84–85

Текущая сессия, [№86](https://github.com/stepanosokin/hmc-app-prototype/issues/86).
Источники: [проверки №84](../wind-snow-84.md), [проверки №85](../wind-threshold-85.md),
`HMC_EVIDENCE_ROOT/wind-threshold-85/backend-final/` — `acceptance.json`,
`selective/cleanup-attempts.json`, планы и логи. Это разбор текущей сессии,
а не новая историческая проверка архивов.

## Улучшения по важности

1. **Объём пересчёта проверялся слишком поздно.**
   Смена общей версии NoData запустила подготовку всех полей. После замечания
   пользователя операция остановлена до переключения каталога, её подготовка
   удалена, алгоритм исправлен на десять партий. Исправление `/4` → `/5` уже
   выполнено в №85. В ретро добавлен независимый барьер в CLI:
   `--expect-rebuild-batches` обязателен перед apply, `--expect-field`
   ограничивает одно поле. Сводка отличает фактические партии от повторно
   используемых записей и считает общие ссылки один раз. Регрессия запускает
   настоящий entrypoint с планом 334 при ожидаемых 10 и пустым PATH: отказ
   должен произойти до Docker. План с неоднозначным составом отвергается.
   Существующий NoData-runner передаёт ожидаемую одну legacy-партию своего
   seed; его прежний ресурсно-свободный AST-preflight теперь проверяет этот
   аргумент и порядок preview/apply, включая отрицательные fixtures.

2. **Очистка потребовала нескольких проб временного адаптера.**
   Не хватало `fetchone`, затем прав на приватные GIS-файлы, затем
   `MOSAIC_PASSWORD`. После неудачного preview следующая native-команда
   однажды продолжила цепочку и создала пустой архив. Теперь существующая
   инструкция cleanup явно задаёт scope одного job при полном графе ссылок,
   необходимую конфигурацию, границу архива и остановку последовательности
   при ошибке. Готовый общий API коллектора используется как основа; новый
   механизм удаления в рамках ретро не вводился. Испытание реального удаления
   потребовало бы отдельного согласования среды и disposable-ресурсов.

3. **Ошибка значения select обнаружилась в дорогом цикле.**
   Chrome ждал срок 13:00 после передачи ISO-строки селектору, принимающему индекс.
   Нынешний runner уже выбирал индекс правильно после исправления №85.
   Теперь общая граница `selectViewerOption` проверяет допустимую опцию
   и результат присваивания до change/ожидания. Node-регрессия исполняет тот же
   браузерный код с контролируемым DOM без запуска браузера. Проверка фактического
   выбранного срока в runner сохранена. Helper включён в его frozen-входы.

4. **Обход существующих команд давал лишние ошибки и неполную проверку.**
   Полный mypy в локальном Runtime и CI включает `tools`; ручная команда на
   93 файла их пропускала. [Подготовка приёмки](../../development/acceptance.md)
   уже требует брать области из существующей команды — новую копию команды
   или стандарт не добавляем. Широкие чтения выводили обрезанные логи;
   существующая сводка и чтение конкретных полей остаются основным способом.

## Размещение и границы

Проверки добавлены в существующие локальные команды и ручной CI. Режим CI
`workflow_dispatch` и локальный основной путь проекта сохранены; контроль
объёма встроен в сам apply и работает независимо от CI. Тесты границы
селектора запускаются локальным Viewer, тесты CLI — локальным Windows.
Нового фреймворка, pre-commit hook или файла coding standards нет:
обнаруженные механические ошибки закрываются исполняемыми проверками,
а scope очистки описан рядом с существующей процедурой.

`AGENTS.md` уже направляет к таблице выбора проверок; новая строка таблицы
и условные ссылки в service/browser/cleanup дают нужную навигацию без роста
постоянного контекста. Сторонние skills, приложение, конфигурация live,
серверные образы и исторические evidence не менялись.
