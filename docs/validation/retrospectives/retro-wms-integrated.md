# Ретроспектива итоговой приёмки WMS — №110

16.11.2026. Основание: текущая сессия реализации, [итог №110](../wms-110.md),
[индекс архивов](../wms-110.archives.json) и
[коммит b2dfca7](https://github.com/stepanosokin/hmc-app-prototype/commit/b2dfca769ad50c77f05492372351a3c4fb0326a0).
Пути первичных материалов ниже относительно `HMC_EVIDENCE_ROOT/wms110/`.
Согласованы минимальные проверки в Windows PowerShell + Node.js, без Docker,
браузеров, QGIS и live. Принятая реализация и закрытая №110 сохраняются.

1. **Высокий приоритет — поздний full suite на несовместимом наборе fixtures.**
   `service-final1-failed-full-suite/gate.json` сохранил failed; его full-suite
   журнал показывает 413 OutputLimit при обходе численного `/ogc/collections`.
   Независимые WMS-fixtures увеличили каталог за бюджет baseline-регрессии.
   Исправление порядка уже вошло в №110: suite выполняется после T5/restart,
   перед расширением fixtures. На свежем final2 обе фазы прошли; лимиты и
   assertions сохранены. Это граница набора проверок, а не доказательство
   успешного численного обхода всех совместных fixtures.

   Расширен существующий [QGIS preflight](../../../tools/check-qgis-preflight.mjs):
   он отклоняет поздний/ранний suite, пропуск, дубликат и дрейф mode guards,
   сохраняя suite в Complete для Development и нерасширенных режимов.
   [Негативные fixtures](../../../tools/test-qgis-preflight.mjs) воспроизводят
   старый порядок без сервисов. Проверка остаётся source-only: неизвестный
   после рефакторинга план требует пересмотра; desktop/HTTP-приёмку она не заменяет.
   Используются существующие Windows/All и Windows job manual CI, новых
   entrypoints и зависимостей нет. [Указатель QGIS](../../development/qgis.md)
   направляет к этой проверке до выделения стенда.

2. **Средний приоритет — DOM hidden приняли за видимость контрола.**
   `observations-final/browser-diagnosis.json` и журналы попыток в
   `service-final1-failed-full-suite/` показывают перекрытый run selector в
   640×360 и преждевременное нажатие CSS-скрытой кнопки. Сводка диагностики
   сохраняет раннюю гипотезу о закрытии до settings; окончательный драйвер
   закрывает уведомление после settings, когда forecast panel уже скрыт.
   Итоговые Chrome/Edge standard1 прошли, неудачные попытки сохранены.
   [Browser guidance](../../development/browser.md) теперь указывает этот
   порядок и наблюдение hit target. Общий линтер не может установить реальное
   перекрытие DOM/Qt; существующие visible-control assertions уже нашли сбой.

3. **Средний приоритет — поздняя неверная классификация Git-входов.**
   `completion-postpush/input-verification-notes.txt` фиксирует два ошибочных
   сравнения: raw Git blob с baseline CRLF, затем Git blob для ignored build.
   Итоговый `commit-verification.json` отдельно учитывает четыре неизменённых
   checkout-filter случая и 51 внешний runtime-артефакт; сборка viewer
   воспроизведена и совпала с frozen inputs. Сами входы не менялись.
   [Процедура сверки](../../development/acceptance.md) теперь начинает с одного
   tracked path/object map и классификации до чтения blobs, рядом с правилами
   raw identity. Это упорядочивает существующие правила; новый универсальный
   Git/evidence CLI из одноразовой проверки не вводится.

4. **Низкий приоритет — дорогие повторы и лишняя область проверки.**
   `observations-final/browser-reuse-after-orchestration.json` подтверждает
   единственное PS-различие среди 453 входов; combined service/QGIS повторён,
   неизменённые успешные browser-сценарии сохранены по действующему правилу.
   Дополнительная активная CDP-изоляция завершилась Invalid InterceptionId;
   она осталась failed и не засчитана как T16. [Итоговый отчёт](../wms-110.md)
   различает целевую WMS-матрицу и полный viewer/T16. Существующие указания
   по выбору affected gates и проверке CDP до полного прогона достаточны.

Проверены `viewer/package.json`, `tools/check-local.ps1` и manual CI:
типизация, unit tests и документационные проверки уже подключены. Общего
pre-commit hook и автоматических CI-триггеров нет; сохранён существующий
локальный workflow. Новое правило CODING_STANDARDS не требуется: механический
порядок контролирует guard, а review №110 явно отделил границы свидетельств.
AGENTS.md, глобальные настройки и сторонние skills не менялись.
