# Ретроспектива применения №105 к live

16.11.2026. По запросу пользователя применены рекомендации после
[обновления hmc-app-live](../live-wms105-20261116.md), commit
`40939cf1e33e23b21d424c3c324c21d70fc46cb4`. Первичные источники: текущая
переписка, отчёт обновления и `HMC_EVIDENCE_ROOT/live-update/wms105-20261116-final`.
Согласованы минимальные проверки локально в Windows PowerShell и Node.js,
без Docker, браузера, QGIS и обращения к live.

## Внесённые изменения

1. Подготовка свидетельств ранее упала с `spawnSync git EPERM`, а копирование
   продолжилось. В первом архиве нет `inputs.json` и `attempt-notes.json`;
   поздний архив содержит их. Новый `archive-prepared-validation.ps1` запускает
   подготовку с проверкой exit code, требует оба JSON, затем вызывает прежний
   архиватор. Существующие подготовленные файлы отклоняются, чтобы повтор не
   использовал старые свидетельства. Синтетические проверки подтверждают отказ
   при exit 7 даже после записи обоих JSON, отсутствующем/повреждённом/пустом
   JSON и повторе со старыми файлами.
2. Docker build и start ранее повторялись из-за stderr под PowerShell Stop.
   Существующие `publication/process.ps1` и его Windows-проверки уже решают эту
   задачу. Новый инструмент и инструкция используют этот запускатель;
   его реализация не менялась. Успешный процесс со stderr включён в проверку
   нового архивирования.
3. Первый `ResourceLimit` не получил отдельной полной HTTP-записи. Новый
   `check-live-http.mjs` сохраняет статус, длительность, request ID, выбранные
   заголовки и тело для каждой попытки; сетевые ошибки также оставляют JSON.
   Автоматических повторов нет. Синтетические ответы проверяют HTTP 504,
   успешные бинарные данные и обрыв тела после получения заголовков.
4. Ручное сравнение mounts дало ложные отказы по порядку, Windows-алиасам
   Docker Desktop и приоритету операторов PowerShell. Новый
   `compare-live-resources.mjs` сравнивает нормализованные снимки. Регрессии
   проверяют замену тома/назначения/read-only, сети, состояния и ID, лишний
   или пропавший контейнер; Linux-регистр сохраняется.
5. В таблицу проверок добавлен маршрут
   [обновления существующего стенда](../../development/live-update.md), также
   доступный из ADMIN.md. Проверки подключены к существующим Viewer/Windows
   и manual CI. Нового deploy/restart режима, политик доступа, квот или общих
   расширяемых схем не добавлено. AGENTS.md и сторонние skills сохранены.
