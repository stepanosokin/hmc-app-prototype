# Ретроспектива T16 — 21.10.2026

Основание: реализация [№28](https://github.com/stepanosokin/hmc-app-prototype/issues/28),
коммит `e96619d1bf8a2bcba4c3f953fa2cb59c44b15859`,
[история попыток](../archives.md), [review](../archives.md),
[приёмка](../archives.md), последующий запуск живой карты и вопросы о графике.
Это отдельная последующая работа; архив T16 и исходники карты сохраняются.

1. **Временная проверка T16 отсутствовала в CI.** Существующие type/unit/archive
   checks подключены, но аудит T16 выполнялся удалённым после работы скриптом.
   Добавлен `--t16` к существующему `tools/check_evidence.py` и отдельный шаг CI.
   Общие GPU/update/numeric проверки переиспользуют модуль T15. Новый модуль
   проверяет Git blob identities, наличие всех восьми попыток, offline policy
   страницы/worker/nested-worker, отсутствие внешних runtime-зависимостей,
   desktop navigation races, точный разрешённый desktop-only diff и wireless cleanup.
   Проверяются индексы, копии frozen inputs, start/end выбранных полных прогонов,
   процессы, Chrome/Edge/физический Android, native/canonical/EDR/WMS comparisons,
   responsive layouts и unavailable GPU. Синтетические негативные случаи
   пересчитывают индекс: одного `passed` или совпадения SHA256 недостаточно.
   Источники берутся из архива, а не из текущей рабочей карты. Это механический
   пробел; новое правило в CODING_STANDARDS не требуется.

2. **CDP и cleanup предположения выявлялись в дорогих прогонах.** Worker-target
   Fetch оказался неподдерживаемым; page Fetch перехватил все три контрольных
   запроса. `taskkill /T` сообщил ошибку при исчезновении дочернего процесса,
   хотя независимая инвентаризация дала ноль. Исправления уже входят в T16.
   В [browser workflow](../../development/browser.md) добавлены ранняя проверка
   page/worker/nested-worker и обязательная независимая проверка процессов.
   Новый cleanup helper и повторный service/GPU gate для этой ретроспективы
   не нужны: runtime и browser runner не меняются.

3. **Повтор Android и различие входов требуют точного объяснения.** В первой
   полной попытке Chrome не завершил click после pointerdown/up. Проверка
   того же контрола и полный повтор прошли; причина единичного сбоя не доказана.
   Guidance требует сохранять неуспешную попытку и не называть replay исправлением.
   [Acceptance workflow](../../development/acceptance.md) объясняет ограниченное
   переиспользование другой платформы после проверки недостижимости diff.
   Новый checker допускает только историческую desktop cleanup замену T16;
   произвольный runner diff с пересчитанными manifest/index отвергается.

4. **Открытие готовой карты и первый запуск были смешаны.** Первый demo launch
   не нашёл `npm.cmd` через process launcher, второй не имел одобренного
   `/evidence/selection.json`. Оба стенда архивированы и retired; третий
   опубликован и оставлен по запросу пользователя. В [viewer README](../../../viewer/README.md)
   записаны прямой Node build, порядок подготовки/публикации, approved T4 inputs,
   демонстрационные часы и отличие повторного включения готового проекта.
   Новый launcher здесь не вводится; operational script и секретный env-файл
   остаются локальными.

5. **Макет создавал ожидание графика в рабочей карточке.** Runtime запрашивает
   значение одного срока; SVG-график макета использует демонстрационные данные.
   README теперь явно описывает эту границу. Несколько опубликованных сроков
   позволяют отдельно реализовать прогнозный ряд; наблюдения требуют источника.
   График и сроки его реализации не входят в эту ретроспективу.

AGENTS.md и сторонние skills не расширяются: правила находятся у существующих
условных ссылок. Дополнительные доступы и новые reviewer rules не требуются.
Самопроверка diff относительно начального коммита включает общий путь T15,
CI wiring, смысл негативных тестов, исторические bytes и границы документации.
Результаты проверок, frozen inputs и cleanup: [validation](../archives.md).
