# Время и значения нескольких слоёв WMS — №109

[спецификация №105](https://github.com/stepanosokin/hmc-app-prototype/issues/105).
Начальный коммит: `4e980416975e5219d550be292983403872c5a631`, ветка `main`.
Согласованы базовый уровень, Windows PowerShell, Docker Desktop Linux,

## Результат

Общий WMS обрабатывает несколько LAYERS: проверяет весь состав, стили и точный
TIME до формирования результата, затем смешивает карты в указанном порядке или
возвращает отдельные блоки Identify. Отсутствие срока у любого отображаемого слоя
отклоняет весь запрос, даже при подмножестве QUERY_LAYERS. Без TIME каждый слой
получает свой ранний срок; разные начала не выдаются за сравнение одного момента.
Identify раскрывает модель, расчёт, редакцию, срок, единицы и конкретные
границы/статистическую операцию накопления. Карта, Identify и легенда закреплены
за одним снимком. Ошибки слоя, срока, публикации, сервиса, доступа и лимита различаются.

Одиночное добавление проверено штатным окном WMS. Массовое добавление трёх
самостоятельных временных слоёв разных моделей проверено штатным действием
Browser «Add Selected Layers to Project»: URI и temporal metadata формирует QGIS.
Старые слои сохраняют диапазоны и значения после новой публикации; новая общая
ссылка и повторное добавление дают срок 09:00 и 295 K. Автоматическое обновление
temporal extent не заявляется.

У окна WMS QGIS 3.44.11 сохраняется ограничение: массовый выбор даже с
«Load as separate layers» теряет temporal metadata. Отрицательный опыт записан
отдельно; его три статических слоя удалены перед Browser-проверкой.
Причину объясняет [collectDimensions QGIS](https://github.com/qgis/QGIS/blob/release-3_44/src/providers/wms/qgswmssourceselect.cpp#L992).
Рабочий путь описан в [инструкции](../qgis.md#несколько-слоёв-и-точный-общий-срок).
Программная сборка или исправление URI не заменяли пользовательский опыт.

## Финальная приёмка

Обе фазы `-CommonWms -MultiLayer` прошли на свежем
`hmc-publication-t11-w109-final2` после всех review-исправлений:

- Actual-source T5: все 24 срока, промежуточные редакции, исправления, отказы
  и сохранённые читатели; после restart — 28 редакций/28 уникальных batches
  и независимый нативный эталон 298.2274169921875 K.
- Scoped/common HTTP, многослойные точный/default TIME и порядок смешивания,
  два CRS, два срока каждого показателя, интервалы осадков, Identify 3201×1801,
  точность 0.0001 и независимые нативные константы fixtures. NoData сверху/снизу
  и полностью пустая композиция не создают вымышленных чисел.
- Реальный отказ покрытия GeoServer даёт 503 всему запросу и восстанавливается;
  проверены доступ/отзыв, очередь, независимые организации, управляющие запросы,
  дедлайн, отключение клиента, частота и байты для нескольких слоёв.
- QGIS: карта, temporal metadata, легенда и same-layer Identify; renderer
  и фактический viewport Identify 3201×1801 без обходных DPI/URI-размеров,
  независимые маски поля/NoData, отрицательный тест удалённого фрагмента.
  Холодная матрица 48/48: public/org, два CRS источника, три CRS проекта,
  два размера и два срока. Это виртуальное полотно, не физический монитор 4K.
- Многослойный desktop: 30 наблюдений — single 4, bulk 12, retained 12, new 2,
  оба CRS, карта/легенда и Identify 3201×1801. После restart повторно прочитан
  прежний многослойный снимок без republish; снятие/истечение/GC дают 410
  без подмены прогноза.

Полный Python-suite: 146 тестов, OK, 56 ожидаемых пропусков для других стендов;
четыре новых HTTP-теста отдельно выполнены в Prepare. Runtime probe,
standalone full-source mypy (132 файла), PowerShell syntax (38 файлов) и ссылки
инструкции пройдены. Доступ/бюджеты/retention policy не менялись; отдельные полные
T8/T9/T7 не требуются. Браузерное приложение и его приёмка не затронуты.

228 входов начала и конца финальной приёмки совпали. Каждая точная копия
сопоставлена с исходным размером и SHA256; дополнительно сохранены исходный GRIB,
Git attributes и инструкция. SHA256 инвентаря:

## Review и предыдущие попытки

Независимые Standards и Spec review выполнены относительно начального коммита;
оставшихся замечаний нет. Добавлены restart- и NoData-проверки композиции,
отметка desktop-фазы только после всех проверок без принятия частичных
наблюдений и безусловный cleanup canvas/tool при ошибке настройки.

Прежний helper сохранял viewport 638×478 у ни разу не показанного Qt canvas,
несмотря на внешний resize. Большой Identify выявил некорректные I/J и 400.
Исправлена реальная инициализация layout вне экрана пользователя; проверяется
фактический размер mapSettings. Первый полный HTTP-прогон и focused desktop
со сменой helper сохранены как Development; финальным является только
неизменный двухфазный final2. Ранняя проверка асинхронного Add в final2 повторена
после подтверждения загрузки четырёх слоёв, без изменения входов.

Сохранены первоначальный red-тест (404 для нескольких известных слоёв), ошибочные
эталоны прозрачности/редакции/DPI, дублирование snapshot, смешение usage запусков,
ошибки сужения типа PIL и авария QGIS при обходе rootItems(). Browser-драйвер
использует Qt indices. MCP восстановлен локальным forward 9876→9877 без изменения
настройки пользователя. Первоначальные Telegram-отказы сохранены; последующая
тестовая отправка с сетевым доступом подтверждена API.
