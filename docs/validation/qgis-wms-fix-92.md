# Исправление пропусков WMS в QGIS — №92

Задача: [№92](https://github.com/stepanosokin/hmc-app-prototype/issues/92).
Исходный commit: `a0542a7f481aa80291eff38196c9ba6c82ba98d7`.
Согласованы средний уровень, Windows/PowerShell, Docker Desktop и реальный
QGIS 3.44.11 через MCP; HTTP gateway, рендер/Identify и существующий учёт T9.

## Поведение

GetMap ожидает свободный слот в пределах исходного срока запроса. Повторный
допуск обновляет одну запись usage, сохраняет общие квоты ключей и не повторяет
HTTP-запрос к backend. Request/byte exhaustion не ставится в очередь.
В gateway допускаются шесть активных/ожидающих GetMap одного bucket и семь
суммарно; атомарный WMS-допуск ограничен двумя активными в bucket и тремя
суммарно, с сохранением меньшего лимита политики и консервативных резерваций.
Это оставляет обработчик API для управляющего запроса и место другому bucket.
См. [операторский контракт](../budgets.md).

Отзыв проверяется после admission-lock, остаток deadline ограничивает retry
DB-транзакцию. Ожидающий отключённый клиент не запускает backend. Очередь
ограничена HTTP-обработчиками; новая фоновая инфраструктура, схема БД,
серверные CRS и ручные настройки QGIS не добавлены.

## Проверки и ограничения

Development воспроизвёл исходное падение шести GetMap: 200/429 вместо шести
успехов. Исправленный сценарий завершился шестью 200, наблюдаемый public
active — максимум два. Проверены shared keys, org concurrency=4, bucket/global
overflow, health/каталог/другая организация, rate/bytes, deadline, 504 lease,
отзыв в очереди и во время DB-lock, обрыв соединения без запуска backend.

Ревью Standards/Spec выполнено относительно исходного commit. Четыре
замечания Spec исправлены и повторно проверены; открытых замечаний нет.
Дублирование подготовки HTTP-фикстуры убрано.

Complete T9 пройден на замороженных входах: T5, T8-регрессия, новые HTTP
сценарии, перезапуск и полный набор — 132 теста, 43 штатных пропуска проверок
других изолированных стендов. Исходники до/после совпали; проект удалён.
