## Поведение

`hmc-app.mjs revisions <project>` принимает один из `--report`,
`--collect-view`, `--collect-apply`, `--keep-latest`. Применение показывает
план и требует подтверждения либо `--yes`; `--dry-run` не применяет его.
План привязан к стенду, политике и состоянию редакций/заданий под writer lock;
устаревший план отклоняется до фиксации истечения.

Разовая очистка сохраняет последнюю доступную редакцию каждого расчёта.
Старые уже недоступные редакции таких расчётов тоже собираются. Полностью
истёкшие расчёты остаются областью обычной очистки; ранее начатое удаление
предыдущих редакций может завершиться. Постоянная политика не меняется.
Для отложенного удаления используются долговечные обычные часы, включая
стенд с фиксированным временем. Общие партии, исходный `/input` и активные
чтения защищены; исходный `expired_at` уже снятых данных сохраняется.

## Проверка live

На `hmc-app-live` выполнены только `--report`, `--collect-view` и
`--keep-latest --dry-run`. Применение не запускалось. Компактный каталог
содержит те же 1674 выборки; политика, 85 897 файлов и логический объём
12 682 161 779 байт совпали до/после. Отчёт содержит 195 записей редакций,
включая долговечные отметки уже удалённых; 11 доступны. План keep-latest
сохраняет последние редакции двух расчётов и выбирает 193 старые записи,
из которых только девять были доступны. Выбор записи не означает наличие
ещё не удалённых файлов. Все три операции завершились без result/apply.
