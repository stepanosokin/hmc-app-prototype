Два тикета нужны, потому что полный обход файлов перед картой и последовательное
получение описаний каталога — отдельные причины задержки с разными измерениями.
Проверки входят в каждый тикет; отдельная задача только на приёмку не создаётся.
Оба тикета прочитаны как OPEN с `ready-for-agent`, по 0/8 выполненных критериев.
[№105](https://github.com/stepanosokin/hmc-app-prototype/issues/105) остаётся CLOSED
с 16/16; прежняя спецификация и дочерние задачи не изменяются.

## Согласованные решения

- Использовать существующие `revision.batches[].discovery` и
  [нормализованный каталог](../../publication/catalogue.py), сохраняя проверку
  манифестов и научной идентичности. Новый постоянный формат и переимпорт
  не являются исходным решением.
- Проверять и читать тяжёлые данные выбранного поля/срока. Повреждение файла
  постороннего поля не блокирует исправный слой; выбранные повреждённые данные
  и недостоверные описания самого индекса отвергаются.
- Ограничивать память кешей; проверять холодное/параллельное построение,
  вытеснение, ошибки, перезапуск и старые публикации.
- На каждом запросе проверять доступность всех редакций снимка, доступ/отзыв,
  reader guard и бюджеты. Сохранять snapshot, exact/default TIME,
  атомарный многослойный отказ, latest без TTL задержки и без отката,
  410 после снятия/истечения и научные значения/NoData.
- В GetCapabilities повторно использовать общие описания. Внешние адреса,
  snapshot URL, права и текущие пределы размеров учитывать при формировании
  каждого ответа; изменяемые XML-деревья не разделять между запросами.
- Словарь домена не меняется: индекс и кеш — детали реализации, а опубликованный
  слой, редакция и снятие используются в смысле [глоссария](../../GLOSSARY.md).
  Новый ADR не требуется для этого локального обратимого решения.

## Цели будущей приёмки

Для №111: не менее 20 чередующихся прогретых GetMap каждого маршрута в одной
сборке при одинаковых gateway/поле/TIME/CRS/BBOX/размере/стиле.
Медиана общего WMS ≤1,5 медианы отдельного маршрута, PNG побайтно совпадают;
тяжёлое чтение посторонних полей отсутствует на современном наборе более
64 полей/сроков. Проверяются также Identify, легенда и масштабирование состава.

Для №112: не менее 20 прогретых GetCapabilities на одинаковых замороженных
входах; медиана минимум втрое меньше исходной версии. Повторных запросов
описания каждого слоя нет. Эффект второго тикета отдельно сравнивается
с принятым результатом первого.

Холодные/legacy затраты, медиана/p95, ошибки, размеры, память и ограничения
фиксируются отдельно. Абсолютный SLA и производственная ёмкость не обещаются.
Исходный baseline измеряется в изолированном стенде, прежние наблюдения live
не заменяют его.

Перед реализацией отдельно согласуются уровень тестирования и точный порядок
запуска. Требуемые gates определяются по [таблице изменений](../development-workflow.md):
Development, затем применимый двухфазный T11 с ordinary QGIS 3.44.11,
`-CommonWms -FullCatalogue -PublicationUpdates -MultiLayer`, actual-source T5
и включённые регрессии. Полные T8/T9/T7 добавляются при изменении их политик.
Все тестовые ресурсы принадлежат отдельным стендам.

## Проверка оформления и границы

Проверяются тексты/ссылки, состояние и чеклисты обоих тикетов, штатная зависимость,
различие ветки с исходным commit и сохранность основной рабочей копии/live.
Продуктовые тесты, HTTP-пробы, браузер и QGIS в этой задаче не запускались.
Docker использован только для чтения метаданных существующих контейнеров;
новые тестовые ресурсы не создавались. Сравниваются идентификаторы, образы,
время запуска и множества подключений, порядок вывода mounts значения не имеет.

Первый подробный черновик отклонён автоматической проверкой; опубликованы
сокращённые переносимые требования. Коннектор записи вернул 403;
использован штатный repository helper, затем выполнен readback коннектором.
Это оформление задач, не подтверждение реализации.

Полные материалы и размеры/SHA256 новых копий сохраняются по
[правилам evidence](evidence-storage.md). Исторические архивы не проверяются.
Commit/push и remote HEAD подтверждаются после фиксации этой записи;
тикеты остаются открытыми и неприменёнными.
