# Отсутствие изолиний на hmc-app-live — №75

[Тикет №75](https://github.com/stepanosokin/hmc-app-prototype/issues/75),
связан с [№74](https://github.com/stepanosokin/hmc-app-prototype/issues/74).
Исходный HEAD — `c48508407b44b95b4cd7955e232a9afac22ee898`.

## Воспроизведение и диагноз

Прямая команда `node tools/check-live-contours.mjs data/reports/contour-live/<fresh>`
трижды воспроизвела симптом: растр ready=true, кнопка есть, canvas=false,
contours=null. Ошибка — `Live viewer has no isoline runtime`, 3–4 с.
Сценарий минимален: только открытие исходного live URL без кеша, без прокси,
без выбора другого поля и без сборки подменяемого просмотрщика.

Проверены три гипотезы: старая сборка, недоступность модулей и кеш перед сервером.
Подтвердилась первая. Live HTML содержит `contourToggle`, но `/build/main.js`
не содержит `ContourOverlay`, а `/build/contours.js` и `/build/contour-worker.js`
возвращают 404. Ответы имеют `Cache-Control: no-store`; cache-busting не меняет
SHA256 main.js. Его байты совпадают с локальным старым `data/viewer/build/main.js`.

Причина: отдельные read-only bind mounts исходников `viewer` и готовой сборки
`data/viewer` позволяют обновить HTML, сохранив старый JavaScript. Приёмка №74
проверяла отдельную замороженную сборку, а live-сервисы по её объёму не менялись.

## Подготовленное исправление

Старая сборка сохранена в `contour-live/before-build-01`. Проверен абсолютный
путь рабочего каталога, сохранены идентификаторы пяти live-контейнеров и хеш
компактного каталога публикаций. API/БД/GRIB не менялись.

Новая сборка подготовлена **вне live**: `data/reports/contour-live/prepared-01/build`.
Все 22 модуля побайтово совпадают с принятой сборкой
`contours74/acceptance-chrome-05/site/build`. Регрессия добавлена в
[check-live-contours.mjs](../../tools/check-live-contours.mjs), порядок обновления —
в [ADMIN.md](../../ADMIN.md#обновление-кода-просмотрщика).

Изолированная проверка `contours74/live-candidate-01` прошла: исходное поле,
давление и пять увеличений, семь снимков, runtime изолиний готов. Она использует
отдельную сборку и read-only доступ к live API; это проверка кандидата, не
подтверждение исправления самого live. Её браузер, профиль и прокси удалены.

## Применение и прямая приёмка — 30.10.2026

Автоматическая проверка разрешений отклонила команду `node viewer/build.mjs`,
поскольку она изменяет каталог, используемый работающим hmc-app-live, а сообщение
о сбое не было признано явным разрешением на live-обновление. Команда не запускалась.
Проверка после отказа подтвердила: live main.js остался неизменным.
Подготовка сборки в отдельном каталоге не применяет её к live.

После явного ответа владельца «разрешаю» выполнен `node viewer/build.mjs`.
Применены только статические файлы существующего hmc-app-live. Все 22 локальных
модуля и их HTTP-ответы 200 JavaScript совпали по SHA256 с подготовленной и ранее
принятой сборкой. Идентификаторы/образы пяти контейнеров и SHA256 компактного
каталога публикаций не изменились. Сервисы не перезапускались, API/БД/GRIB не менялись.

Прямая регрессия прошла в Chrome и Edge на 1440×900, 360×740 и 640×360:
runtime ready, 29–92 контура, непустые пиксели canvas, выключение/включение
сохраняет выбранный растр. Успешные попытки: `green-01/02/03/05/07/08`.
`green-04/06` при параллельном запуске получили HTTP 429 для основного поля;
это не прежнее отсутствие JS runtime. Их последовательные повторы `green-07/08`
прошли без изменения лимитов стенда. Все попытки сохранены, профили удалены,
собственных браузерных процессов осталось ноль. Снимки 360×740 и 640×360 осмотрены.

Прямая проверка создана до исправления и трижды обнаружила исходный дефект.
Ревью изменений относительно исходного HEAD: инструкция, прямая регрессия,
этот компактный отчёт; приложение и алгоритм изолиний не менялись. Проверки
синтаксиса Node, ссылок документации и diff не создают тестовых ресурсов.
Полная научная приёмка №74 используется по побайтовому совпадению сборки;
историческая проверка всего архива отдельно не запускалась.
Физический Android остаётся явно отложенным по решению владельца от 30.10.2026;
его прохождение не заявляется. Итоговые коммит/push и закрытие читаются после публикации.
Предкоммитное ревью и замороженные исходники — `final-02` (тикет открыт, 4/5).
Подготовительная `final-01` остановилась на sandbox EPERM дочернего git,
не создав тестовых ресурсов; повтор с необходимыми правами прошёл.
