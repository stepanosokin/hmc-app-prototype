# NoData ветра 10 м: порог 0,01 м/с — №85

Задача [№85](https://github.com/stepanosokin/hmc-app-prototype/issues/85).
Начальный commit `b9f8aad7cf65243d40f7b107579b85a01274eb0c`, ветка `main`.
Пользователь подтвердил строгий порог и базовые проверки: Docker, API и
Chrome/Edge на `hmc-app-live`. Это заменяет точечное правило №83.

- Причина: `field-validity/4` отклоняла только одно точное значение и его
  float32-представление. Значение `0.0006662628415582928` в сроке 13:00 UTC
  встречалось в 246145 ячейках и оставалось допустимым. Регрессия сначала
  воспроизведена без исправления.
- `field-validity/5`: только скорость GRIB2 0.2.1 в м/с на
  `heightAboveGround` 10 м отклоняет значения <0,01, включая ноль.
  Ровно 0,01 допустимо; U/V и остальные уровни сохраняют свои правила.
  Проверены ближайшие float64-значения ниже/выше порога, приоритет исходного
  пропуска, статистика и сохранение чисел в Zarr/COG/native metadata.
- Исправлен выбор партий при переходе `/4` → `/5`: сравнивается записанное
  правило конкретного поля; неизменённые правила совместимы. План содержит
  `rebuild_keys`. На live пересчитаны только десять партий ветра; остальные
  324 партии повторно использованы с теми же идентификаторами. Переходы с
  более старых версий и изменение версии палитры сохраняют консервативную проверку.
- Независимый аудит десяти фактических массивов: маска в точности соответствует
  порогу, маски COG совпадают с Zarr; API-точки возвращают `rejected_value`.
  В GIS для указанного значения Identify возвращает NoData. Исходные численные
  хеши и исходные пропуски всех 334 выборок сохранены; остальные поля сохранили
  также статистику. Всего отклонены 2462004 ячейки, дополнительно 2215539;
  минимум допустимой скорости среди сроков — `0.010005646423581363` м/с.
  У срока 13:00 минимум `0.011094499239713547` м/с.
