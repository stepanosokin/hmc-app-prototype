# Восстановление живого демостенда — №43

22.10.2026 выполнено операционное восстановление запрошенного пользователем
`hmc-app-live`. [Задача №43](https://github.com/stepanosokin/hmc-app-prototype/issues/43).
Исходный HEAD — `0c0c66ee5353a4287733bb8fe6b821a274fb8ac1`.
Код приложения, алгоритмы, миграции, политики и credentials не менялись.

Причина: локальный `published.json` сохранился отдельно от пустой БД.
Каталог воспроизводимо возвращал HTTP 503. Роль `hmc_gateway` не имела USAGE
на схему `access`; её таблицы отсутствовали. Отдельная access migration
восстановила доступ, но API обнаружил отсутствие `app.retention_policy`.
Полная штатная миграция через `publication.recovery.migrate()` устранила 503;
каталог стал отвечать 200 с пустым списком. SQL подтвердил отсутствие заданий,
ревизий и старых публикаций. Факт потери/замены конкретного Docker volume
не установлен; наличие старого marker не подтверждает сохранность БД.

Выполнены существующие процедуры без обработки очереди при миграции:

```text
python -m publication.access migrate
python -c "from publication.recovery import migrate; migrate()"
init-assets
worker submit --clock 2026-10-19T05:00:00Z --hours 1,3
worker once
```

Миграция не изменила существующие записи публикаций: SQL-снимки до и после
пусты. После подтверждения пустой БД восстановлены реальные сроки +1/+3 ч
из частного GRIB с SHA256, указанным в [inputs.json](inputs.json).
Четыре одобренных входа T4 сверены по SHA256 с известными файлами архива T4.
Ручных GRANT, смены паролей, удаления volumes или подмены значений не было.

Финальная проверка после обзора документации:

- Страница и [каталог](reports/after-http.json) возвращают 200. Три записи
  соответствуют первой промежуточной и итоговой ревизиям реальных +1/+3 ч.
- [Точечный запрос](reports/point.json) для 10° в. д., 50° с. ш., +3 ч
  вернул 278.68756103515625 K, `nearest-native-cell`, `exact`.
- [Native block](reports/native-block-check.json) возвращает 200; SHA256
  совпадает с опубликованными [метаданными](reports/native-metadata.json).
- Обычный `hmc-demo -Action start` завершился успешно, ссылка
  `http://127.0.0.1:8140/`; [result.json](ready-start/result.json) — `ready`.
- Локальный marker обновлён после подтверждения готовности; его старое
  значение сохранено в [published-marker-before.json](reports/published-marker-before.json).

Неуспешные попытки сохранены в `failed-start/`, `after-access-only/` и
`reports/`: первоначальный 503, отсутствие retention, пустой каталог после
миграций. В диагностических командах дважды потребовалось исправить проверку
пустого stdout через `ReadAllText`; это не повторяло миграцию. Дополнительный
probe использовал непубликуемый viewer маршрут `tiles.json` и получил 404;
проверка повторена по фактическому `native_display`. Имя поля representative
block уточнено по метаданным перед успешной проверкой SHA256. Эти ошибки
проверочных команд не считаются успешной приёмкой и не меняли приложение.

Обзор: изменены только инструкции восстановления и этот архив. По таблице
change-to-check для документации выполнена проверка ссылок и хешей. Работа
с живым экземпляром проверена реальными HTTP/SQL запросами; T5/T8, GPU и
браузерная матрица повторно не заявляются: исходники и контракты не менялись.
Проверка точечного значения устанавливает работоспособность, а не новую
независимую оценку научной точности.

[Cleanup](reports/cleanup.txt): шесть одноразовых контейнеров удалены через
`--rm`, отсутствие проверено Docker. Отдельных тестовых проектов нет.
**Сохранён работающий `hmc-app-live` по запросу пользователя**, включая его
тома; исходный GRIB, исторические доказательства и общие кеши сохранены.
Секреты и исходный GRIB в этот архив не включены.

Архив фиксирует фазу до коммита; issue ещё open, push ожидается. Итоговые
коммит, remote HEAD и закрытие фиксируются в задаче после публикации.
