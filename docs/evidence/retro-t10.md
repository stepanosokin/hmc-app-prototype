# Ретроспектива реализации T10

Дата: 20.10.2026. Исходный коммит ретроспективы:
`1efc9ee346d02ea25e43854586ff4146f2ff47d1`.
Объект — реализация [№22](https://github.com/stepanosokin/hmc-app-prototype/issues/22).
Источники: текущая сессия, [неуспешные попытки](t10/failed-probes.md),
[ревью](t10/review.md), [доказательство deadlock](t10/deadlock-review.json),
[итоговая приёмка](t10/validation.md), [очистка](t10/cleanup-summary.json),
[CI](../../.github/workflows/checks.yml) и существующий
[development workflow](../development-workflow.md).

Выводы в порядке значимости:

1. **Диагностика должна предшествовать удалению стенда.** Первый полный gate
   получил 503, но автоматический retirement удалил контейнеры до чтения их
   логов. Успешный повтор не объяснил отказ; следующая полная попытка снова упала.
   Сохранённые логи focused-пробы установили deadlock INSERT access.usage ↔
   ALTER TABLE после CREATE INDEX. В реализации уже добавлен failure-log handler
   T9. Workflow теперь указывает этот порядок и требует считать необъяснённый
   failed gate отдельной неуспешной попыткой, даже если повтор прошёл.

2. **Ревью миграций должно учитывать живых читателей.** Наличие IF NOT EXISTS
   скрывало тяжёлую блокировку при повторном запуске worker. Это суждение о
   нескольких транзакциях и порядке блокировок, а не основание запретить DDL
   синтаксическим линтером. В workflow расширен существующий разбор учёта:
   repeated provisioning под трафиком, lock upgrades и отдельная проверка
   legacy-схемы. Используются уже существующие T5/T9 проверки. Исправленная
   проба реализации выполнила 24 публикации и 372 запроса без отказа; новый
   legacy-upgrade тест и полный объединённый gate прошли в №22.

3. **Отсутствующие Zarr chunks могут выглядеть как значения.** Ранний тест
   после удаления longitude directory получил 200 с fill value, а не 503.
   Ревью расширило защиту с metadata на ожидаемые chunks. Workflow направляет
   такие изменения к существующему point/EDR fault/recovery тесту и проверенному
   manifest inventory. Первичная проверка sampler не заменяет эту границу;
   допустимая sparse fill и native nodata сохраняют собственную семантику.

4. **Сверка Git-байтов была отложена до подготовки коммита.** Working inputs
   и финальная приёмка совпадали, но Git нормализовал CRLF в evidence checker.
   Правило сохранения байтов уже добавлено в `.gitattributes` реализацией №22.
   В workflow ранняя проверка теперь использует встроенный `git hash-object`
   с фильтрами и без них; после staging и commit остаётся сверка фактических
   blobs. Это перенос детерминированной проверки до дорогого gate, без нового
   параллельного evidence checker. Проверены совпадающий защищённый файл и
   искусственный CRLF-файл, для которого нормализация обнаруживается.

5. **Существующие проверки нужно запускать до выделения проекта.** Ошибки
   передачи `*match.groups()` уже ловил mypy, но одна попытка создала ранний
   Compose-проект ради обнаружения ошибки типов. Workflow уже требует host-bind
   mypy в имеющемся locked image до выделения стенда — это правило сохранено.
   Готовый маршрут tracker 403 сохранён; для списка документов уточнён прямой
   PowerShell-вызов с массивом `-Path`. Дополнительные линтеры, hooks и CI jobs
   не добавлялись.

Правки ограничены workflow и этим отчётом. AGENTS.md уже содержит подходящий
условный указатель; его объём не увеличен. Сторонние навыки, код приложения,
runners, конфигурация CI и исторические свидетельства T1–T10 не менялись.

Проверка ретроспективы: стандартный documentation checker, отдельная проверка
ссылок этого отчёта, Git diff относительно исходного коммита и локальная проба
Git-фильтров с удалением временного файла. Runtime/Compose не запускались.
Новых Docker-ресурсов и live stacks нет; проектов для retirement в этой
ретроспективе — ноль. Архив реализации остаётся в
`data/archives/publication/`; его 15 retirement receipts сохранены в T10.
