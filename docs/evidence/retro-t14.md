# Ретроспектива T14 — 21.10.2026

Основание: текущая сессия реализации
[№26](https://github.com/stepanosokin/hmc-app-prototype/issues/26),
коммит `b21834d413015bbb04ebf2dfbbf72f81f74b82d5`,
[история попыток](t14/validation.md#история-development),
[review](t14/review.md), [полная приёмка](t14/validation.md#полная-приёмка-21102026)
и [проверка Git index](t14/checks/git-index-verification.json).
Это отдельная последующая работа. Принятый архив T14 сохраняется побайтно;
функциональность просмотрщика и сторонние skills не изменяются.

1. **Проверка T14 осталась во временном скрипте и не попала в CI.**
   Существующий workflow уже запускал viewer type/unit checks, T13 verifier
   и Python evidence checker с отрицательными тестами; отсутствие guardrail
   в целом не было проблемой. Новый архив T14 из 1012 файлов не был подключён
   к этому механизму. `tools/check_evidence.py --t14` теперь проверяет его
   хеши, полноту копий frozen inputs, Chrome/Edge × четыре viewport,
   числовые и canonical point матрицы, шесть tile/decode/upload races,
   поздний point response, наблюдения prototype и cleanup.
   Исторические inputs сравниваются с сохранёнными байтами, а не с будущим
   live workspace. CI использует тот же checker и существующий `test_evidence.py`.
   Синтетические случаи отклоняют неполные доказательства даже после пересчёта
   внешнего artifact index: одно слово `passed` не доказывает полный gate.
   Это механический пробел покрытия; новый coding standard не требуется.

2. **Два дорогих прогона проверяли неверные предположения тестового драйвера.**
   `dev1` пытался закрыть drawer после смены расчёта, хотя он уже закрыт.
   `dev2` принимал второй пункт списка за другой расчёт, хотя там была другая
   редакция того же расчёта. Эти дефекты уже исправлены в принятом
   `viewer-navigation.mjs`; новый драйвер не нужен. Browser workflow теперь
   направляет сначала к `-Navigation -NavigationOnly`, выбору по идентичности
   и наблюдаемой видимости панели. Последующие полные gates сохраняют прежний
   объём. В этой ретроспективе Compose/GPU повторно не запускаются: runtime
   и browser runner не меняются.

3. **Признаки успешного сценария должны доказывать нужный переход.**
   Review заменил накопительный `deletions > 0` проверкой конкретной текстуры,
   а строковую ссылку на prototype — выполнением его видимых переходов.
   Там же исправлены утечка `T13_FOCUSED` и пустое числовое сравнение в
   NavigationOnly. Эти исправления уже входят в T14; ретроспектива добавляет
   автоматическую проверку сохранённых full/focused признаков, реальных
   held/released событий и непустых числовых матриц. Существующий browser
   сценарий остаётся проверкой фактического GPU поведения; archive checker
   не воспроизводит его и не заменяет визуальную оценку.

4. **Правило фиксации входов было прочитано слишком поздно.**
   В `dev1` main.ts менялся после start snapshot; эта попытка явно исключена
   из acceptance. Само правило уже существует. Добавлен условный указатель
   из browser workflow на input-freeze перед первым Development-прогоном,
   без расширения AGENTS.md и дублирования процедуры.

5. **Большие чтения и временная автоматизация увеличивали стоимость завершения.**
   В сессии большие объединённые чтения обрезались, а sandbox запрещал
   subprocess из Node. Для ретроспективы использованы узкие чтения и имеющийся
   закреплённый Python-контейнер: новый checker остаётся в репозитории.
   Существующие launcher, SHA256, пакетная проверка Git index и repository-scoped
   tracker helper уже решают соответствующие задачи; их второй версии и
   новых общих запретов в AGENTS.md не добавлено.

Изменения ограничены checker/tests/CI и проектной документацией. Исходные
third-party навыки, viewer, числовые допуски и принятые evidence не меняются.
Проверки ретроспективы и отсутствие оставленных ресурсов сохраняются в
[retro-t14-checks](retro-t14-checks).

Development typecheck; его отказ сохранён отдельно. Пять входов checker/CI
