# Ретроспектива реализации T11

Дата: 20.10.2026. Исходный коммит ретроспективы:
`6816a0c734d074efbea0fc89e0dbaf83ad570903`.
Объект — реализация [№23](https://github.com/stepanosokin/hmc-app-prototype/issues/23).
Источники: текущая сессия, [попытки](t11/failed-probes.md),
[отказ T8](t11/development-access-failure.stderr.log), [ревью](t11/review.md),
[приёмка](t11/validation.md), [очистка](t11/cleanup-summary.json),
[CI](../../.github/workflows/checks.yml) и [workflow](../development-workflow.md).

Выводы в порядке значимости:

1. **Предпосылки перенесённого сценария нужно проверять до полной цепочки.**
   Первая полная попытка потратила 280.983 s на T5 и 425.709 s на WMS,
   затем T8 получил 200 вместо ожидаемого 503: новый runner не включил
   `T6_TEST_FAULTS=1`. Флаг уже присутствовал в исходных T8/T9 runners.
   Исправление и запуск T8 policies в Development уже вошли в №23.
   Workflow теперь требует переносить flags/mounts/fault coordination вместе
   со сценарием и сначала доказывать отказ/восстановление в focused-запуске.
   Это условие композиции нескольких компонентов; проверяет его существующий
   интеграционный сценарий, а не новый синтаксический линтер.

2. **Настольная совместимость должна проверяться рано и отдельно от HTTP.**
   HTTP уже проходил, когда QGIS выявил начальный GetCapabilities без VERSION
   и пустой временной домен URI без `timeDimensionExtent`. Ревью затем нашло
   независимое время identify: renderer использует клон provider.
   Эти дефекты исправлены и покрыты существующими HTTP/Desktop проверками.
   Workflow добавляет указатель на T11 и требует сначала Development с
   закреплённым клиентом, а при ревью — отдельный разбор времени map/identify
   и сравнение различающихся значений. Детерминированный запрет конкретного
   PyQGIS-вызова не установил бы корректность этого состояния.

3. **Диагностика клиента может содержать ключ.** В первой неудачной пробе
   `layer.error().message()` вывел URI с заголовком одноразового ключа.
   В реализации уже применено общее сообщение ошибки, ключ и его хранилище
   удалены при retirement; секретное значение здесь не воспроизводится.
   Workflow теперь относит authenticated source URI и содержащие его ошибки
   к credentials и направляет к очистке диагностики перед общим выводом.
   Правило зависит от содержимого сообщения; оно не запрещает API ошибок
   без учёта контекста. Сохранение проекта с ключом отдельно описано в qgis.md.

4. **Матрица клиента должна соответствовать выбранной ревизии.** Выбор
   максимального домена привёл к 240 HTTP-наблюдениям по 24 срокам и долгому
   повторению уже выполненного T5. В итоговой реализации выбрана сохранённая
   ревизия 01/03 на фоне 24 опубликованных сроков и другого run: весь её
   домен проверяется в HTTP и QGIS, а чужие гранулы исключаются. Workflow
   фиксирует этот принцип; полный T5 остаётся обязательной регрессией.
   Старая успешная фаза не использовалась вместо нового замороженного gate.

5. **Использовать готовые средства раньше, а не добавлять дублирующие.**
   Mypy несколько раз находил ошибки новых Python-проб; существующий CI уже
   выполняет эту проверку, а workflow уже требует её до выделения Compose.
   Это правило сохранено без повторного текста. Первые поиски инструментов
   выводили слишком широкие описания, а справочные PyQGIS-пробы обращались
   к недоступным методам. Новый условный указатель ведёт к рабочему helper и
   процедуре подключения, чтобы будущая работа начиналась с проверенного пути.

Дополнительных hooks, линтеров и CI jobs не добавлено: обнаруженные дефекты
либо уже исправлены и проверяются реализацией №23, либо требуют суждения о
состоянии клиента и конфигурации интеграционных сценариев. Замечания ревью о
раннем публичном error check и сохранении failure logs уже устранены и были
описаны прежним workflow; повторные правила не добавлялись.

Изменены только workflow и этот отчёт. AGENTS.md уже ведёт к workflow для
runner/scientific-compatibility изменений; его объём не увеличен. Сторонние
навыки, код приложения, runners, CI и исторические свидетельства T1–T11
остались прежними. Родительские задачи и закрытая №23 не редактировались.

Проверка: стандартный documentation checker, отдельная проверка ссылок двух
изменённых документов и Git diff относительно исходного коммита. Runtime и
Compose для этой правки документации не запускались. Новых Docker-ресурсов
не создано; проектов для retirement в этой ретроспективе — ноль. Семь архивов
реализации остаются в `data/archives/publication/`; receipts сохранены в T11.
