## Проверенные критерии

| Критерий №20 | Доказательство |
| --- | --- |
| Создание/ротация/отзыв, защищённое хранение | `t8-access.json`: реальные команды CLI, эксклюзивный файл 0600, отказ перезаписи, SHA256 вместо исходного секрета, безопасный list, атомарная ротация, повторный отзыв; `access-upgrade` и `access-remigrate` на непустой базе |
| Публичный и защищённый профили, 401/403 | `access-acceptance.stderr.log`, `t8-access.json`: Bearer/X-API-Key, отсутствующий/неверный/отозванный ключ, numeric/gis/all, публичный запрос без секрета; политика в `docs/access.md` |
| Проверка до кеша, отсутствие обхода | Тёплый числовой тайл остаётся доступен при остановленной генерации, холодный возвращает 503; edge-контейнер не соединяется с API/GeoServer/DB; только gateway имеет host-порт; admin/assets/staging вне белого списка |
| Отзыв не нарушает другую организацию | Первый ключ теряет доступ после ротации; новый — после revoke; независимый ключ второй организации продолжает читать те же point/metadata/tile/WMS; revoked `If-None-Match` возвращает 401 |
| Нет секретов в URL/публичных страницах/журналах | URL-параметры ключей отвергаются без отражения значения; публичный профиль не использует ключ; `t8-restart.json` подтверждает сканирование реальных журналов/отчётов; переносимые артефакты дополнительно проверены на все сгенерированные пароли и временные ключи |
| Numeric metadata/bytes под той же политикой | Каталог, tile URL и WMS capabilities сохраняют `/org`; метаданные и bytes проходят проверку до backend, включая прогретый кеш и прямые object/backend URL; `t8-access.json` |

Недоступная база авторизации приводит к 503 даже для прогретого тайла
(`t8-auth-store-failure.json`). После перезапуска DB/API/gateway/GeoServer
сохраняются действующий ключ второй организации и отказ отозванному
(`t8-restart.json`). Прямые внутренние и административные адреса не являются
публичными маршрутами. Общедоступные продукты намеренно остаются в публичном
профиле: отзыв закрывает организационный профиль, а не удаляет public demo.

## Проверки и review

Все 23 native process results финального runner имеют exit 0
(`process-results.jsonl`). Typecheck, три gateway boundary-теста и runtime
startup/shutdown probes прошли. Перед дорогим acceptance выполнен существующий
`sanitized_service_failure`: реальная ошибка GeoServer сохраняет прежний
санитарный контракт.

T5-регрессия прошла без пропуска: 24 реальных времени, последовательная
видимость, late/missing/correction/overlap, старые читатели и реальные сбои
GIS/тайлов. После рестарта проверены 28 immutable batches и 28 revisions,
гранулы/identify и сохранённое значение `298.2274169921875 K`
(`t5-acceptance.json`, `t5-restart-and-manifests.json`). Synthetic fixtures
явно помечены и дополняют реальный образец.

Полная suite: **32 теста, OK, 13 ожидаемых skips**
(`full-suite.stderr.log`), native exit 0. Skips относятся к отдельно
включаемым T5/T6/T7/T8 HTTP-профилям и старому T4 job fixture; T5 и T8
в данном runner запущены отдельными реальными фазами без skip.
T6/T7-специфические acceptance не заявляются: recovery/retention алгоритмы
не менялись. Проверка целостности охватила 213 архивных ссылок и отвергла
одноразово повреждённый T8 gate; исторические доказательства не изменены
(`integrity.stdout.log`).

Двухосевой review незакоммиченных изменений относительно начального commit
завершён: Standards — 0 открытых замечаний; Spec — 0 после исправления
upgrade-команды. См. `review.md` и `failed-probes.md`. Неуспешные
разработческие прогоны сохранены отдельно и не подменяют финальный gate.
