# Очистка контейнеров и образов демостенда — №44

[Задача №44](https://github.com/stepanosokin/hmc-app-prototype/issues/44),
22.10.2026. Исходный HEAD — `84ed670d90f117c1902dfb5fb7dfc186d5aab35c`.

`hmc-demo stop` теперь архивирует inventory, проверяет принадлежность каждого
контейнера проекту и репозиторию, выполняет `container rm --force` для всех
контейнеров проекта, удаляет сети и захваченные образы. Тома, исходники,
credentials и посторонние проекты сохраняются. Реестр `purge-targets.json`
сохраняет image ID и ссылки до удаления контейнеров; повторный stop продолжает
очистку без env-файла и без оставшихся контейнеров. Успех подтверждается
отсутствием контейнеров, сетей и захваченных image ID.

Удаление образов использует `--no-prune` без `--force`. Образ, используемый
посторонним контейнером, остаётся; команда завершается с ошибкой и записывает
неполный `purge-result.json` с image ID и контейнерами, блокирующими удаление.
Следующий start требует предварительно восстановить удалённые образы.

Проверки после обзора и исправлений:

- [Финальный Docker-архив](final-docker.zip): три настоящих контейнера
  (running/stopped/orphan), два разных уникальных дочерних образа, проектная
  сеть и том. Ошибка записи inventory сохраняет все три контейнера. Затем
  контейнеры и сеть удалены, эксклюзивный образ удалён, общий образ и чужой
  sentinel-контейнер сохранены, том сохранён. После удаления собственного
  sentinel повторная очистка без проектных контейнеров удаляет образ по
  реестру. Повторный purge успешен, кешированный базовый образ сохранён.
- [Финальный lifecycle-архив](final-lifecycle.zip) и
  [stdout](checks/lifecycle-final.txt): готовый запуск со ссылкой, статусы,
  отказ удаления контейнера, успешный stop, повтор без env-файла, общий образ
  с ошибкой неполной очистки, успешный retry, пустой каталог и native exit 7.
  Это синтетический Docker/HTTP fixture, а не повторная GPU-приёмка.
- Windows process check прошёл (exit 0/7, пути/аргументы с пробелами,
  stdout/stderr), [журнал](checks/process-check.txt), сырые результаты в
  `process-check/`. Его временный каталог удалён.
- `stop -WhatIf`, синтаксис PowerShell, read-only Compose config, ссылки и
  [штатный валидатор навыка](checks/skill-validation.txt) прошли.

Во время обзора исправлена дедупликация Hashtable: `Sort-Object -Property`
не выделял свойства словарей, теряя разные образы. Введено преобразование в
PSCustomObject, а реальная проверка расширена вторым image ID и повторена.
Две ранние ошибки проверки сохранены: UTF-8 без BOM не разбирался Windows
PowerShell; затем guard ошибочно считал `--no-prune` глобальным prune.
Исправлены BOM и точный запрет команды prune. Development-архивы сохранены
отдельно и не устанавливают окончательную приёмку. Первая попытка реального
check завершилась на разборе helper до создания Docker-ресурсов.

Все шесть ZIP сверены по числу файлов, длине и SHA256 каждого исходного файла;
[результат проверки](archive-check.json). Точные входы — [inputs.json](inputs.json).
Первая проверка ZIP ошибочно приняла запись каталога с Windows-разделителем
за файл; после учёта обоих разделителей проверены все исходные байты.
Ресурсная очистка теста подтверждена [retirement.json](retirement.json) и
`cleanup.txt` внутри Docker-архивов: тестовые контейнеры, сети, тома и оба
уникальных дочерних образа отсутствуют; общие образы и кеши сохранены.

Живой `hmc-app-live` проверен только чтением и оставлен работающим по прежнему
запросу пользователя: [inventory](checks/live-inventory.stdout.log).
Общий PostGIS используется также остановленным `vgdb_tools-vgdb-db-1`:
[подтверждение](checks/shared-postgis.stdout.log). Его удаление не является
очисткой исключительно демостенда; будущий stop явно сообщит об этом остатке.
Сам запрос менял поведение команды, отдельного вызова stop здесь не было.

Валидация выбрана по строкам retirement helper и process launcher. Изменений
запуска/публикации или научных контрактов нет, T5/GPU матрица не требуются.
Изменены только repo-навык, tool/helper/checks и инструкции; сторонние навыки
не менялись. Архив фиксирует фазу до коммита: задача open, push ожидается;
окончательные commit/remote HEAD/closed проверяются в трекере после push.
