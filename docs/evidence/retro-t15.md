# Ретроспектива T15 — 21.10.2026

Основание: текущая сессия реализации
[№27](https://github.com/stepanosokin/hmc-app-prototype/issues/27),
коммит `b83f005b814f63184c2429ef5c442d86ed2b8968`,
[история 14 попыток](t15/development.md), [review](t15/review.md),
[приёмка](t15/validation.md) и [аудит публикации](t15/checks/publication-checks.json).
Ретроспектива — отдельная последующая работа. Архив T15 сохраняется побайтно;
карта, browser runners, числовые допуски и сторонние skills не меняются.

1. **Временный аудит T15 не защищал архив в CI.**
   Проверки типов, Node-тесты и archive checker уже подключены к CI; общего
   отсутствия guardrail нет. Однако 3459 файлов T15 проверялись одноразовым
   Node-скриптом, удалённым после реализации. Добавлен `--t15` к существующему
   `tools/check_evidence.py`, с отдельным модулем `evidence_t15.py` и шагом CI.
   Он проверяет внешние/retirement индексы, все копии frozen inputs и их
   согласованность между desktop/Android start/end, полные процессы и матрицы,
   controlled races, явные переходы revision/run, atomic field/point identities,
   GPU-бюджет, независимые числовые/canonical сравнения, responsive layout,
   unavailable GPU и очистку браузера/ADB/телефона. Исторические inputs
   сравниваются с архивом, а не с будущими рабочими исходниками. Хеш каждого
   файла вычисляется один раз за проверку; повторные ссылки должны содержать
   ту же идентичность. Синтетические отрицательные случаи пересчитывают
   внешний индекс, чтобы проверять смысл доказательств, а не одно слово `passed`.
   Это механический пробел; новое правило в CODING_STANDARDS не требуется.

2. **Ошибки драйвера удлиняли физические прогоны.**
   В android2/android3 выходящие за карту подписи увеличивали viewport с 384
   до 460 px, из-за чего касания попадали мимо контролов. В android4 драйвер
   продолжал работу до завершения выбора native select. Исправления уже входят
   в T15: clipping страницы, диагностика viewport, различение настоящих
   Android options и ожидание selected index. Browser workflow теперь ведёт
   к `-Updates -UpdatesOnly` перед полным gate и называет необходимые
   наблюдения. Новый драйвер и повторный Compose/GPU-прогон здесь не нужны.

3. **Смешанная тестовая редакция выявилась только в полном Edge.**
   Final1 пропускал унаследованные реальные сроки частично исправленной
   тестовой редакции в публичный каталог. T15 исправил фильтрацию всей
   редакции и маркировку validation-режима независимо от порядка элементов.
   Регрессионный black-box Node-тест сначала воспроизвёл ошибку, затем прошёл;
   он уже запускается CI. Дублировать его в новом linter или reviewer rule
   не требуется. Это также обосновывает сохранение отдельного полного Edge
   после focused-проходов, а не объединение их как успешной приёмки.

4. **Unstaged diff check пропустил новые архивные файлы.**
   После staging обнаружились старые trailing spaces и пустые EOF в точных
   копиях baseline/vendor. Байты сохранены; scope исключения ограничен
   immutable input snapshots и записан в T15. Acceptance guidance теперь
   направляет к staged check до commit. Для обычного исходника исключение
   неприменимо. Существующие Git-object/hash проверки остаются источником
   истины; новый побайтовый verifier вне общего checker не добавляется.

5. **Инструментальные ошибки не требуют разрастания AGENTS.md.**
   В сессии PowerShell 5 не поддержал `SHA256.HashData`, Node subprocess
   потребовал sandbox escalation, а большие чтения обрезались. Уже существуют
   закреплённый Python-образ, пакетное чтение Git index и штатный
   `publication/process.ps1`. При работе над этой ретроспективой первая попытка
   запуска unittest снова столкнулась с terminating stderr в PowerShell;
   повтор использовал этот launcher. Существующая инструкция services и
   Windows process tests уже покрывают случай — новый запрет не нужен.
   Typecheck сначала нашёл три ошибки аннотаций, затем ещё одно повторное имя
   с другим типом. Все четыре исправлены до успешного final2; журналы
   неуспешных проходов сохранены отдельно.

Проверки и очистка ретроспективы записаны в
[retro-t15-checks](retro-t15-checks). Compose-проекты, браузеры, ADB, сети и
тома не требуются: использованы только временные `--rm --network none`
контейнеры существующего validation-образа.

Итоговый final2 прошёл: 54/54 archive tests (7 новых T15-тестов с таблицей
отрицательных случаев), все 3459 артефактов настоящего T15, mypy по 70 файлам,
ссылки в 21 документе. Семь checker/CI-входов совпали между start/end;
проверки staged/committed bytes выполняются при публикации. Все десять
временных контейнеров удалены. Задача №27 прочитана как closed с 10/10
критериями; её тело и состояние в ретроспективе не менялись.
Полная [запись проверок](retro-t15-checks/validation.json) отмечена фазой
до commit/push и не подменяет последующую живую проверку удалённого HEAD.
