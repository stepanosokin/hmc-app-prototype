## Попытки разработки

Все результаты разработки сохранены, включая неуспешные. Исправлены:
двумерное обратное преобразование с восстановлением высоты; сравнение
эквивалентной сериализации CRS в COG; длина секций разных шаблонов;
диагностика нарушенного размера сетки; обработка Albers на сфере в proj4js;
геопривязка контрольной точки производного COG; возврат 400 для неверных
координат API; подмена контрольной суммы исходного файла суммой манифеста.
Полная проверка типов также выявила конфликт имени нового инструмента
`reference.py`: он переименован в `crs_browser_reference.py`.

Сбой запуска `npm.cmd` устранён вызовом существующего `node viewer/build.mjs`.
Ошибка `spawn EPERM` тестового Node-процесса обойдена поддерживаемым
`--test-isolation=none`, без изменения тестируемого кода.
Первый QGIS-вызов получил ошибочный путь отчёта `null`; исправлена только
приватная конфигурация запуска. Повтор прошёл 12 проверок, слои проекта не менялись.

Первая попытка native display остановилась до запуска сервисов из-за различия
LF/CRLF неизменённого `AGENTS.md`. Её ресурсы архивированы и удалены.
Подробности окончательной проверки и сравнения входов фиксируются отдельно.
Следующая попытка native display прошла HTTP-проверки, но браузер не запустился:
путь Chrome по умолчанию указывал на `Program Files (x86)`. Повтор использует
фактический `Program Files/Google/Chrome`; код при этом не изменялся.

Первая полная T12 выявила 413 при перечислении большой истории коллекций:
добавленный полный снимок CRS повторялся в каждой записи. Снимок сохранён
в отдельной коллекции по её ссылке `self`, из списка убрано дублирование.
Лимиты gateway не увеличивались. Контроль на 307 коллекциях сократил ответ
с 4 083 809 до 3 641 596 байт и подтвердил полный снимок в отдельной коллекции.
Начальное ожидание 413 на этом меньшем наборе оказалось ошибочным: исходный
ответ ещё укладывался в 4 MiB. Фактический отказ большей истории сохранён
в T12. Обе диагностические попытки восстановили исходные retention-значения.
Первый запуск диагностического файла дополнительно требовал `PYTHONPATH=/app`.

Перед изменением листинга полный T6 и матрица интерфейса Chrome/Edge прошли
на неизменных входах `acceptance2`. После исправления сформирован отдельный
снимок `acceptance3`; повторная приёмка не объединяет несовместимые фазы.
Вторая T12 показала, что снимок также дублировался внутри `source`.
Окончательное исправление убирает обе копии только из листинга.
Описания отдельной коллекции, исходные файлы, конфигурация, worker,
преобразования и браузерные формулы при этом не меняются.

Desktop-сценарий native display включает действительные GRIB, числовые блоки,
независимую PROJ-проверку и Chrome/Edge. Его отчёт сохраняет собственное
`acceptance: incomplete` для полного T23a: физическая мобильная матрица и
диагностика взаимодействий не входят в согласованную область #49.

Автоматический review отклонил перезапись общего Docker-тега `t12`, чтобы
сохранить прежний runtime рабочего стенда. Приёмочные команды получили
параметр отдельного образа; общий тег не перезаписывался.

## Границы проверки

Реальный ICON проверяется по всем 24 срокам; реальный ENA — только чтение
поворота и метаданных. Остальные шаблоны проверяются синтетическими GRIB2
через настоящий decoder/worker/Zarr/COG/API/GeoServer/QGIS и независимыми
формулами CPU/GPU против PROJ. Реальных образцов производителя для этих
проекций нет; эти проверки не подтверждают их будущую совместимость.

Полные ограничения поддерживаемых разновидностей сеток и операторского
профиля описаны в [документации](../../grib-crs.md).
