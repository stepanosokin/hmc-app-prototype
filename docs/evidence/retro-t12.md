# Ретроспектива реализации T12

Дата: 20.10.2026. Исходный коммит ретроспективы:
`d97e4e33327330b98ddc274c79625d51944bac7d`.
Объект — реализация [№24](https://github.com/stepanosokin/hmc-app-prototype/issues/24).
Источники: текущая сессия, [разработочные попытки](t12/development.md),
[ревью](t12/review.md), [приёмка](t12/validation.md),
[очистка](t12/cleanup-summary.json), [CI](../../.github/workflows/checks.yml)
и [workflow](../development-workflow.md).

Выводы в порядке значимости:

1. **Изменение задачи нельзя использовать для выяснения схемы инструмента.**
   Пробная запись тела `TEMP` была отклонена автоматической проверкой;
   исходный текст задачи сохранился. Последующие обновления использовали
   полное сохранённое тело. Workflow теперь направляет к metadata инструмента
   или локальной проверке запроса и требует просмотреть diff полного тела
   перед отправкой. Это предотвращает потерю критериев при успешной мутации.

2. **Отказ connector и отказ разрешить helper требуют разных действий.**
   Connector вернул 403; предусмотренный workflow локальный helper затем
   отдельно отклонила автоматическая проверка разрешений. Работа продолжилась,
   а запись через helper состоялась после явного разрешения пользователя
   «Разрешаю helper для issue №24». Workflow уточнён: такой отказ требует
   разрешения для конкретного helper и задачи. Разрешение №24 не расширяется
   на последующие задачи. Новых credentials и дополнительных прав не добавлено.

3. **Короткая разработочная история не воспроизводит состояние после T5.**
   Первый полный запуск прошёл T5 за 279,795 s, затем T12 не увидел новых
   ревизий внутри polling, хотя итоговая публикация завершилась. Focused-запуск
   с полной историей воспроизвёл окно и подтвердил старые ответы всех четырёх
   типов при живом worker. В №24 наблюдение ответов и итоговых ревизий уже
   разделено; проверка промежуточной видимости остаётся в T5. Workflow теперь
   требует воспроизводить существенную историю в focused-запуске и ведёт к
   диагностике T12. Ускорение polling не доказывало бы требуемую семантику.

4. **Прогрев должен учитывать всех потребителей ограниченного кеша.**
   Следующий focused-запуск выявил 503 вместо ожидаемого warm 200:
   `/ogc/collections` наполнил общий кеш метаданными и вытеснил байты тайла.
   В №24 уже добавлены явное вытеснение, подтверждение cold 503 и повторный
   прогрев точных metadata/bytes перед отказом генерации. Focused policy прошёл
   за 134,751 s; итоговый T12 — за 158,165 s. Новый workflow связывает
   focused-предпосылки также с нагрузкой на общий кеш. Производственное
   поведение кеша ради ошибочного ожидания теста не менялось.

5. **Существующие проверки и узкие источники достаточны.**
   Mypy обнаружил три неаннотированных списка до Compose, а сравнение Git bytes
   выявило CRLF до итогового стенда. Обе проверки уже предусмотрены workflow
   и CI; новые hooks и дублирующие линтеры не нужны. Широкие выгрузки metadata
   инструментов и большие повторные чтения давали обрезанный вывод. Для этих
   выводов использованы конкретные отчёты попыток; указатель к ним добавлен
   рядом с M3, без нового общего правила поиска или дополнительного инструмента.

Изменены только workflow и этот отчёт. AGENTS.md уже содержит нужный указатель;
новых coding standards не требуется: ошибки касались состояния сценария и
выбора разрешённого действия, а механические ошибки нашли действующие проверки.
Сторонние навыки и исторические свидетельства T12 не редактировались.
Закрытая №24 и родительские задачи в рамках ретроспективы не изменялись.

Проверка: стандартный documentation checker, отдельная проверка ссылок двух
изменённых документов и ревью diff относительно исходного коммита.
Runtime и Compose для этой правки документации не запускались; новых тестовых
ресурсов не создано, проектов для retirement — ноль. Пять архивов реализации
и подтверждения очистки остаются перечислены в свидетельствах T12.
