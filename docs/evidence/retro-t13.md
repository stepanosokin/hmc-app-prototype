# Ретроспектива T13 — 21.10.2026

Основание: текущая сессия реализации
[№25](https://github.com/stepanosokin/hmc-app-prototype/issues/25),
коммит `ea95650928e041b79264e183ddbffa33ed9a6835`,
[история попыток](t13/development.md), [review](t13/review.md),
[приёмка](t13/validation.md) и
[проверки завершения](t13/completion-checks/stage-audit.json).
Это отдельная последующая работа; принятые архивы и состояние задачи сохранены.

1. **Существующие проверки viewer не были подключены к CI.**
   В `viewer/package.json` уже есть TypeScript check и четыре Node-теста,
   а в архиве — самостоятельный `verify.mjs`. Workflow выполнял Python,
   mockup и исторические native проверки, но пропускал эти команды. Новый
   `weather-viewer` job использует закреплённые setup-node и Node 26.10.0,
   `npm ci` с lock-файлом и существующие проверки. Verifier запускается без
   `--current`: он проверяет принятые исторические входы, будущие изменения
   исходников не должны объявляться повреждением старого архива. Полный
   Compose/GPU/physical-device gate этим CI не заменяется. Документационный
   checker дополнен viewer README и этой ретроспективой. Это механический
   пробел покрытия, новый coding standard не требуется.

2. **Совместимость начального каталога нужна до объединения gates.**
   `desktop1` прошёл браузеры, затем T5 отклонил уже опубликованные +1/+3 ч:
   его начальная проверка ожидает только +1 ч. Свежий отдельный T5 прошёл
   без ослабления assertions. Service workflow теперь требует выбирать gate
   по начальному каталогу и истории его изменения, а не по флагу `-Final`.
   Там же указаны существующие viewer команды и ранний полный CI mypy:
   service typecheck не охватывал 13 ошибок старого диагностического файла.

3. **Retirement receipt не устанавливает полноту исходных снимков.**
   Отбор report extensions оставил 24 из 172 input files в первоначальной
   копии. При завершении все 172 файла скопированы отдельно с проверкой SHA256;
   принятый verifier проверяет каждый из них. Cleanup workflow теперь требует
   сопоставить весь input manifest с копией до удаления start snapshot.
   CI повторяет существующую проверку; retirement helper и его область
   ответственности сохраняются. Типовой shell inline generator также ошибся
   в Windows separator/NUL escaping — принятый
   [отдельный JS generator](t13/completion-checks/generate-index.mjs) уже решает
   эту задачу, новый генератор не нужен.

4. **Android driver должен наблюдать результат touch, а не длину паузы.**
   `android1`/`android2` доставляли pointerdown/up до правильного SUMMARY,
   но Chrome отправлял compatibility click позднее фиксированного ожидания.
   Рабочий runner уже ожидает click и выбирает native dialog; browser workflow
   направляет следующие проверки к этому пути. Сохранены реальные координаты
   и события, без изменения геометрических допусков или подмены физического
   устройства эмуляцией. Повторять уже существующие правила доступности
   браузера и ownership ADB в AGENTS.md не требуется.

5. **Большой Git index и baseline line endings — отдельные случаи.**
   При завершении пакетный `git ls-files --stage -z` превысил стандартный
   subprocess buffer; после увеличения до 64 МиБ сравнение выявило обычные
   CRLF filters неизменённого baseline. Новые изменённые inputs и все архивные
   bytes сверены без преобразований; исходный snapshot сохранён точно.
   Acceptance workflow уточняет буфер и разделяет raw evidence/changed inputs
   с существующими filters baseline. Пакетный подход уже описан после T24,
   второго механизма проверки не добавлено.

AGENTS.md уже содержит достаточные условные указатели. Сторонние skills,
runtime, численные допуски и исторические архивы не менялись. Frame p95 из T13
не переименован в успешный performance gate: полная диагностика остаётся №31.

Проверки ретроспективы сохраняются в [retro-t13-checks](retro-t13-checks).
Запускаются существующие Node-тесты, TypeScript check, T13 verifier и проверка
ссылок; они не требуют браузера, Compose, сервера или физического телефона.
Результаты и отсутствие созданных тестовых ресурсов фиксируются перед commit.

Итог: [проверки](retro-t13-checks/validation.json) прошли — lock install,
TypeScript, 4/4 теста, 1362 архивных артефакта / 172 inputs / 16 receipts,
локальные ссылки. Первые ошибки подготовки launcher каталогов и поиска npm
зафиксированы отдельно от результатов тестов; повторные проверки успешны.
Новые тестовые серверы, Docker-проекты, профили и ADB-сессии не создавались.
