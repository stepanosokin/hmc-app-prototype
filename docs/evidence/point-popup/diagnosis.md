# Пустой график на живом стенде — №45

Дата: 22.10.2026. Исходный HEAD: `02ce45506cce5571fb96fa90f4d510953330022c`.
Задача: [№45](https://github.com/stepanosokin/hmc-app-prototype/issues/45).

## Воспроизведение

Пользователь сообщил о численной температуре при пустом графике на
`http://localhost:8140/`. Отдельный Chrome открыл рабочую карту, дождался
готового GPU-поля и щёлкнул около Москвы. Карточка показала 6,95 °C.
Ряд содержит +1/+3 ч одной редакции, +2 ч отсутствует; SVG содержит две
точки, видимую область и **ноль сегментов**. Соединять эти значения через
пропуск запрещает действующий контракт прогнозного ряда.

Изначальная проверка наличия точек/размера SVG проходит (`before-2`), хотя
полного графика исходного образца нет. Усиленная проверка в `before-3`
падает: `Live actual sample must publish all 24 source times: 2 !== 24`.
Это проверка полноты демонстрационной публикации, а не утверждение, что
любой реальный частичный прогноз обязан иметь 24 срока.

Команда воспроизведения (временный браузер и профиль очищаются самим скриптом):

```powershell
node docs/evidence/point-popup/probe.mjs data/reports/point-popup/reproduce
```

## Проверенные объяснения

1. **Сокращённая публикация:** каталог содержит первую редакцию с +1 ч и
   следующую с +1/+3 ч. Выбранная редакция не содержит остальных сроков.
   Именно такой набор создаёт обычный T13 для проверки отсутствующего +2 ч.
   Исторический способ запуска живого стенда здесь не доказывается.
2. **Потеря ответа API:** не подтверждается. Оба опубликованных срока
   имеют `state=value`, численные значения и общую run/revision identity.
3. **Скрытый/сломанный SVG:** не подтверждается. SVG имеет размер
   268 × 111,65625 px и обе точки с конечными координатами и видимым fill.

Новые доменные термины и архитектурное решение не нужны. Правила canonical
nearest-native-cell, точного времени, закреплённой редакции и разрывов сохраняются.

## Исправление и границы

Нужна допубликация всех реальных сроков образца в существующий проект с
сохранением старых редакций. `worker submit` по умолчанию выбирает 1…24;
`publication/revisions.py` переиспользует неизменённые существующие партии.
Новая редакция должна быть явно принята в открытом viewer или выбрана при
перезагрузке страницы. UI не подменяет отсутствие данных интерполяцией.

Автоматическая проверка разрешений отклонила эту операцию на живом
`hmc-app-live` до отдельного разрешения владельца. Отклонённая команда не
исполнялась. Для проверки используется отдельный локальный Docker-проект.

Существующий браузерный сценарий дополнен проверкой именно видимого SVG
карточки **до** открытия панели, а затем SVG панели: число маркеров равно
числу значений, число сегментов — числу соседних пар значений. Нового
тестового набора или изменений алгоритма графика нет. README объясняет,
как отличить сокращённую проверочную публикацию от полного образца.

## Начальная неудача окружения

`before-1` не смог запустить Chrome в sandbox; проверка процессов также
получила EPERM. Это отказ окружения, а не воспроизведение дефекта. Проверка
процессов вне sandbox подтвердила отсутствие оставшегося браузера; последующие
попытки используют отдельные профили и записывают нулевой остаток процессов.
Docker-ресурсы диагностические пробы не создавали; пользовательский живой
стенд сохранён.
