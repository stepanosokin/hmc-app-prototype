# Проверка изменений №45

Проверено относительно `02ce45506cce5571fb96fa90f4d510953330022c`.

- Код отображения, canonical sampling, publication pipeline, gateway policy,
  зависимости, Compose и научные контракты не меняются. Сокращённый набор
  +1/+3 ч остаётся допустимым частичным прогнозом, без линии через пропуск.
- В существующий сценарий T27 добавлены проверки видимости SVG, числа точек
  и соседних сегментов. Desktop popup проверяется до открытия drawer;
  после повтора ошибки проверяется полный график в drawer. Ранее сценарий
  подтверждал числа ряда, но явно не проверял рисунок исходной карточки.
- На первом изолированном прогоне эта проверка прошла. Отказ далее возник
  в прежней синтетической обёртке: реальный HTTP 429 для +3 ч был преобразован
  в `Response.json` с HTTP 200, `Retry-After` утрачен, canonical validation
  закономерно отвергла неполный ответ. Обёртка теперь сохраняет все неуспешные
  реальные ответы; synthetic 503/410 и намеренное игнорирование отмены остаются.
- Точный тест извлекает и исполняет настоящую строку fixture с реальным Web
  Response: до изменения получает 200/null, после — 429/1. Он не создаёт ресурсов.
- README различает полный демонстрационный образец и набор проверки пропуска;
  восстановление дополняет существующую публикацию, не удаляет старые редакции
  и требует явно принять новую редакцию в открытой карте.
- Нового интерфейса, библиотеки, сервиса, общего retry-механизма и отдельного
  набора тестов не добавлено. Старые исторические evidence остаются неизменными.

После исправления fixture запускается один полный затронутый локальный gate
на замороженных входах. Повторные backend/unit/network/GIS/physical-device
наборы не требуются: их runtime-код и конфигурация неизменны. Мобильные viewport
проверки не выдаются за физический Android.

При staged whitespace check исключены только исторические source snapshots:
`docs/evidence/point-popup/attempts/isolated-1/inputs/**` и
`docs/evidence/point-popup/attempts/isolated-2/inputs/**`. Их исходные байты
сверены по SHA256 отдельно; изменённый код и остальные новые файлы проверяются.
Первый запуск Node-проверки Git index в sandbox получил `spawnSync git EPERM`;
ресурсов не создавал, файлы не менял. Проверка повторяется вне sandbox.
