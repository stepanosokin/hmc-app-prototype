# Разработка T9

Финальная приёмка выбирается отдельно; результаты разных исходных ревизий
не объединяются в один успешный gate.

- `hmc-publication-t9-red`: реальный GRIB опубликован, санитарная проверка
  GeoServer прошла; новый HTTP-тест упал из-за отсутствующего
  `publication.budgets`. Это ожидаемая red-фаза.
- `hmc-publication-t9-dev1`: первый rate/accounting-тест и T8 прошли.
  Ревью выявило раннее освобождение concurrency после тайм-аута и потерю
  cache/product metadata при 413. Эта версия не выбирается финальной.
- Отдельная попытка mypy с ошибочно заключённым bind mount была отклонена
  Docker до создания контейнера; следующая проверка выявила вывод типов
  смешанного JSON-словаря в `limited.py`. Добавлена явная аннотация `dict`.
- `hmc-publication-t9-dev2`: typecheck остановил runner из-за обращения к
  `ensure_ascii` через базовый `JSONProvider`. Ненужная настройка удалена.
- `hmc-publication-t9-dev3`–`dev5`: расширенные реальные HTTP-проверки прошли,
  включая отдельные стадии timeout/retention, затем T8 restart. Они остаются
  development evidence: последующее ревью добавило подтверждение завершения
  API и атомарный запрет позднего запуска просроченного queued request.
- `hmc-publication-t9-recovery-final1`: внешняя PowerShell-оболочка остановилась
  на строке stderr успешного Docker build, до T6 acceptance. Проект архивирован
  и удалён. Повторный запуск использует штатный `Invoke-CheckedProcess`,
  который проверяет native exit code и сохраняет оба потока.
- `hmc-publication-t9-final1`: T5 прошёл, затем T9 выявил ошибку тестовой
  настройки public rate limit: lifetime usage был принят за размер скользящего
  минутного окна. После длительного T5 это давало слишком высокий лимит.
  Исправлен только тест: public policy=1 проверяет реальные отказы, затем
  восстановление policy подтверждает успешную выдачу. Поведение шлюза не менялось.
- `hmc-publication-t9-recovery-final2`: во время проверки worker crashes
  acceptance-контейнер намеренно остановлен (native 137), чтобы исправление
  тестового файла не смешивалось с замороженными входами. Предшествующие
  recovery-фазы прошли, но эта попытка целиком не выбирается финальной.
- `hmc-publication-t9-dev6`: исправленная demo quota прошла; сигнал начала
  генератора пытался записываться из API в read-only assets и потому не
  появился. Запись маркера удалена. Симметричные concurrent cold requests
  теперь проверяют пару 429/504 через HTTP, не предполагая заранее победителя.
- `hmc-publication-t9-dev7`: typecheck выявил повторное использование имени
  `pending` для set и Future в тесте; набор переименован.
- `hmc-publication-t9-dev8`: concurrency и оба late-queue отказа прошли;
  финальный queued request был отправлен до истечения собственной 40-секундной
  reservation второго тайм-аута и правильно получил 429. Тест теперь отсчитывает
  полный срок от второго запроса. Перед public policy=1 добавлен свежий
  публичный запрос, чтобы проверка не зависела от длительности предыдущих фаз.

Все завершённые Compose-попытки архивируются штатным retirement helper;
точные пути и нулевые остатки будут перечислены в `retirement.json`.
