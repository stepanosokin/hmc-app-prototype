# Ретроспектива дополнения TLS

Дата: 20.10.2026. Исходный коммит: `a4b5854c0907791c9d843967531ff8a0271f07f3`.
Источники: текущая сессия, [отчёт планирования](tls-planning.md), существующий
workflow CI и процесс разработки. Объект ретроспективы — добавление требований
и задачи [T21 / №33](https://github.com/stepanosokin/hmc-app-prototype/issues/33),
а не реализация TLS.

Выводы в порядке значимости:

1. Проверка ссылок в PowerShell продолжила выполнение после ошибки на корневом
   README и напечатала PASS. Добавлен `tools/check-documentation.ps1` с остановкой
   при ошибках и разрешением путей относительно абсолютного пути документа.
   Проверка подключена к существующему Windows CI. Удалённые адреса и содержимое
   section fragments в её область не входят.
2. `Get-Content` передал метаданные PowerShell в JSON тела задачи; GitHub вернул
   422. Repository-scoped помощник теперь отвергает объект вместо строкового
   `body` до доступа к учётным данным и сети. В workflow записан способ чтения
   plain string через `ReadAllText`.
3. Поиск спецификации и повторная передача больших документов через tool output
   занимали лишние вызовы. Добавлены адреса обеих языковых версий и зеркала №12
   в workflow; существующий указатель AGENTS.md расширен на изменения спецификации.
   Тексты сторонних навыков и исторические доказательства сохранены.

Проверка изменений:

- Стандартная проверка всех семи текущих документов завершилась с native exit 0.
- Отдельная положительная проба ссылок с пробелами, percent encoding, fragment
  и удалённым адресом завершилась с native exit 0.
- Ссылка на отсутствующий файл и отсутствующий входной документ дали native
  exit 1 без сообщения об успехе.
- Тело GitHub issue в виде объекта отвергнуто с native exit 1 до обращения
  к credential helper и сети; внешние задачи этой пробой не менялись.
- `node --check` помощника и `git diff --check` прошли.
- Проверен весь diff относительно исходного коммита; изменения ограничены
  workflow, документацией и защитой вспомогательных инструментов.

Пробы не создавали Docker-ресурсов; проектов для удаления — ноль, оставленных
стеков нет. Временные локальные fixtures удалены после фиксации результатов
в этом отчёте. Проверки приложения и runtime TLS не запускались: код приложения
не менялся. №33 остаётся будущей открытой задачей реализации.
