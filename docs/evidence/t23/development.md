# T23: геометрический кандидат и отклонённая числовая интерполяция

Задача [№35](https://github.com/stepanosokin/hmc-app-prototype/issues/35),
исходный коммит `ff451d1cd381b896a1e08147973f33291f9318c3`.
Статус: **разработка, приёмка T23 не завершена**. Это технический эксперимент,
не расширение принятого макета T22 и не рабочая карта.

## Воспроизведение

Из корня репозитория, Windows PowerShell, Node.js с WebSocket и Windows Chrome:

```powershell
New-Item -ItemType Directory -Force data/reports/t23 | Out-Null
node tools/check-display-projections.mjs
powershell -NoProfile -File tools/run-display-projections.ps1 -Project hmc-publication-t23-unique -Port 8135
```

Первый вариант проверяет только геометрию/локальную подложку. Второй проверяет
контрольную сумму частного GRIB до выделения ресурсов, требует уже собранный
hash-locked publication image (`-Image`, по умолчанию `hmc-publication:t12`),
создаёт свежий Compose-проект, публикует только реальный срок +1 ч и обращается
к числовым тайлам и point API через gateway. Конец каждой попытки автоматически
архивирует отчёты и удаляет контейнеры, сети и тома точного проекта.
Существующий приватный образец не включается в Git; его SHA256:
`dddfd6c63ba73e5e7337c21e105f16417003429f8179a44ca58bb110cb43736a`.

Настройки `T23_CHROME` и `T23_REPORT_DIRECTORY` задают исполняемый файл и новый
каталог под `data/reports`. При отдельном браузерном запуске родитель каталога
должен существовать. Загружаемые до старта браузера зависимости закреплены
версиями, длинами и SHA256 в [vendor-lock](../../../tools/display-projections/vendor-lock.json).
Их фактические байты сохраняются в новых отчётах. Во время работы браузера
скрипты, worker и Natural Earth поступают только с собственного loopback-сервера.
Тестовый прокси пересылает только перечисленные в эталоне URL тайлов в локальный
Compose gateway; он не является новым публичным API и не обходит gateway.

MapLibre GL JS 6.15.0 остаётся движком. proj4js 2.22.0 преобразует координаты;
D3 Geo 3.1.1 и D3 Array 3.2.4 используются только для сферического отсечения
геометрии подложки. Нового картографического движка нет. Локальная подложка —
ранее сохранённая Natural Earth 5.1.2 из T22, общественное достояние.
Исходные пакеты и лицензии доступны по закреплённым именам/версиям;
MapLibre сохраняет BSD license header в загружаемых байтах.

## Геометрия и камера

Штатный `globe` использует перспективу и при zoom 11–12 переходит в Mercator;
`vertical-perspective` оставляет перспективу. Неподдерживаемая строка
`orthographic` сохраняется в `getProjection()`, но фактическая геометрия
подменяется Mercator. Поэтому чтение имени не служит доказательством.
Это согласуется с [фабрикой проекций закреплённой версии](https://github.com/maplibre/maplibre-gl-js/blob/v6.15.0/src/geo/projection/projection_factory.ts)
и [перспективной матрицей](https://github.com/maplibre/maplibre-gl-js/blob/v6.15.0/src/geo/projection/vertical_perspective_transform.ts).

Рабочий **геометрический кандидат** использует публичный экспериментальный
`addProjection`: собственный `hmc:orthographic`, PROJ `ortho`, сферу отображения
R=6378137 м и WGS84 геодезические углы. Это не нативная сфера хранения.
На плоскости MapLibre камера имеет pitch=0 и maxPitch=0; все отображаемые точки
на одной плоскости, поэтому перспективное деление камеры одинаково для всех
точек и не превращает сферическую ортографию в перспективный глобус.
Zoom меняет только масштаб; перехода в Mercator в этом CRS нет.
Камера находится над плоскостью отображения; ортографический взгляд на сферу
соответствует параллельным лучам, а не конечной высоте над сферой.

Поворот в эксперименте меняет центральную долготу/широту PROJ и пересоздаёт
MapLibre с заново отсечённой геометрией. Проверены центры (0°,0°), (170°,50°),
(90°,90°), zoom 0 и 2. Это подтверждает изменение ориентации и масштабирования
геометрии, но **не доказывает плавность интерактивного вращения**.
Независимые формулы ортографии проверяют x/y после определения экранного
масштаба; абсолютный физический масштаб Земли этим тестом отдельно не измеряется.

Сферическое отсечение подложки выполняется перед её передачей MapLibre;
[D3 clip stream](https://d3js.org/d3-geo/projection#projection_preclip) служит
геометрическим помощником. EPSG:3576 использует фиксированное официальное
определение из EPSG-базы PROJ: WGS 84 / North Pole LAEA Russia, lat_0=90°,
lon_0=90°, x_0=y_0=0, WGS84, метры. Подложка отсекается на 45° с. ш.
Экспериментальная квадратная сетка ±5 000 000 м — только сетка тестового
рендеринга подложки, не объявленный серверный TileMatrixSet.

Регистрация CRS сама по себе не перепроецирует содержимое числовых тайлов.
Для GeoJSON настроен отдельный worker projection handler; без него библиотека
может оставить подложку в Mercator при правильных `project`/`unproject`.
Ограничения экспериментального API описаны в [официальном руководстве](https://maplibre.org/maplibre-gl-js/docs/guides/custom-crs/).
В частности, источники создаются заново после смены CRS, а не переиспользуются
после загрузки в другой проекции.

## Научный эталон и результат v2

[reference.py](../../../tools/display-projections/reference.py) читает первый
сырой GRIB frame, а не Zarr/COG или production `bilinear`/`coordinates`.
Положение рассчитывается отдельной скалярной обратной формулой Mercator и
геоцентрической широтой `atan((1-e²) tan(phi_WGS84))`, e²=0.0066943799901413165,
при высоте WGS84 h=0. Это та же согласованная нулевая геоцентрическая
datum-гипотеза для native sphere R=6371229; подтверждения производителя и
иной геодезической точности эксперимент не добавляет.

Реальные тайлы: 3/4/2, 3/5/2, 6/35/21, 6/36/21. Проверены 864 валидных
пикселя и маски в проверяемой сетке, две пары горизонтальных halo и каноническая
nearest-native-cell точка CRS84 (37.6173°,55.7558°). Срок точный; выборка
опубликована существующим worker. Ошибка в центрах ≤0,000015252109 K
при пределе кодирования 0,001 K; проверенные halo побайтно/численно совпали.
Каждый f32 тайл содержит 332820 байт; SHA256 проверяется и браузером.

GPU-проба выполняет ручную билинейную интерполяцию RG32F через texelFetch,
без перенормировки масок, читает RGBA32F framebuffer и сравнивает результат
с независимым GRIB в той же WGS84 точке. Отдельная CPU-сумма четырёх f32
значений различает ошибку арифметики GPU и дополнительной интерполяции.
На проверенных дробных позициях максимальная суммарная ошибка составила
**2,558872628 K > 0,01 K**. Этот способ повторной интерполяции v2 отвергнут.
Отдельный предел COG 0,0001 K не заменяет ни одну из этих проверок.

Провал относится к проверенной выборке/способу. Он не доказывает невозможность
всех браузерных алгоритмов или ортографии в MapLibre. Для выбора рабочего пути
нужно сравнить доставку нативных ячеек для однократной GPU-интерполяции с
производными, сохраняющими общий допуск. Это вынесено в связанную
[№37 / T23a](https://github.com/stepanosokin/hmc-app-prototype/issues/37).
Новая версия URL/metadata/matrix/CRS/origin, cache identity, readiness,
generation/usage budgets, access/retention и применимые T5–T12 gates перечислены
в этой задаче. Сам эксперимент не меняет контракт v2 и API/хранилище/WMS.

## Попытки, review и незавершённые критерии

- Первая загрузка UMD `maplibre-gl.js` дала HTTP 404: v6 предоставляет ESM.
  Заменена закреплённым `.mjs`; никаких браузерных/Compose ресурсов не создано.
- `browser-bc1b…`: timeout из-за отсутствующего локального worker; отчёт сохранён,
  браузер/профиль/сервер удалены. Следующая отдельная проба завершилась, но снимок
  LAEA показал Mercator: отсутствовал worker projection handler. Её результат
  не используется как положительное доказательство подложки LAEA.
- `hmc-publication-t23-probe1` и `probe3`: ранние отказы проверки будущих Git
  байтов (CRLF/LF в существующих config-файлах). Нормализованы только рабочие
  окончания строк до уже существующих Git LF; семантика исходников не менялась.
  Оба отчёта архивированы, retirement подтвердил пустые ресурсы.
- `probe2`: реальные reference/GPU и полный unittest discovery:
  42 теста, 18 пропущены по отсутствующим отдельным gate-флагам, остальные прошли.
  Это успешный эксперимент отклонённого числового способа, не прохождение T23;
  неверная подложка сохранена как development failure. Retirement завершён.
- `browser-38df…`: ошибка обёртки изменяемого D3 clipping stream исправлена
  делегированием текущих методов. Отчёт отказа и успешная последующая отдельная
  геометрическая проба `browser-3993…` сохранены; каждый браузер/профиль/сервер закрыт.

Независимый `code-review` выполнен двумя агентами: Standards и Spec.
Standards выявил потерю service logs при ошибке; runner теперь сохраняет их
до retirement. Последующая проверка не нашла блокирующих нарушений.
Оба reviewer отметили, что время SHA256 включалось в decode: измерения разделены.
Spec подтвердил допустимость зарегистрированной сферической ортографии и
разделение ошибок сырого GRIB/f32/GPU, но перечислил отсутствующую приёмку.

Открыты: проецируемый погодный слой с общим допуском; согласование его положения
с подложкой/подписями/границей/маркером; полная независимая проверка обратного
выбора, масок и синтетических полюса/±180°/горизонта/отсечения; сравнение серверного
пути; состояние и сообщения при переключениях; frame/memory/device acceptance.
Геометрический кандидат нельзя выдавать за готовую реализацию этих критериев.
До их завершения №35 не закрывается, #36/#25/#27 не объявляются разблокированными.

## Итог последней попытки и архив

После probe4 итоговый общий mypy выявил конфликт имён float/bytes в новом
CPU/f32 эталоне halo. Переименованы только буферы; общий mypy по 54 файлам
повторно прошёл до выделения нового стенда. Старые отчёты не переиспользованы
как проверка новых байтов.

`hmc-publication-t23-probe5`: неизменные начальный/конечный inventories;
42 теста за 83,788 с, 18 пропущены по условиям отдельных T5–T12 gate;
выполненные 24 теста прошли. Общий mypy с tools проверил 54 файла; история
его исправлений сохранена в [отдельной записи](attempts/mypy.md).
Runner дополнительно проверил существующие 51 исходник сервиса.
Node syntax и diff whitespace также проверены.

Максимальное отклонение координатной формы ортографии от скалярной
тригонометрии — 5,1×10⁻¹³ пикселя; преобразование EPSG:3576 против независимого
PROJ — 3,8×10⁻⁹ м. Это проверки преобразователей, а не точности всей видимой карты.
GPU против CPU-интерполяции f32: ≤0,000026702881 K; против GRIB после повторной
интерполяции — 2,558872628 K. В проверенных GPU-позициях различий масок — 0,
но полный набор синтетических случаев ещё не выполнен.

Снимки 1440×900, 390×844, 360×740 визуально просмотрены. После настройки
worker LAEA подложка действительно полярная, а ортография показана диском.
У горизонта ортографической подложки остаются узкие артефакты геометрии;
на узком экране диск горизонтально обрезается viewport. Это исследовательские
снимки, не положительная визуальная приёмка или подтверждение положения поля.

Полный последний отчёт сохранён в `probe5/`, предыдущий — в `probe4/`,
более ранние результаты и отказы — в `attempts/`, квитанции пяти retirement —
в `retirement/`. Байты бинарных f32 и runtime-зависимостей, намеренно исключённые
стандартным retirement из переносимого архива, дополнительно скопированы
из сохранённых report fixtures и включены в общий индекс.
Индекс `artifact-index.json` фиксирует длины/SHA256 выбранных артефактов;
полные исходные архивы также остаются в
`data/archives/publication/hmc-publication-t23-probe{1,2,3,4,5}/<archive-id>`.
Удалено 3 реально созданных стенда; ещё 2 попытки завершились до выделения
Docker-ресурсов. Для всех 5 квитанций подтверждены пустые container/network/volume.
Собственные браузеры, профили и loopback-серверы закрыты во всех браузерных
попытках. Живых стендов T23 не оставлено; сторонний `vgdb_tools` не изменён.

Connector разрешил чтение №35/№37, но создание issue вернуло 403. Предусмотренный
workflow repository-scoped helper создал №37 с предварительно просмотренным

прогресс и ссылка №37: исходное тело сохранено, 0 отмеченных и 8 неотмеченных
критериев, состояние open прочитано обратно; [снимок проверки](tracker-readback.json).
Отказов автоматической проверки разрешений нет,
секреты в отчёты не включались. Родитель №12 и закрытые задачи не изменялись.
Поскольку полная приёмка №35 не завершена, итоговый commit/push по правилу
одного коммита для завершённой задачи пока не выполняется.
