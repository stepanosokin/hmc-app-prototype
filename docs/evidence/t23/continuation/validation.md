## Проверяемый путь

Используется утверждённый в [T23a](../../t23a/validation.md) контракт
`hmc-native-display/1`: реальные native f32/mask/halo через Compose gateway,
одна билинейная GPU-интерполяция, канонический point API. Замороженный v2,
WMS/QGIS, GRIB/Zarr/COG и серверные сервисы не меняются.

Камера и геометрическая модель унаследованы от [эксперимента T23](../development.md).
Ортография — сфера отображения R=6378137 м, геодезические углы WGS84,
параллельные лучи и плоская камера MapLibre с pitch=0. Поворот меняет
центральные lon/lat зарегистрированного CRS; приближение меняет масштаб.
Фиксированная EPSG:3576 — WGS 84 / North Pole LAEA Russia, lon₀=90°,
lat₀=90°, WGS84, метры; показ ограничен 45° с. ш.

Кандидат пересоздаёт CRS и карту **после отпускания** однопальцевого жеста.
Это ограничение показано по-русски. Он не подтверждает непрерывное вращение.
Измерение `rotation_settle_ms` — задержка завершения перестроения, а не p95
кадра вращаемого глобуса. Старый GPU/frame gate T23a этого пробела не закрывает.

При смене вида исходные блоки переиспользуются, выборка не запрашивается заново.
Сохраняются полная selection, единицы K/°C и WGS84-точка; масштаб приводится
к прежнему числу пикселей на метр, центр LAEA при необходимости ограничивается
45° с. ш. Граница покрытия обрезается сферически до проецирования; подписи
и маркер скрываются за горизонтом/вне полярной области. Для сохранённой точки
показывается причина. Два пальца не инициируют поворот. Сбой режима предлагает
кнопку явного перехода в Mercator; в автопробе причина вводится тестовым
сценарием, это не свидетельство реального отказа устройства.

## Воспроизведение

```powershell
$env:T23_CHROME = 'C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe'
powershell -NoProfile -File tools/run-native-display.ps1 -Project hmc-publication-t23a-t23-unique -Port 8137 -Image hmc-publication:t23 -Interaction
```

Нужны Windows, Node с WebSocket, Docker, locked publication image и частный
GRIB с SHA256 `dddfd6c63ba73e5e7337c21e105f16417003429f8179a44ca58bb110cb43736a`.
Образ собирается `docker build -f Dockerfile.publication -t hmc-publication:t23 .`.
Зависимости закреплены в существующем vendor-lock; runtime-ресурсы локальные.
Каждый запуск использует новый проект/каталог, сохраняет начальные/конечные
хеши входов, а затем выполняет автоматический retirement.

Независимый PROJ/GRIB-reference проверяет GPU-readback также при центрах
(10°,40°), (30°,60°), (170°,0°), (90°,90°) и в явном Mercator fallback.
Вид без температурных отсчётов обозначается `mask-only`; нулевая ошибка
в таком виде означает только отсутствие расхождений маски.

  Для скрытой точки выбран (170°,0°); причиной не объявляется ошибка renderer.
- `hmc-publication-t23a-t23-dev3`: native HTTP 4/4, Edge 155.0.4283.62,
  три desktop viewport, interactions и независимое PROJ/GRIB-сравнение прошли.

  synthetic projection diagnostic ≤1,648 м. GPU: NVIDIA GTX 1070 / D3D11.
  Числовой допуск пройден, полный performance gate **не пройден**:
  холодный показ 5464/3572/4186 мс при цели 3000 мс.
  Тёплое переключение ≤111 мс; scripted pan/zoom p95 ≤17,1 мс;
  перестроение поворота после отпускания 111–160 мс.
- Профиль первого desktop вида dev3: field load 5283,5 мс; metadata через
  gateway 1295,4 мс, запросы блоков 287–700 мс при concurrency=2;
  decode суммарно 10,7 мс, upload с gl.finish суммарно 1,8 мс.
  Наблюдение указывает на I/O/сервисную часть, а не GPU-upload. Это профиль
  этой машины, не измерение всех причин задержки backend. Лимиты запросов
  не повышаются; архитектура сервиса без дополнительной проверки не меняется.
  Gateway не передаёт X-HMC-Cache клиенту; null в proxy-журнале не означает
  cache miss. Следующие попытки сохраняют request ID для сопоставления с
  отдельным операторским usage-отчётом.
- `hmc-publication-t23a-t23-phone1`: подготовка прошла 4 native HTTP tests;
  попытка остановлена до приглашения телефона после review failed-path cleanup.
  Остановлен только проверенный Node PID с проверенным родителем. Родительский
  runner сохранил service logs и выполнил retirement; мобильного результата нет.
- `hmc-publication-t23a-t23-phone2`: сервер был привязан к сохранённому адресу
  отключённого Wi-Fi адаптера. Windows не разрешила добавить firewall rule
  без UAC; после временного правила и моста на активный Ethernet телефон
  подключился, но завершилось общее 10-минутное ожидание. Полного телефонного
  отчёта нет, GPU/mobile pass не заявляется. Runner retired; оба временных
  firewall rules и portproxy удалены. Для phone3 выбран активный Ethernet
  напрямую, ожидание открытия страницы и самой пробы разделено; firewall lease
  согласован с максимальным ожиданием и снимается досрочно после результата.
- Финальные desktop/phone пробы описаны ниже.

Оценка управляемых числовых массивов/текстур/framebuffer не является
измерением всей памяти браузера. Поле проходит одну GPU-интерполяцию;
native HTTP 4/4 отдельно проверяет все блоки, encoding, halo и API-семантику.
В этой пробе 30 gateway-запросов: 18 native blocks, metadata, 2 серверных
сравнительных кадра и 9 point-запросов. Переключения не загружают блоки заново.

Сохранены два PNG физического GPU canvas; они исключают HTML-подписи,
маркер и контролы и не заменяют полноэкранную визуальную приёмку телефона.
Canvas-снимки просмотрены; ошибочные/неполные свидетельства не объявляются
полным визуальным pass. Оба режима, маски и численные координаты проверены
независимым PROJ/GRIB-reference. Ошибок renderer/JS в отчёте нет.

Начало холодного интервала — navigation origin телефона, включая локальные
скрипты/worker, metadata/блоки, shader и uploads. API/gateway перезапущены;
браузер получает no-store ответы. OS page cache не объявляется очищенным.
Тестовый timeout начинается отдельно после первого Android/Chrome открытия.
Во время phone measurement дополнительные validation workloads не запускались.
Map/worker удалены на телефоне, поле/point отменены; сервер остановлен,
retirement receipt проверен. Временные firewall rules и portproxy удалены.
Все 30 запросов сопоставлены по request ID с операторским usage-отчётом:
21 cache miss (metadata/блоки/сравнительные кадры), 9 point-запросов с cache
`unavailable`, все status=200. Это наблюдение gateway, а не предположение по
отсутствующему клиентскому заголовку X-HMC-Cache.
