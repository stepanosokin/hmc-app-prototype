## Spec

M1-выбор сохранён: узкий HTTP-адаптер с общим Zarr sampler, а temporal WMS
остаётся в GeoServer. M3 дополняет T5/T8/T9/T10/T11 интеграцией защищённых
point/EDR/collection/tile metadata/bytes/WMS при исправлениях и отказах.
Для карты и identify повторно используется проверенный desktop helper T11.
Сферические исходные координаты и WGS84 не отождествляются.

До итоговой приёмки исправлены/учтены следующие замечания:

- Каталог и collections читаются отдельными HTTP-запросами во время публикации.
  Между ними допустимо появление новой ревизии; проверяется включение collections
  в следующий каталог, а не ошибочное требование атомарного snapshot двух запросов.
- T9 eviction-сценарий требует кеш ровно на два Float32-тайла (`665640` bytes).
  Предварительно проверяется именно этот размер; стандартный кеш T11 не подходит.
- T8 warm-cache/fault сценарий требует `T6_TEST_FAULTS=1` в настоящем API;
  этот prerequisite перенесён из T11 и сохраняется во всём T12 запуске.
- Проверка квоты сначала создаёт свежий запрос, чтобы граница скользящей минуты
  не зависела от продолжительности предшествующей публикации.
- На полной T5-истории нельзя требовать, чтобы последовательный polling
  обязательно успел увидеть новую ревизию до завершения worker. Старые ответы
  теперь читаются до тяжёлого discovery, после каждого ответа проверяется
  живой процесс worker, а новые опубликованные ревизии проверяются отдельно.
  T5 по-прежнему требует наблюдения нескольких промежуточных ревизий.
  Счётчики реального пересечения и окончательные ревизии сохраняются также
  в `t12-publications.json`, даже если последующая проверка завершится ошибкой.
- Discovery collections заполняет тот же ограниченный кеш tile metadata
  и может вытеснить bytes. Warm-cache prerequisite устанавливается после
  discovery заново; явное вытеснение и cold 503 сначала воспроизводятся
  даже на маленькой Development-истории. Сервисный кеш не менялся.

Проверки подтверждают исходные и исправленные значения, а не только статусы
HTTP 200; decoded display values сравниваются с отдельным scalar bilinear
reference из исходного GRIB. Реальная маска sample не содержит внутренних
missing cells, поэтому внутренний native nodata — отдельное синтетическое
дополнение существующего полного suite. Внешняя footprint mask проверяется
также через тайлы и WMS/QGIS.

Browser/GPU/interpolation части A2/A3/A8, TLS и production capacity остаются
в следующих задачах. Содержимое и состояние parent #12 и wayfinder не меняются.
Итоговые результаты, входные байты и очистка учитываются в `validation.md`.

После итоговой приёмки staged diff относительно исходного коммита повторно
просмотрен, включая новые файлы; `git diff --cached --check` прошёл.
