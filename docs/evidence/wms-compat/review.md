# Review относительно исходного коммита

Область: scoped WMS API/gateway, настольная проверка QGIS, существующий T11
HTTP-сценарий, два коротких геометрических/негативных unit-теста и документация.
Числовые тайлы браузера, нормализация GRIB, палитра и научные допуски не менялись.

- Проверка размеров разделяет создаваемую картинку (максимум 512 или более
  строгая политика организации) и виртуальное окно Identify (до 16384).
  При Identify проверяются I/J, конечный упорядоченный BBOX и границы размеров;
  запрос upstream становится 1×1. Для EPSG:4326 сохранён порядок latitude/longitude,
  разрешение по каждой оси и центр выбранного пикселя. Есть независимое сравнение
  с native API в T11, обе CRS, края и NoData.
- Допускаются только проверенные DPI-подсказки и SCALE легенды; служебные параметры
  удаляются перед GeoServer, whitelist произвольных параметров сохраняется.
- TIME по умолчанию берётся только из закреплённой редакции, совпадает с advertised
  default. Явная недоступность и истечение срока публикации не подменяются.
- Gateway заменяет внутренний заголовок размеров своим значением; пользователь
  не может повысить предел организации. Capabilities отражает меньшую политику,
  а ETag включает профиль WMS и действующий предел. Этот случай добавлен в T11.
- В desktop helper удалены обходные настройки DPI/размеров/URL. Проверяются
  автоматический temporal mode и exact-start по умолчанию, окно 1204×700,
  настоящий Identify на том же слое после смены времени без URI time.
  Временные canvas удаляются; после проверки остаются исходные слои пользователя,
  проект не сохраняется. Основной canvas не используется для тестовых кадров.

Проверки выбраны по строке QGIS/scoped WMS таблицы разработки: Development T11
и закреплённый desktop, затем двухфазный полный T11 на замороженных входах.
Полный T11 включает T5, restart, сценарий T8 policies, общую suite и runtime.
Правила аутентификации/профилей ключей, алгоритм admission/accounting, TTL,
байтовые/временные бюджеты не менялись. Отдельные полные T8/T9 и браузерная
GPU-матрица не требуются для этой области; более строгий dimension проверяется
непосредственно в T11. GitHub Actions не использовались.
