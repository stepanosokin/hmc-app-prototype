# NoData и прозрачные нули

Дополнение 03.11.2026, [№85](https://github.com/stepanosokin/hmc-app-prototype/issues/85):
для скорости ветра GRIB2 0.2.1 в м/с на уровне `heightAboveGround` 10 м
все значения строго меньше `0.01`, включая ноль, отбраковываются как NoData.
Ровно `0.01` допустимо. Это заменяет точечную отбраковку
`0.0005118664217222548` и сохранение других малых скоростей этого слоя.
Компоненты U/V и другие уровни сохраняют прежнюю допустимость.
Политика — `field-validity/5`; [согласование](design/field-style-20261103.md).

Последующее согласование 28.10.2026: точные 0 и −0 давления у поверхности
и на уровне моря (Па), относительной влажности (%), удельной влажности
у поверхности и на 2 м (кг/кг), порывов (м/с) и видимости (м) — полноценный
NoData во всех численных и картографических представлениях. Малые ненулевые
и отрицательные значения этих показателей новым правилом не отбраковываются.
Распознаётся также температура почвы GRIB2 2.3.18: ≤ 0 K — NoData.
Это заменяет прежнее правило только прозрачности для перечисленных полей;
нули остальных показателей сохраняют прежнюю трактовку.
Подписи легенды удельной влажности округляются до трёх значащих цифр
в кг/кг; точки, графики и исходные значения не округляются этим правилом.

| Показатель | Идентификатор GRIB2 (discipline.category.number) | Уровень | Новая отбраковка |
| --- | --- | --- | --- |
| Температура почвы | 2.3.18, также ранее поддержанный 2.0.2 | исходный уровень почвы | ≤ 0 K |
| Поверхностное давление | 0.3.0 | surface | = 0 Па |
| Давление на уровне моря | 0.3.1 | meanSea | = 0 Па |
| Относительная влажность | 0.1.1 | исходный уровень | = 0 % |
| Удельная влажность | 0.1.0 | surface или heightAboveGround 2 м | = 0 кг/кг |
| Скорость порывов | 0.2.22 | исходный уровень | = 0 м/с |
| Видимость | 0.19.0 | исходный уровень | = 0 м |

Правила требуют совпадения единиц, а не только названия поля. Удельная
влажность на других уровнях сохраняет численные нули. Для температуры
сохраняются прежние исключения статистических операций, разностей и аномалий.

Предыдущее согласование, сохраняющее силу для остальных показателей:

Согласовано 28.10.2026: точные 0 и −0 давления, влажности, порывов ветра,
осадков, облачности, снега, видимости и всей группы «Другое» прозрачны на карте
и в цветном WMS и исключены из автоматических границ шкалы. Численная статистика,
точки, графики, массивы и GIS Identify сохраняют эти нули. Малые ненулевые
значения не скрываются. Нули ветра кроме порывов видимы. Температурные правила
прежние. При полностью прозрачном поле шкала отсутствует, но численные нули
доступны; это отличается от полностью пустого поля NoData.

Для распознанных показателей абсолютной температуры в K значения ≤ 0 K
становятся NoData. Правило определяется по идентификатору GRIB2, единицам
и статистической операции. Ноль аномалии, разности, дефицита точки росы или
стандартного отклонения не отбраковывается. Для неизвестных показателей
дополнительных предположений о допустимом диапазоне нет.

Единая маска используется в статистике, числовых блоках/тайлах, точечных
ответах, графиках и COG/GIS. NoData прозрачны на карте. Полностью пустое поле
сохраняет выбранный срок и отображается как «Нет данных» без шкалы.
Исходные GRIB и численные массивы сохраняются; в Zarr `missing_reason`
различает допустимое значение (0), исходный пропуск (1) и отбраковку (2).
Метаданные содержат версию правила и раздельные счётчики. Точечный API
сохраняет `reason: native_nodata` и добавляет `nodata_reason` с причиной.

Маска допустимости прозрачных нулей остаётся действительной.
Допустимые 0 °C абсолютной температуры видимы.

Службы обработки и численного API используют `decoder` из текущего репозитория
через read-only mount Compose, как и `publication`. После обновления Compose
пересоздайте затронутые службы штатной командой `start`, чтобы применить mount.
Если запущенная при старте штатная очистка ещё держит блокировку, preview
сообщит «Идёт публикация или очистка». Дождитесь её завершения и повторите
preview; опубликованные данные при таком отказе не меняются.
`refresh-grib` использует текущий decoder при новых загрузках, но пропускает
уже опубликованные файлы. Для них выполните пересчёт ниже: повторное
декодирование исходных GRIB не требуется. Версия политики включает оформление.

## Пересчитать существующие публикации

После обновления приложения выполните предварительный просмотр для
запущенного стенда и сохраните отдельный план:

```text
node tools/revalidate-fields.mjs preview --project hmc-app-live --plan data/live/hmc-app/nodata-plan.json
node tools/revalidate-fields.mjs apply --project hmc-app-live --plan data/live/hmc-app/nodata-plan.json --expect-rebuild-batches 10
```

Каталог для плана должен существовать. Имя плана для просмотра должно быть
новым. При изменении каталога публикаций, конфигурации, образа или исходников
между просмотром и применением требуется новый план. Команда не запускает
остановленные службы. При необходимости увеличьте бюджет управляемого
хранилища параметром `--storage-budget-bytes ЧИСЛО` в обеих командах.
Preview печатает сводку `revalidation_scope`: число корневых редакций,
уникальных партий для пересчёта, повторно используемых партий и состав полей.
`--expect-rebuild-batches` обязателен для apply: число выбирается из требуемого
объёма задачи и сверяется со сводкой. В примере 10 — десять сроков одного слоя;
для пустого плана укажите 0. Для изменения одного поля добавьте
`--expect-field ИДЕНТИФИКАТОР_ПОЛЯ` из каталога. Несовпадение количества или
поля останавливает команду до обращения к Docker. Старый план без
`rebuild_keys` требует нового preview.
У прямого `tools/revalidate-fields.mjs` нижележащий бюджет по умолчанию — 16 ГиБ;
у операторского `hmc-app.mjs` — 64 ГиБ. Для пересчёта с тем же бюджетом, что
у операторского CLI, передайте `--storage-budget-bytes 68719476736` в обеих
командах. Это разные значения по умолчанию; увеличение бюджета не требуется
для обычных публикаций через CLI лишь из-за превышения 16 ГиБ.

Пересчёт читает проверенные опубликованные массивы; наличие исходной папки
GRIB не требуется. Сохраняются численные значения и исходная маска пропусков,
пересчитываются дополнительная маска, статистика, числовые и GIS-производные.
При переходе `field-validity/4` → `/5` сравнивается правило конкретного поля:
пересчитывается только скорость ветра на 10 м. Неизменённые партии используются
по прежним ссылкам, включая U/V и остальные высоты. В плане `rebuild_keys`
перечисляет партии для пересчёта; `entries` содержит полный состав новой
корневой редакции, включая повторно используемые партии. Различие общих
номеров версии само по себе не требует пересчёта остальных полей при этом переходе.
Общие исходные партии пересчитываются один раз. Все новые производные
проверяются до единого переключения доступности. Новые редакции сохраняют
сроки хранения и порядок прежних публикаций; старые ссылки после переключения
возвращают `410 Gone`. Физическое удаление остаётся задачей обычного сборщика
с защитой активных чтений и общих данных.

При ошибке подготовки прежние публикации доступны; подготовленные неизменяемые
данные остаются для штатного сборщика. При потере подтверждения транзакции
проверьте каталог и постройте новый план перед повтором. Пересчёт существующих
публикаций не имеет общего ограничения по времени; для большого каталога он
может длиться более десяти минут. Ctrl+C прерывает подготовку; проверяйте каталог
перед повтором, если прерывание пришлось на момент переключения. Ограничение
обычной загрузки GRIB в 600 секунд сохраняется. Новый `preview` всегда требует
нового имени файла; после просмотра запускайте `apply` с тем же файлом.
Повторный пересчёт уже исправленного каталога не создаёт редакций.
