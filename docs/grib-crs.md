# Система координат исходных GRIB2

Параметры читаются из секции 3 каждого сообщения GRIB2. Имя файла, модель и
соседний `proj.txt` не определяют CRS. Значение стандартного кода формы Земли
имеет приоритет: код 6 задаёт радиус 6 371 229 м, даже если числовой слот радиуса
содержит `FF`.

Единственный файл геодезических значений по умолчанию:
[config/grib-crs-defaults.json](../config/grib-crs-defaults.json).

| Параметр | Умолчание | Применение |
| --- | --- | --- |
| `earth_radius_m` | 6 371 229 м | Отсутствующая форма Земли или отсутствующий числовой размер |
| `prime_meridian_degrees` | 0° — Greenwich | Шаблон не задаёт начало долгот |
| `geocentric_translation_m` | `[0, 0, 0]` м | Явное прототипное допущение преобразования датума |
| `coordinate_height_m` | 0 м на WGS84 | Поверхность высоты для двумерных преобразований |

Неверный или отсутствующий файл останавливает новую пакетную загрузку.
Скрытых резервных значений для новых публикаций нет. Полная разрешённая CRS
в WKT/PROJ, форма Земли, поворот, применённые умолчания, снимок конфигурации
и её SHA256 сохраняются с публикацией. Изменение файла не переопределяет старые
редакции. Их чтение не требует исправной текущей конфигурации. Исторические
константы прежних версионных контрактов используются только для старых публикаций.
Список коллекций содержит идентификатор CRS и ссылку `self` на коллекцию;
полное определение `source_crs` доступно в этой отдельной коллекции, без
многократного дублирования большого снимка в списке.

## Поддержка и ограничения

Поддерживаются прямоугольные сетки 3.0, 3.1, 3.10 (Mercator), 3.20
(полярная стереографическая), 3.30 (коническая Ламберта) и 3.31 (Albers).
Коды формы Земли 0–8 и отсутствующая форма 255 интерпретируются с учётом
стандартных значений, масштаба и единиц. Углы используют GRIB sign-magnitude;
проекционные шаги из миллиметров переводятся в метры.
Коды 5 и 8 явно задают горизонтальный датум WGS84: для них географические
углы сохраняются, а умолчания смещения и нулевого меридиана не подменяют датум.
Отрицательное направление
строк/столбцов нормализуется вместе со значениями и масками.

Обязательные параметры проекции не угадываются. Отклоняются другие шаблоны,
коды с неподдержанным датумом, ненулевой угол сетки Mercator, наклонные/биполярные
конические разновидности, чередующиеся, идущие по столбцам или смещённые строки.
Ошибка объясняет неподдержанный вход; остальные файлы пакета продолжаются.

Операторский профиль принимает мгновенную температуру поверхности в K,
считывая дату расчёта и прогнозные сроки из GRIB2. Другие величины, уровни
и статистические продукты отклоняются. Проверки конкретной контрольной суммы,
даты и 24 сроков ICON сохранены отдельно в исторических проверочных командах;
они не ограничивают новую пакетную загрузку одним файлом. Неизвестная модель
получает нейтральный идентификатор по центру и процессу GRIB. Известный образец
ICON распознаётся по контрольной сумме. Один файл должен содержать один расчёт.
В каждом сроке поддерживается одно поле температуры поверхности.

## Хранение и выдача

Исходные значения и маски остаются в Zarr; нативный COG использует исходную CRS
с отдельным допуском float32 0,0001 K. Point/EDR выбирает ближайшую исходную
ячейку без пространственной интерполяции и без чтения обзорных изображений.
Координаты запроса задаются в `storageCrs` выбранной коллекции или CRS84;
при отсутствии `crs` используется исходная CRS этой публикации.

Проекционные координаты имеют порядок x/y и единицы метров. Исторические
имена полей `lon`/`lat` и массивов `longitude`/`latitude` сохранены для
совместимости; фактические оси, единицы и CRS явно записаны в метаданных.
Карта преобразует координаты к исходной сетке перед одной билинейной
интерполяцией. Новая геометрия использует [native display v2](../publication/native-display.v2.json)
и [numeric tiles v3](../publication/contract.v3.json). Исходный профиль ICON
сохраняет прежние контракты; исторические определения не редактируются.

Для новой геометрии GeoServer получает отдельный производный COG EPSG:4326,
построенный выборкой ближайших исходных ячеек с явным преобразованием CRS.
Метаданные содержат `derived`, исходную CRS и способ выборки. Проверка GeoServer
сравнивает его собственный полный растр; числовые ответы остаются по нативному
Zarr. ГИС-покрытие через антимеридиан пока требует отдельного разбиения
и отклоняется с объяснением.

Нулевое смещение к WGS84 — согласованное допущение, не подтверждение производителя.
Вектор `geocentric_translation_m` применяется от геоцентрических координат
WGS84 к геоцентрическим координатам исходной Земли; обратное преобразование
вычитает этот вектор. `coordinate_height_m` задаёт исходную высоту на WGS84.
Обратное двумерное преобразование восстанавливает отброшенную высоту исходной
поверхности так, чтобы результат лежал на той же поверхности высоты WGS84,
что и прямое преобразование.

## Пересчёт стенда

Операторский модуль `python -m publication.grib_batch --clock <UTC> --report /evidence/reload.json`
сканирует только непосредственные файлы `/input` по сигнатуре содержимого.
Подпапки и символические ссылки не обходятся; расширение `.grb` допустимо.
До постановки задания проверяется весь файл. Пересчёт создаёт новое задание
с неизменяемой конфигурацией и отключённым переиспользованием прежних полей.
Отчёт перечисляет файлы и ошибки. До проверки новых редакций прежние сохраняются.
Операционные пределы: до 64 MiB на файл, до 4096 сообщений, до 8 MiB на сообщение;
лимиты сетки и числовых блоков дополнительно проверяются при обработке.

Целевой стенд — `hmc-app-live`, интерфейс 8140, gateway 8141. После пересчёта
пакет исключает свои промежуточные редакции из discovery через retention без
удаления их файлов, сохраняя итоговую полную редакцию. Обычные ограничения
retention для прежних редакций продолжают действовать.
Для проверенного образа этой задачи:

```powershell
powershell -NoProfile -File tools/reload-grib.ps1 -Image hmc-publication:grib49-final
```

Текущий реальный ICON проверяется по всем 24 срокам. ENA из `data/grib/test`
используется только для проверки поворота и на стенд не загружается.
Другие проекции проверяются синтетическими GRIB2, независимыми формулами CPU/GPU
и PROJ; это не заменяет проверку будущих реальных данных производителя.

Источники: [шаблоны GRIB2](https://codes.ecmwf.int/grib/format/grib2/templates/),
[форма Земли](https://codes.ecmwf.int/grib/format/grib2/ctables/3/2/).
При сверке с ENA учтено округление `roundf` из
[ecCodes 2.44.0](https://github.com/ecmwf/eccodes/blob/2.44.0/src/eccodes/geo/grib_geography.cc).
