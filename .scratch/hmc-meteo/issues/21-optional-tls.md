# T21 — Опциональный TLS с сертификатами организации

Status: open

Родительская спецификация: #12. Срез T21; M5, критерии A10 и транспортная часть A7. Согласовано пользователем 20.10.2026.

## Задача

Добавить опциональный HTTPS для сайта, числового API, тайлов и GIS через внешний reverse proxy перед существующим gateway. Сейчас локальный HTTP остаётся доступным для разработки. После получения серверного сертификата, цепочки доверия и соответствующего закрытого ключа организации оператор включает TLS конфигурацией без изменения кода приложения. Отсутствие настоящих сертификатов не блокирует реализацию и тестовую проверку этой возможности.

## Что реализовать

- Отдельная конфигурация/override Docker Compose для TLS; документированные адрес сервера, порты и пути к PEM-файлам сертификата/цепочки и ключа. Конкретный proxy выбрать при реализации с фиксацией версии.
- Сертификаты и ключи предоставляются извне, доступны proxy только для чтения, не попадают в Git, образ, web assets, журналы или переносимые отчёты. Ключи доступа API остаются отдельными секретами.
- В TLS-режиме внешний доступ идёт через HTTPS и существующий gateway; внутренние API, БД, GeoServer и assets не получают внешних портов. Незашифрованный внешний доступ к защищённым маршрутам закрыт; перенаправление не используется как способ безопасно передавать ключ по HTTP.
- Настроенный внешний HTTPS origin сохраняется в ссылках каталога, метаданных тайлов и WMS capabilities без mixed content и потери /org или run/revision. Не доверять произвольным клиентским forwarding-заголовкам.
- Операторская инструкция по включению TLS, установке доверия к CA организации в клиентах, замене сертификата/цепочки/ключа с проверкой конфигурации и управляемым reload/restart, проверке результата и восстановлению предыдущей конфигурации. Не требовать отключения проверки сертификатов.
- TLS-режим с отсутствующими, нечитаемыми или несогласованными сертификатом/ключом завершается понятной ошибкой без автоматического отката на открытый HTTP.

## Критерии приёмки

- [ ] Локальный режим HTTP работает без сертификатов; HTTPS включается конфигурацией без изменения кода и пересборки приложения.
- [ ] Тестовая CA, сертификат с SAN и ключ позволяют проверить доверенную цепочку и имя сервера с включённой проверкой сертификата; неверное имя/недоверенная CA отвергаются клиентом.
- [ ] Сайт, публичные и защищённые API/тайлы/WMS работают через HTTPS; ссылки сохраняют внешний origin, профиль /org и выбор run/revision.
- [ ] Неверные/отозванные API-ключи и прогретый кеш сохраняют политику gateway; прямой доступ к backend и внешний защищённый HTTP недоступны, поддельные forwarding-заголовки не обходят ограничения.
- [ ] Ошибки файлов TLS не открывают HTTP автоматически; замена сертификата с reload/restart и восстановление предыдущей конфигурации воспроизводимо проверены.
- [ ] Секреты не обнаружены в Git/образе/журналах/архивируемых доказательствах; mounts и доступ к ключу ограничены TLS proxy.
- [ ] Документация и воспроизводимые проверки включены; требуемые регрессии пройдены, доказательства архивированы, тестовые ресурсы удалены с проверкой нулевого остатка.

## Проверка и границы

Использовать изолированный Compose-проект, реальный proxy/gateway и существующий опубликованный GRIB-образец. Проверить локальный HTTP и HTTPS, публичные/защищённые запросы, ссылки каталога/тайлов/WMS, доверие и имя сервера, замену сертификата и ошибки конфигурации. Выполнить T8 actual-sample access gate (включает T5-регрессию) и проверки из docs/development-workflow.md для затронутых компонентов; дополнить их реальной TLS-проверкой. Записать версии, конфигурацию и результаты без закрытых ключей, архивировать доказательства и выполнить обязательное удаление тестовых ресурсов.

Проверка на тестовой CA доказывает готовность подключения TLS. Боевой DNS, сертификаты организации и проверка доверия на целевых клиентах/сервере остаются отдельными входными условиями эксплуатационного запуска. Полная совместимость desktop QGIS проверяется в соответствующей GIS-задаче; этот срез обеспечивает HTTPS WMS и документирует настройку доверия.

Вне задачи: получение настоящих ключей/сертификатов, публичное развёртывание, автоматический выпуск/продление ACME, mTLS и замена существующей API-аутентификации.
