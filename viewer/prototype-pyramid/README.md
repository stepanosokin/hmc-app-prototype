# Сравнение пирамиды отображения

Одноразовый прототип для [№79](https://github.com/stepanosokin/hmc-app-prototype/issues/79).
Исходная карта и три степени обобщения отвечают на вопрос о допустимом виде
заливки/изолиний и цене вычислений. Это не производственный LOD.

При работающем `hmc-app-live` на порту 8140:

```powershell
node viewer/prototype-pyramid/server.mjs
```

Открыть <http://127.0.0.1:8158/?validation=1&variant=1>.
Четыре варианта: `variant=1`, `2`, `4`, `8`. Нижняя панель переключает уровень
на той же карте, сохраняя поле, срок, проекцию, камеру и канонический ряд точки.
Кнопки «Обзор» и «Приблизить» показывают различие масштаба; «Свернуть точку»
убирает карточку, сохраняя её данные. Стрелки клавиатуры вне полей ввода меняют
вариант. Исходный вариант всегда доступен вручную: автоматического LOD пока нет.

Первое открытие поля получает исходные native-блоки через публичный gateway
и создаёт все уровни в `data/prototype-pyramid/`. Подготовка не входит в
сравнение повторной загрузки. Реальные GRIB и продукты live не меняются.
Сервер принимает только GET и слушает localhost. Ctrl+C завершает его.
Можно задать `--port=8158 --upstream=http://127.0.0.1:8140`.

## Что сравнивается

| Вариант | Шаг сетки | Радиус экранного скругления |
| --- | --- | --- |
| Исходный | 1 | 0,6 CSS px |
| Умеренный | около 2 | до 2 CSS px |
| Сильный | около 4 | до 4 CSS px |
| Очень сильный | около 8 | до 8 CSS px |

Размеры округляются вверх. Сохраняется исходный footprint; новые ячейки
имеют одинаковый размер в исходных координатах. Значение — среднее с весами
перекрытия исходных ячеек. Это не среднее по геодезической площади.
Любой пропуск с положительным весом делает производную ячейку NoData;
пропуски не заполняются. Допустимые нули участвуют в среднем как числа.
Старые display range/физические палитры сохраняются для сравнимого цвета.

Изолинии строятся по выбранной уменьшенной сетке и затем скругляются.
Шаги уровней изолиний, преобразования единиц и четырёх проекций остаются
существующими. Прежний допуск ≤1 px здесь **не заявляется**: изменение
экстремумов, топологии и точности требует отдельного согласования.
Контракт производных помечен `prototype-display-pyramid/1`; исходный
`native_grid_sha256` обозначает происхождение, а не новую сетку.

Точка и график используют неизменённый API и nearest-native-cell, не пирамиду.
Число запросов графика не оптимизируется. Ветер выключен при открытии,
чтобы исключить его загрузку/анимацию из сравнения заливки и изолиний.
Снимки — исследовательские данные с закреплённой идентичностью, они не
реализуют производственные expiry/access/readiness gates. Не публиковать сервер
в интернет и не использовать его как эксплуатационный gateway.

Сервер компилирует viewer в память и применяет явно ограниченные изменения
к экспериментальным копиям модулей. Исходные модули и сборка live не меняются.
Проверяется наличие каждого ожидаемого места изменения; при изменении viewer
прототип может потребовать адаптации. Производственная реализация должна
использовать явный versioned интерфейс, а не эти текстовые замены.

## Измерения и проверка

```powershell
node viewer/prototype-pyramid/check.mjs --browser=chrome --fields=t,prmsl,tp --report=data/reports/pyramid79/chrome-new
node viewer/prototype-pyramid/check.mjs --browser=edge --fields=t,prmsl,tp --report=data/reports/pyramid79/edge-new
node viewer/prototype-pyramid/verify.mjs
```

Каждый каталог отчёта должен быть новым. Проверка запускает собственный
headless-браузер и удаляет его профиль. Окно 1280×800, DPR=1; LAEA — РФ,
обзор/два приближения, четыре варианта, реальные температура/давление/осадки.
Через `--modes=laea-rf,mercator,orthographic,laea` доступны дополнительные виды.
Результат содержит версии, camera/selection, сетку, байты, load/upload,
контуры, память, точные значения ряда, снимки и cleanup.

`load_ms` охватывает загрузку метаданных/блоков и их проверку; `build_ms` —
worker изолиний. `complete_ms` — наблюдение runner с ожиданием стабилизации
и вводом, не чистая latency интерфейса. Запись upload измеряет CPU submit,
не время завершения GPU. Память — существующая управляемая оценка, не весь
процесс. Никакого p95/SLA из одиночных измерений не выводится.

Все варианты передаются одним локальным snapshot-сервером. Они не сравнивают
runtime генерацию production API, холодный диск и реальные WAN-сети.
Каждый `receipt.json` сохраняет подготовку, исходную идентичность, SHA256
алгоритма, метаданных и блоков. Независимый verifier проверяет средние/маски,
исходный footprint, CRS и halo. Полные отчёты/снимки хранятся во внешнем
архиве по [правилам проекта](../../docs/validation/evidence-storage.md).

Следующий шаг — выбор приемлемого рисунка пользователем, затем отдельный
производственный контракт LOD и приёмка. [Согласование](../../docs/design/display-pyramid-comparison.md).
