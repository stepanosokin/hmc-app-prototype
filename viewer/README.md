# Рабочая карта прогноза

Просмотрщик T13 / [№25](https://github.com/stepanosokin/hmc-app-prototype/issues/25)
использует опубликованный ICON-EU T_G и многополевой профиль GRIB2, русские подписи
и UTC. Справа расположены кнопки групп выбранной модели: температура, давление,
влажность, порывы ветра и другие доступные показатели. Группы представлены значками
Basic Straight Flat; фон всех плиток групп и отдельных полей, включая выбранные,
прозрачен на 90% на обеих подложках. Выбор обозначается контуром.
Каждая кнопка открывает компактную сетку значков фактически опубликованных полей
с метками разновидности, высоты/слоя, интервала ближайшего доступного срока и единиц.
Полное русское название доступно в подсказке и при фокусе; выбранное поле подписано
в меню и в шкале карты. Значки локальные, [источники и авторство](icons/README.md)
перечислены отдельно; ссылка Magnific / Flaticon есть в настройках.
Селектор отображения называется «Проекция». Несуществующие высоты не
добавляются. Расчёт/редакция и срок выбираются отдельно. Смена поля сохраняет
камеру, точку и ближайший доступный срок, обновляя канонический ряд.
Скорость и направление ветра включены при открытии и независимо накладываются
на основное поле. Кнопка с иконкой и выбор одного уровня находятся над легендой.
Вначале выбираются 10 м, иначе единственный доступный уровень; несколько
других уровней требуют явного выбора. Недоступный выбранный уровень сохраняется
с объяснением. Используются совместимые U/V той же модели, расчёта, редакции,
точного срока и участника; ближайший срок ветра не подставляется.
Движущаяся белая стрелка A1 с тонким тёмным контуром направлена по потоку.
Плотность привязана к площади экрана: 768 знаков на эталонных 1440×900
вместо прежних 192, с пропорциональным количеством на других экранах.
Вне покрытия и при отсутствии обеих компонент стрелка не рисуется.
Скалярные поля рисуются GPU, ветер — отдельным Canvas2D поверх них.

Изолинии скалярного поля строятся в браузерном worker по нативным числам и
маске, независимо от цветной заливки. В легенде кнопка «Изолинии» скрывает
линии вместе с подписями; при открытии страницы они включены. Шаг зависит
от показателя и географической ширины видимого охвата; он указан в легенде.
Линии чёрные в тёмной теме и серые в светлой. Давление в интерфейсе — в гПа;
исходные/API/GIS-единицы сохраняются. Настройки всех 29 полей и ограничения:
[согласованные требования](../docs/design/field-contours-discussion.md).

В popup сохраняется график основного поля. При включённом ветре над ним
показаны традиционные флажки выбранного уровня: стержень направлен **откуда**
дует ветер, полное перо означает 10 узлов, половина — 5, треугольник — 50.
Знак округляется до 5 узлов, точная подпись показывает м/с и направление
относительно географического севера. График целиком помещается в ширину popup
без горизонтальной прокрутки. В длинном ряду флажки уменьшаются, подписи оси
показываются реже; все точки и флажки сохраняются. Диапазон и кнопка выбора
срока доступны с клавиатуры.
Штиль, NoData, точка вне покрытия, пропуск срока и ошибка различаются.
Ветер в точке вычисляется по двум каноническим значениям одной исходной ячейки,
а не по отображаемому растру. Выключение ветра скрывает его полосу.

При смене основного поля старый кадр ветра освобождается для сохранения общего
бюджета 128 МиБ; включение и выбранный уровень сохраняются. Во время загрузки
ветер ожидает выбранное поле. Смена проекции переиспользует пару U/V.
Диагностический полноэкранный GPU-readback допускается только когда его
добавочная текстура также помещается в общий бюджет.
Просмотрщик подключается к gateway отдельного Compose-проекта. Учётные данные
организаций браузеру не передаются.

## Подготовка

Научная и браузерная проверка изменения ветра:
[свидетельства №72](../docs/validation/wind-overlay-72.md).
Обычные тесты используют сохранённый синтетический PROJ-эталон и не требуют
исторического архива. Отдельная проверка реальных API и GPU запускается
из корня репозитория так:

```powershell
node tools/check-wind-overlay.mjs data/reports/wind72/my-chrome chrome
node tools/check-wind-overlay.mjs data/reports/wind72/my-edge edge
```

Нужен локальный сервис на `http://127.0.0.1:8140` с опубликованными U/V;
`HMC_WIND_GATEWAY` задаёт другой loopback-адрес. Каждый запуск требует нового
каталога. Runner собирает замороженный viewer отдельно, читает API через
временный прокси, повторно использует успешные неизменяемые ответы и ограничивает
исходные чтения до одного каждые 150 мс. Это функциональная проверка, не
нагрузочное измерение и не проверка production-кеша или политики доступа.
В конце проверяются удаление собственного профиля, отсутствие процессов
браузера и закрытие тестового прокси. После запуска архивируйте отчёт штатным
`tools/archive-validation.mjs`. Опция `--direct-smoke` после имени браузера
открывает обслуживаемый viewer напрямую для отдельной дымовой проверки.

В корне репозитория:

```powershell
npm --prefix viewer ci --ignore-scripts --no-audit --no-fund
npm --prefix viewer run build
node viewer/prepare.mjs
```

TypeScript зафиксирован в `package-lock.json`. `prepare.mjs` проверяет SHA256
MapLibre GL JS 6.15.0, proj4js 2.22.0 и D3 из существующего
[lock-файла](../tools/display-projections/vendor-lock.json). Получение зависимостей
нужно только при подготовке; браузер получает код, workers и Natural Earth
с локального сервера. Используются системные шрифты, без внешнего font API.

Для существующего настроенного проекта запустить сервис `viewer` теми же
Compose-параметрами, что и `gateway`. Порт интерфейса задаётся `T13_PORT`
(по умолчанию `http://127.0.0.1:8140`). Настройки паролей остаются в локальном
env-файле проекта. Не создавать второй проект с теми же томами.

Первый запуск нового проекта требует публикации данных. Порядок:

1. Проверить Docker, свободные порты, locked image, локальный исходный GRIB и
   его SHA256; создать отдельные имя проекта, env-файл с паролями и каталог
   `PUBLICATION_EVIDENCE_DIR`. Исходный образец остаётся частным.
2. Собрать viewer и подготовить локальные assets. Если процесс запускается через
   `Invoke-CheckedProcess`/`Start-Process`, после установки зависимостей вызывать
   `node viewer/build.mjs` напрямую: доступный в shell `npm` не гарантирует,
   что launcher найдёт `npm.cmd`.
3. С одинаковыми Compose-параметрами поднять `db api gateway geoserver viewer`,
   выполнить `run --rm init-assets`, проверку готовности через
   `run --rm --entrypoint python check -m publication.verify_revisions --ready-only`
   и `run --rm worker once --migrate`.
   Этот шаг обязателен и перед использованием ранее созданной БД с новым кодом:
   он применяет миграции доступа, лимитов и хранения публикаций. Создание схемы
   `access` при старте PostgreSQL само по себе не создаёт таблицы и права gateway.
4. До `worker submit` скопировать одобренные `selection.json`, `browser.json`,
   `comparison.json`, `geoserver-numeric.json` из
   [принятого T4 эталона](../tests/fixtures/publication/tile-engine/selection.json)
   из `tests/fixtures/publication/tile-engine/` в каталог, смонтированный как
   `/evidence`. Без `selection.json` worker не допускает публикацию.
5. Выполнить `run --rm worker submit --clock <UTC>` и `run --rm worker once`,
   перезапустить `api gateway`, проверить непустой `/api/v1/catalogue` и открыть
   viewer. Для исторического образца явно записать демонстрационные часы;
   их значение не является текущим временем или свежим прогнозом.

Повторное включение готового проекта использует его прежние env-файл, тома,
порты, clock и Compose-параметры. Повторная миграция/публикация для открытия
карты не нужна. Проверочные runners создают временные стенды и завершаются
retirement; пользовательский живой стенд сохраняется по явному запросу.

Для демонстрации полного прогноза исходного образца проверьте в каталоге
**24 разных срока одной редакции** выбранного расчёта. Непустой каталог и
работающий слой карты этого не гарантируют: проверочный сценарий T13 намеренно
публикует только +1/+3 ч с пропуском +2 ч. В таком наборе график корректно
показывает две отдельные точки, без линии через пропуск. Не используйте этот
сокращённый набор как полный демонстрационный прогноз.

Если в живом проекте остался сокращённый набор, с разрешения владельца
допубликуйте исходный образец с **теми же** Compose-параметрами и демонстрационными
часами. `submit` без `--hours` запрашивает все 24 реальных срока; существующие
неизменённые партии переиспользуются, прежние редакции сохраняются:

```powershell
docker compose <параметры проекта> run --rm worker submit --clock <UTC>
docker compose <параметры проекта> run --rm worker once
```

Дождитесь успешного завершения worker и проверьте каталог. В уже открытой карте
явно примите новую редакцию либо перезагрузите страницу, затем проверьте
24 точки и 23 сегмента графика. Данные разных редакций не объединяются в UI.

Локальный `published.json` не заменяет проверку непустого каталога: он может
сохраниться после потери или замены Docker volumes. При HTTP 503 сначала
проверьте журналы БД и API. Для восстановления пропущенных миграций без
обработки очереди выполните с параметрами именно этого проекта:

```powershell
docker compose <параметры проекта> run --rm --no-deps --entrypoint python worker -c "from publication.recovery import migrate; migrate()"
```

Если отсутствует сама роль gateway, сначала выполните процедуру обновления
существующей БД из [инструкции доступа](../docs/access.md#команды-оператора).
Если после миграции каталог отвечает 200, но пуст, проверьте записи `app.jobs`,
`app.revisions`, `app.catalogue` и сохранность assets. Восстанавливайте исходную
публикацию по шагам 4–5 только после подтверждения отсутствия опубликованных
данных; сохранение одного `published.json` не означает их наличия в БД.
Для диагностики сохранять stdout/stderr и native exit code каждого шага,
не публикуя env-файл с паролями.

## Поведение

Панель «Источник и настройки» содержит раздел «WMS и API»: рабочие публичные
ссылки, поля адресов и отдельные кнопки копирования. WMS GetCapabilities закреплён
за выбранным расчётом и редакцией; point API — также за точным сроком UTC и
географической точкой, с исходными значениями в K. Без выбранной точки используется
подписанный пример центра опубликованного покрытия. Если копирование браузером
недоступно, адрес выделяется для ручного копирования.

При смене срока ссылки относятся к запрошенному прогнозу, даже если карта пока
сохраняет прежний кадр. При загрузке/ошибке без выбранной точки пример ожидает
готового покрытия; отсутствующий срок отключает API и ссылку метаданных, но
сохраняет WMS расчёта/редакции. Истечение публикации отключает все эти ссылки.
Смена только единиц или проекции не меняет числовой контракт.

«Происхождение и числовой контракт» показывает краткие русские поля: источник,
поле, расчёт, срок, короткую редакцию, доступность, полноту, возраст и метод
выборки; имя файла появляется только из соответствующего выбранному сроку
описания. Полный JSON доступен отдельной ссылкой «Технические метаданные».
Организационные подключения с ключом в заголовке выполняются через gateway
по [инструкции QGIS](../docs/qgis.md), а не через публичный bridge viewer.

Каждое открытие начинается с «LAEA - РФ» и охвата доступного покрытия.
Это фиксированная эллипсоидальная LAEA с центром 60° с. ш., 90° в. д.:
`+proj=laea +lat_0=60 +lon_0=90 +x_0=0 +y_0=0 +datum=WGS84 +units=m +no_defs`.
Границы РФ и широта 45° не ограничивают этот вид. Последний вид не запоминается.
Также доступны Меркатор, строгий ортографический глобус и арктическая
LAEA — фиксированная EPSG:3576 севернее 45° с. ш.
Смена вида сохраняет опубликованную выборку, единицы и географическую точку.
Кнопка «К области данных» возвращает к покрытию текущего вида. За горизонтом
или вне области выбранной проекции точка сохраняется с объяснением, маркер скрывается.
Переключение выполняется в браузере без повторной загрузки GRIB и изменения публикаций.

Начальный расчёт — новейший доступный, срок — первый опубликованный.
Расчёт/редакция выбираются явно, новые публикации принимаются отдельной кнопкой.
Смена срока сохраняет тот же экземпляр карты, локальную подложку, камеру,
подписи, координату точки и состояние панели. Старое число очищается сразу;
новое появляется из point API для выбранного срока. До полной подготовки
новой GPU-текстуры остаётся прежний кадр с его фактическим временем,
расчётом и редакцией; запрошенный срок отдельно помечен как загружающийся.
Готовое поле заменяется сразу, без анимации. Ошибка загрузки сохраняет
подписанный прежний кадр, истечение публикации скрывает его. Кеша кадров нет;
массивы, текстуры и диагностический framebuffer учитываются вместе в 128 МиБ.
Пропуск срока очищает слой и значение. Клик получает nearest-native-cell из
point API; цвет карты не используется для числового ответа. Нативные
координаты ячейки, точная выборка и происхождение раскрываются в карточке.
Кнопка сворачивания сохраняет точку, удаление и Escape очищают выбор.

Карточка точки показывает весь опубликованный прогноз одного закреплённого
расчёта и редакции. Все значения берутся из канонического point API: точный срок
и ближайшая нативная ячейка. На телефоне график находится во вкладке «Точка»;
кнопка «Выбранная точка» открывает панель и на компьютере, включая точку за
горизонтом или вне текущего экрана. Кнопка сворачивания доступна при прокрутке.
Наведение и ползунок графика показывают UTC и значение без смены срока;
нажатие SVG, Enter/пробел или «Выбрать этот срок» меняют общий срок карты.
График в [визуальном макете](../docs/prototypes/design-concept.ru.md) сохраняет
демонстрационные данные; они не используются рабочей картой.

Ряд переиспользуется при смене срока, проекции, единиц и палитры. Новая точка
или принятая публикация очищают прежнюю идентичность. Запросы выполняются
последовательно; хранится только текущий ряд, максимум 745 часовых позиций
в пределах 31 дня. Канонические ответы проверяются по model/run/revision,
field/level/grid/member/valid time; ограничены 8192 символами каждый. Резерв
ряда и разбора ответа 16 МиБ входит в общий бюджет 128 МиБ. Пропуск срока,
native nodata, положение вне покрытия и ошибка запроса различаются; линия
через них не проводится. Повторяются только ошибки, успешные значения
сохраняются. HTTP 410 очищает ряд и слой; кнопка «Перевыбрать публикацию»
заново читает каталог, прежде чем возобновить запросы. Наблюдения и временная
интерполяция не добавляются; новый серверный endpoint не требуется.

Проверка публикаций выполняется раз в минуту, пока вкладка видима, и кнопкой
«Проверить обновления». «Обновить текущий расчёт» сохраняет расчёт и точный
срок; «Перейти к новому расчёту» начинает его первый опубликованный срок.
До подтверждения карта остаётся закреплённой. «Позже» отменяет также уже
начатую загрузку. Поле, GPU-текстура, метаданные и значение сохранённой точки
заменяются вместе после подготовки; отказ API/GPU сохраняет прежнюю выборку.
Одновременно допускаются только текущая и одна промежуточная числовые
текстуры в общем бюджете 128 МиБ. Смена проекции/выбора отменяет старую работу.

Телефон использует одну изначально закрытую панель с вкладками «Настройки»
и «Точка». Переходы сохраняют контекст. Навигация по времени оставляет панель
открытой и очищает старое значение согласно правилам выбора; шкала и срок UTC
доступны над нижними подписями. Внеэкранные подписи обрезаются областью карты,
не увеличивая viewport. Наблюдения и анимация ветра не добавляются.

Числовой путь — утверждённый
[native-display/1](../publication/native-display.v1.json), с однократной GPU
bilinear-интерполяцией и маской. Замороженный v2 и внешние point/EDR/WMS
не меняются. Шкала постоянная: −20…40 °C (253,15…313,15 K), крайние значения
насыщаются. Смена единиц/палитры не перезагружает блоки. Ветер и временное
смешивание не реализованы.

Загружаются максимум 18 блоков, два одновременно, до 8 МиБ на выборку.
Устаревшие запросы отменяются; результат повторно проверяется перед использованием.
Массивы/текстуры и диагностический framebuffer ограничены 128 МиБ; DPR — до 2,
canvas — до 2048×2048. Выход за возможности WebGL 2 даёт русское сообщение
недоступности и явную кнопку Меркатора; автоматической подмены нет.
Потеря GPU-контекста скрывает значение до восстановления. Safari/iOS не заявляется
поддерживаемым по ранее согласованной отсрочке T23.

## Проверка

Для M4 / T16 / [№28](https://github.com/stepanosokin/hmc-app-prototype/issues/28)
добавить `-Offline` к полному `-Navigation -Updates -WithEdge -Final`.
Проверка блокирует все внешние HTTP(S)-запросы страницы и её dedicated workers
до отправки, оставляя доступ к локальному origin. Контрольные запросы страницы,
worker и вложенного worker должны попасть в журнал блокировки; ошибка DNS
сама по себе не считается доказательством. Кеш браузера отключён, service worker
обходится. В `browser.json` сохраняются разрешённые/заблокированные URL,
состояние probes и результаты T13–T15. Это отключение публичной runtime-сети
для проверяемого приложения; setup-time скачивания и сеть других приложений
не отключаются. Физический Android проверяется тем же `-Offline` без `-WithEdge`.
Версии, локальные пути и основания распространения перечислены в
[реестре ресурсов T16](../docs/validation/archives.md).

```powershell
npm --prefix viewer test
npm --prefix viewer run check
powershell -NoProfile -File tools/run-weather-viewer.ps1 -Project hmc-publication-t13-new -WithEdge
```

График T27 / [№41](https://github.com/stepanosokin/hmc-app-prototype/issues/41):
добавить `-PointSeries -Offline`. Этот сценарий публикует все 24 реальных срока,
проверяет график в трёх проекциях и сверяет каждый срок с независимым raw GRIB
и EDR. `-WithEdge` добавляет Edge; переменные `T13_ADB`/`T13_ANDROID_SERIAL`
выбирают отдельную физическую Android-попытку. `T13_FOCUSED=1` ограничивает
desktop одним viewport и остаётся Development. Полный desktop использует
1440×900, 390×844, 360×740 и 640×360. Задержки, пропуск, nodata, outside,
HTTP 503/410 и частичный/полный отказ явно синтетические; успешные исходные
значения не заменяются макетом. Для регрессий навигации/обновлений/смены срока
выполняется отдельный сценарий `-Navigation -Updates -TimeSwitch -Offline`
с его прежним начальным набором +1/+3 ч. Не смешивать эти фикстуры.

Для навигации T14 / [№26](https://github.com/stepanosokin/hmc-app-prototype/issues/26)
добавить `-Navigation`. Runner публикует отдельный явно синтетический
перекрывающийся расчёт и реальные сроки +1/+3 ч с пропуском +2 ч.
Для T25 / [№39](https://github.com/stepanosokin/hmc-app-prototype/issues/39)
добавить `-TimeSwitch`: проверяются три проекции, идентичность canvas/подписей,
камера, точка/панель, все элементы времени, задержки реальных fetch/decode/upload/point,
а также явно синтетические HTTP 503/410. Значения GPU и точки для реальных
+1/+3 ч сверяются с raw GRIB/PROJ в `tools/viewer-time-reference.py`.
`-TimeSwitch -TimeSwitchOnly` ограничивает Development одним этим сценарием;
добавление `-TimeStatusOnly` проверяет только приоритет загрузки/ошибки
при сохранённой точке вне LAEA, в том числе с закрытой шкалой телефона.
полная приёмка использует `-TimeSwitch -Navigation -Updates -Offline -WithEdge -Final`
и отдельный физический Android без `-WithEdge -Final` на тех же входах.
`-NavigationOnly` вместе с `-Navigation` запускает только Development-сценарий;
полная приёмка использует `-Navigation -WithEdge -Final` без этого ограничения.
Для T15 / [№27](https://github.com/stepanosokin/hmc-app-prototype/issues/27)
добавить `-Updates`; целевая Development-проверка использует `-UpdatesOnly`,
полная — `-Navigation -Updates -WithEdge -Final`. Сценарий публикует явно
подписанную коррекцию +1 K, удерживает реальные ответы/загрузки, проверяет
отказ/принятие, настоящий отказ API, GPU loss, повторные замены и мобильную
панель. Независимый raw GRIB/PROJ, EDR и scoped WMS сверяются после обновления.
Физический Android запускается отдельным полным прогоном с
`-Navigation -Updates`, без `-UpdatesOnly`; входы совпадают с настольной приёмкой.
Тестовый расчёт виден только при явном `?validation=1&fixtures=1`, с русской
пометкой в выборе расчёта и сводке. Обычное открытие использует реальные продукты.
Проверки задерживают реальные tile/body/point ответы и продолжение реальных
GPU-загрузок, сверяют сброс срока, закрепление редакции и очистку точной
отменённой текстуры. Значения ответов и серверная публикация не подменяются.
Отдельный браузерный документ выполняет видимые переходы согласованного
интерактивного прототипа; его иллюстративные значения не проверяют научную точность.

Runner требует частный образец с проверенным SHA256 и существующий locked image
`hmc-publication:t12`. Он создаёт отдельные тома и тестовые ключи, публикует
реальные сроки +1/+3 ч (пропуск +2 ч), проверяет видимые элементы управления,
сохраняет GPU readback/снимки/точные входы и сравнивает с независимым raw GRIB/PROJ.
После любой попытки архивирует отчёт и проверяет отсутствие созданных ресурсов.
`-Final` добавляет полный Python suite; T5 выполняется существующим
`publication/run-revisions.ps1` в отдельном свежем проекте с последующим retirement.
Его начальный пустой каталог нельзя совмещать с уже опубликованными +1/+3 ч
браузерного стенда. До финального запуска завершить review
и заморозить исходники. Не редактировать входы во время проверки.

Матрица runner: desktop 1440×900 и эмулируемые mobile 390×844/360×740/640×360.
Эмуляция не заменяет физический Chrome/Android. Полная приёмка №25 требует
отдельного физического устройства и сверки всех критериев задачи; прохождение
одних unit/type checks не устанавливает готовность. Полный нагрузочный отчёт
остаётся в №31.

Физический Android запускается отдельной попыткой после сопряжения ADB:
`T13_ADB` — явный путь к `adb.exe`, `T13_ANDROID_SERIAL` — согласованное устройство.
Используется отдельный ADB-сервер 5041, собственная вкладка и временные
forward/reverse mappings. Native select выбирается через видимый Android dialog,
проверки карты используют реальные touch events; эмуляция размеров не включается.
Runner удаляет свою вкладку, mappings и временный UI XML после каждой попытки.
После завершения всех попыток отдельно выключить task ADB, удалить собственные
ключи с проверкой неизменности и получить подтверждение удаления сопряжения на телефоне.
